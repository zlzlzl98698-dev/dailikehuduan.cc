# Netflix 解锁判断标准：自制剧 vs 全区剧差异、测试片号自测与 DNS/原生 IP 原理

<div class="answer-first-box">
<div class="answer-first-label">核心结论 · Answer First</div>
<p>判断一条机场节点是否真正「解锁 Netflix」，绝不能只看能否打开官网首页，也不能以能否播放《怪奇物语》作为标准，核心指标在于<strong>能否正常检索并播放非自制第三方版权剧集（全区解锁）</strong>。面对 Netflix 日益严苛的数据中心 ASN 审查与代理侦测，市面上的解锁方案分化为「原生 ISP 落地」与「非原生 DNS 解锁中转」两条路径。日常自测只需用无痕浏览器分别验证测试片号 <code>70143836</code> 与 <code>80018499</code> 并搭配 <code>fast.com</code> 测速；若遇到「电脑网页能看、电视盒子或手机 App 报 <code>M7111-5059</code> / <code>E100</code>」，则需重点排查 App 硬编码 DNS 逃逸、本机 IPv6 泄漏以及 <code>nflxvideo.net</code> 视频流路由分裂。</p>

## 一、Netflix 解锁的三个层级：为什么能看《怪奇物语》却搜不到《绝命毒师》？

**为什么很多机场在面板里宣称「全节点解锁 Netflix」，但连上去打开官网，却发现以前收藏的经典美剧、英剧和日本动漫全部消失了，列表里只剩《怪奇物语》《鱿鱼游戏》《纸牌屋》等少数剧集？** 直接答案是：你所在的节点正处于 Netflix 风控体系的中间降级层——**「仅解锁自制剧（Netflix Originals Only）」**，并未实现真正的全区解锁。

Netflix 购买了全球各地区极其复杂的第三方影视版权（例如华纳、索尼、AMC、东宝等片方的授权内容），版权方在合同中严格要求 Netflix 必须利用地理封锁技术防止跨区观看并阻止匿名数据中心代理流量。相比之下，Netflix 自家投资制作并拥有全球独占发行权的原创剧集（Originals）不受第三方地理授权纠葛限制。因此，Netflix 的边缘反代引擎将全球访客的出口 IP 划分为截然不同的三个待遇层级：

| 解锁层级 | 页面与片库典型表现 | 底层风控判定原因 | 实际观影体验评估 |
| :--- | :--- | :--- | :--- |
| **第一级：完全屏蔽 / 报错拦截** | 打开页面提示 `Something went wrong`，或播放瞬间弹出 `M7111-5059`、`M7111-5095`、`E100`、`Proxy Detected` | 该 IP 段因大规模自动化注册、恶意扫号或高频滥用被列入高危代理黑名单，或 IP 归属地位于未提供服务的地区（如中国大陆） | **完全不可用**；既看不了自制剧也看不了非自制剧 |
| **第二级：仅自制剧（Originals Only）** | 可以正常登录账户，首页与搜索栏仅显示 Netflix 自家出品剧集（如《怪奇物语》《黑镜》《毒枭》）；搜索《绝命毒师》等第三方版权片直接显示「无搜索结果」或「未在本地区提供」 | **最常见状态**。Netflix 识别出该 IP 属于普通数据中心（IDC/Hosting）或常规共享 VPN 出口，既不想彻底封杀导致误伤普通用户，又必须向版权方交代，于是采取「隐藏所有第三方版权内容」的柔性降级策略 | **残血降级状态**；绝大多数未做专门解锁处理的平价机场节点均处于这一层级 |
| **第三级：全区解锁（Non-Originals 全库可用）** | 能够正常检索、加载并高清播放当前落地国家/地区授权的全部第三方电影、美剧、韩剧与院线大片，片库丰富度与当地家庭宽带用户一致 | 出口 IP 在 Netflix 风控库中呈现为当地合规的住宅/商业宽带 ISP 属性，或者机场服务端配置了工作正常的流媒体 DNS 解锁中转通道 | **真正的完整解锁状态**；搭配足够单线程带宽即可享受 4K Dolby Vision 观影 |

### 常见热门解锁地区的片库与字幕差异
在确认节点具备全区解锁能力后，不同国家节点的版权片库与字幕配置差异巨大：
- **中国香港（HK）与新加坡（SG）**：拥有全平台最完善的**繁体中文字幕**与大量华语电影、TVB/港台剧及同步更新的爆款韩剧，且物理延迟在亚太区最低（`2026-10-19` 非晚高峰历史测速香港约 `21–27 ms`，新加坡约 `42–46 ms`），是中文用户的首选主力观影区。
- **中国台湾（TW）**：同样具备优秀的繁体中文字幕与丰富的台湾院线、日漫版权，但部分机场台湾节点较少，且偶发出口 IP 被风控库识别错位为其他洲际地区。
- **日本（JP）**：全球日漫新番与日剧库最全的地区之一，且码率高、OCA 缓存节点充沛，但大量日本本土授权电影与动画**仅有日语原声与日文字幕，无中文字幕**。
- **美国（US）与英国（UK）**：美剧、好莱坞老片与纪录片资源极其庞大，但除 Netflix 原创剧外，多数第三方授权片源仅提供英文字幕，且跨洋单线程吞吐在晚高峰容易波动。

## 二、10 秒手工自测法：测试片号 `70143836`、`80018499` 与 `fast.com` 实测

**不想在网上下载来历不明的一键测流媒体脚本，如何用最安全、零风险的方式，在 10 秒钟内亲手验证一条机场节点是不是真全区解锁？** 直接答案是：完全不需要任何第三方脚本，只需要切到目标节点后打开浏览器无痕窗口，直接访问 Netflix 的两个经典片号 URL 对比状态，并用 Netflix 官方测速域 `fast.com` 校验吞吐能力即可。

### 第 1 步：排除本地缓存与账号地区锁干扰
- 测试前请先将代理客户端的规则暂时切换至目标单一节点（或将 `🎬 Netflix` 策略组设为目标节点），确保已设置 `ipv6: false`。
- 打开 Chrome / Edge 的**无痕/隐私窗口**登录正常的 Netflix 账号（注意：部分低价购买的跨区礼品卡新号在首 28–30 天存在官方地区锁，测试节点时请确保账号本身未处于跨区冻结期）。

### 第 2 步：双片号交叉测试（`80018499` vs `70143836`）
业界与自动化解锁检测脚本长期采用固定影片 ID（Title ID）作为对照探针，你只需在浏览器地址栏直接输入以下两个官方链接：

1. **基准探针：测试片号 `80018499`（自制剧对照组）**
   - 直接访问：`https://www.netflix.com/title/80018499`（对应 Netflix 原创高分剧集《毒枭 Narcos》等 Originals 序列条目）。
   - **判定逻辑**：
     - 如果打开页面提示 `Not Available`、`M7111-5059` 或无法登录查看详情，说明当前节点**连自制剧都看不了（第一级：完全屏蔽）**，可直接放弃该节点。
     - 如果能正常出现「播放（Play）」按钮且能播放，仅能说明「网站没有封死你」，接下来必须测试下一个非自制片号。

2. **金标准探针：测试片号 `70143836`（非自制第三方版权剧对照）**
   - 直接访问：`https://www.netflix.com/title/70143836`（对应索尼/AMC 版权的经典美剧《绝命毒师 Breaking Bad》，该剧在美、日、港、台、新等绝大多数主流区均有版权授权，是检验非自制剧解锁的行业通用基准片号）。
   - **判定逻辑**：
     - **页面报错 `404` / 提示「提醒我（Remind Me）」而无「播放」按钮**：明确判定为**第二级「仅自制剧（Originals Only）」**，说明该 IP 被判定为了普通数据中心代理！
     - **页面完整加载分集列表并显示「播放（Play）」按钮，且点击后可正常出画面**：确认该节点在当前地区**成功实现了第三级「全区解锁」**！

> **交叉核验小贴士**：个别小众国家地区可能因当月版权到期下架了某一部老片；如果在某冷门欧洲或拉美节点测试 `70143836` 无播放按钮，可再顺手在搜索框搜一部当地热门的非 Netflix 原创好莱坞大片（如索尼、环球影业电影）或直接用 `https://www.netflix.com/title/81280792` 等当季常用检测片交叉复核，防止因单一区域版权变动产生误判。

### 第 3 步：`fast.com` 官方测速与真实 CDN 出口检查
验证完片号可播后，在同一个无痕窗口打开 Netflix 官方专属测速网站 `https://fast.com`（确保 `fast.com` 也同样命中了你的 Netflix 代理策略组）：
1. 等待测速完成，查看核心下载速率。Netflix 官方对 **4K Ultra HD + HDR / Dolby Vision** 的建议稳定带宽底线为 `15–25 Mbps`（在跨洋链路丢包环境下，建议实测跑出 `35 Mbps` 以上以保留充足缓冲余量）。
2. 点击下方的 **`Show more info（显示更多信息）`** 按钮，重点观察两项数据：
   - **`Client` 栏显示的 IP 与国家城市**：确认出口 IP 是否确实是你所选节点的落地地区，排除流量漏走直连或错分到其他国家的低级配置错误。
   - **`Loaded`（加载延迟）vs `Unloaded`（空载延迟）**：如果空载延迟 `50 ms` 但加载延迟暴涨到 `800 ms+`（Bufferbloat 严重），说明该节点晚高峰拥堵或 DNS 解锁中转机带宽过载，看 4K 时容易中途降画质或转圈。

## 三、底层原理深剖：机房 IDC ASN vs 原生 ISP ASN vs DNS 解锁中转

**为什么同一家机场宣称「全节点解锁 Netflix」，实际使用时却经常发现「开了安全加密 DNS 就突然看不了非自制剧」，或者「明明测速 500 Mbps 看 Netflix 却糊成 480P」？** 直接答案是：市面上的机场解锁能力并非出自同一套技术架构，而是分成 **普通 IDC 机房直出、原生 ISP 落地、以及非原生 DNS 解锁中转** 三种截然不同的底层原理。不懂这三者的区别，买套餐和改客户端配置就很容易踩坑。

| 技术路径 | 底层网络工作原理 | 商业成本与常见价位 | 抗客户端本地 DNS 干扰能力 | 稳定性、延迟与主要隐患 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 普通机房 IDC ASN（无解锁）** | 落地服务器采购自 AWS、DigitalOcean、Vultr 等常规公有云数据中心，出口 IP 直接访问 Netflix | 最低（常见于 [一元机场](/plans/one-yuan/) 与低成本平价节点） | 无影响（无论怎么设都看不了全区） | 几乎固定停留在**仅自制剧**状态，甚至直接弹出 `M7111-5059` |
| **2. 原生 ISP / 优质商业宽带落地（真原生 IP）** | 节点直接租用当地本土运营商（如香港 HKT/HGC、台湾 HiNet、日本家宽/本土 ISP、美国 AT&T/Comcast 或极纯净商业段）作为最终出口 IP | 极高（常见于独享定制套餐或高阶专线特定标注节点，如 [光速云定制版](/brands/guangsuyun/)） | **极强（完全免疫）**：哪怕用户在本地客户端强制开启了 Cloudflare/Google DoH 解析，最终向 Netflix 发包的出口 IP 依然被认可 | **延迟最低、画质起播最快**，直连就近 OCA 缓存节点；唯一风险是若同段人数过多且无隔离，仍可能被风控连累降级 |
| **3. 非原生 DNS 解锁中转（机场主流方案）** | 机场绝大多数节点本身仍是便宜的 IDC 机房 IP，但商家另外花钱租用一台或多台拥有原生 IP 的「流媒体解锁机（Landing VPS）」，通过修改所有中转节点服务器上的 `Dnsmasq` / `SmartDNS`，**将 `netflix.com` 等域名专门劫持解析并 SNI Proxy 转发至那台解锁机** | 适中（用一台解锁机分摊几十台普通节点的解锁需求，绝大多数 `¥20–40/月` 常规机场采用此方案） | **极度脆弱（高度敏感）**：一旦用户在 Clash / 软路由中强制拦截了服务端远程 DNS，自行使用 DoH 直连解析出了 Netflix 官方就近 IP，就会绕过机场 SNI 代理，**瞬间被打回仅自制剧原形** | **中转瓶颈隐患**：所有节点的 Netflix 流量都会汇入同一台解锁中转机，若晚高峰该中转机网卡跑满，就会出现「YouTube 秒开 4K，但 Netflix 只有 480P 转圈」的现象 |

### 为什么「自定义加密 DoH」会让机场的 Netflix 解锁瞬间失效？
这是高阶用户折腾 Clash 或软路由时最常犯的「反向优化」错误。当你使用采用 **DNS 解锁中转** 的机场时，正确的数据通路必须是：
`你的浏览器 → 代理节点（节点内由机场自建 DNS 把 netflix.com 解析为解锁机 IP）→ 解锁中转机 → Netflix 服务器`

而许多网上的教程教用户在本地 Clash 配置文件的 `dns:` 区块强行覆盖 `nameserver: [https://1.1.1.1/dns-query]` 并配合 `redir-host` 解析，或者直接在客户端先由本地发出 DNS 请求再把 IP 丢给机场节点。当机场服务端收到的只是 `1.1.1.1` 返回的常规 Netflix 官方 IP、而没有经过它节点内部特定的域名劫持路由时，机场服务端就会忠实地直接把流量发往官方 IP——从而使用该节点原本的 IDC 机房 IP 访问 Netflix，结果当场暴露并降级为「仅自制剧」！

**黄金法则**：使用支持 DNS 解锁的机场时，请保留客户端默认的 `fake-ip` 模式或由远端代理节点自行完成域名解析（不要强行在本地用外部 DoH 覆盖替换流媒体域名的解析结果），以确保域名字符串原封不动送往机场落地节点处理。

## 四、TV 端（Apple TV / Android TV）与移动端 App 硬编码 DNS 及 IPv6 绕过拦截技巧

**为什么在 Windows 或 macOS 电脑浏览器里能顺畅播放全区剧集，一旦打开 Apple TV、Android TV 电视盒子或者 iPhone / Android 官方 App，却立刻报错 `M7111-5059`、`E100`、`您似乎使用了代理或解锁工具`？** 直接答案是：TV 端与移动端原生 App 内置了比浏览器严苛数倍的 **网络环境探测与反绕过机制**。

### 1. 电视端与 App 的四大隐蔽拦截机制
1. **App 底层硬编码直连 DNS 探测（Hardcoded DNS）**
   浏览器会老老实实遵循系统代理或网关分配的 DNS，但 Netflix 官方移动端 App 与电视端 App 在代码底层硬编码了向 `8.8.8.8`、`8.8.4.4` 甚至内置 DoH 端点直接发送 DNS 查询的逻辑。当系统仅仅配置了常规 HTTP 代理而未接管底层 UDP/TCP 53 端口时，App 绕过你的代理规则拿到了本地直连 DNS 响应或对比出两侧解析不一致，直接判定为代理作弊并弹出 `E100` / `M7111-5059`。
2. **家庭网关 IPv6 泄漏（电视大屏端最高发错误）**
   目前国内光猫拨号默认开启 IPv6 RA 广播。Apple TV、Sony 电视、Shield TV 或手机连上家里 Wi-Fi 后，会自动分配到一个中国大陆的公网 IPv6 地址。即便你的软路由（如 [OpenClash](/clients/openclash/)）代理了 IPv4，电视端 App 也会优先尝试通过本地 IPv6 直连 `netflix.com` 的 AAAA 地址，导致 Netflix 后台同时抓取到了「海外 IPv4 + 中国大陆 IPv6」，瞬间封禁会话。
3. **主站与视频流 CDN 域名路由分裂**
   Netflix 将界面鉴权（`netflix.com`、`nflxso.net`）和高清视频切片传输（`nflxvideo.net`、`nflximg.net`）分离在完全不同的域名后缀下。如果客户端配置了不完整的规则，导致首页走了新加坡解锁节点，而 `nflxvideo.net` 走了直连（`DIRECT`）或落入了香港节点，TV 端就会无限卡在 `25%` 或弹出播放错误。
4. **路由器「绕过大陆 IP」与节点中转 IP 冲突**
   在软路由端，部分 DNS 解锁机恰好架设在某些特殊转发网段，如果路由器规则配置不当或 DNS 劫持模式未选对（如 Fake-IP 与部分电视盒子的连接缓存机制不兼容），会导致连接异常。

### 2. 跨终端绕过拦截标准化解决方案
针对大屏电视与手机 App，请严格按以下四步配置网络环境：
- **第一步（彻底灭杀 IPv6 泄漏）**：在代理客户端（[Clash Verge Rev](/clients/clash-verge-rev/)、[Shadowrocket](/clients/shadowrocket/)、[Stash](/clients/stash/)、[OpenClash](/clients/openclash/)）中全局设置 `ipv6: false`；如果使用软路由做全屋透明代理且电视盒子经常抢走光猫原生 IPv6，建议直接在主路由 LAN 口关闭 IPv6 DHCPv6/RA 分发，或在 OpenClash 中启用「禁止解析 IPv6 DNS 记录」。
- **第二步（开启 TUN 模式并强制劫持 UDP 53）**：手机端与电脑端安装 App 时必须开启 [TUN 虚拟网卡模式](/guides/tun/)；软路由 [OpenClash](/clients/openclash/) / [Passwall 2](/clients/passwall2/) / [Nikki](/clients/nikki/) / [HomeProxy](/clients/homeproxy/) 中务必开启 `DNS 劫持`（拦截局域网发往 `8.8.8.8:53` 与 `1.1.1.1:53` 的明文查询），同时在防火墙规则中拦截发往已知公共 DoT 端口（`TCP 853`）的直连探测流量，迫使 Netflix App 乖乖服从网关路由。
- **第三步（完整锁定全套 7 个核心域名后缀）**：在客户端建立独立的 `🎬 Netflix` 手动 `select` 策略组，将主站、图片、API 与视频 CDN 全部绑定至同一节点：

```yaml
ipv6: false

proxy-groups:
  - name: "🎬 Netflix 全区"
    type: select
    proxies:
      - "🇸🇬 新加坡解锁节点"
      - "🇭🇰 香港原生/解锁节点"
      - "🇹🇼 台湾解锁节点"
      - "🇯🇵 日本节点"
      - "🇺🇸 美国节点"

rules:
  # 强制屏蔽电视/App 向公共 DNS 端口 853 (DoT) 发起探测绕过（可选，视环境启用）
  # - DST-PORT,853,REJECT

  # 优先使用权威 GeoSite 库全覆盖
  - GEOSITE,netflix,🎬 Netflix 全区

  # 显式补全全部关联域名（包含 fast.com 官方测速域，确保测速环境一致）
  - DOMAIN-SUFFIX,netflix.com,🎬 Netflix 全区
  - DOMAIN-SUFFIX,netflix.net,🎬 Netflix 全区
  - DOMAIN-SUFFIX,nflximg.com,🎬 Netflix 全区
  - DOMAIN-SUFFIX,nflximg.net,🎬 Netflix 全区
  - DOMAIN-SUFFIX,nflxvideo.net,🎬 Netflix 全区
  - DOMAIN-SUFFIX,nflxso.net,🎬 Netflix 全区
  - DOMAIN-SUFFIX,nflxext.com,🎬 Netflix 全区
  - DOMAIN-SUFFIX,fast.com,🎬 Netflix 全区
```

- **第四步（TV 端重置网络缓存）**：修改完软路由或网关配置后，电视盒子上的 Netflix App 仍可能读取内存里缓存的旧报错会话，务必进入电视系统设置中**强制停止（Force Stop）Netflix App 或重启电视盒子**，再重新打开验证片号或热门非自制剧。

## 常见问题（FAQ）

### 1. 为什么我连上节点能正常登录 Netflix 首页，也能看《怪奇物语》，但搜《绝命毒师》等热门第三方版权剧却搜不到？
这是典型的「仅解锁自制剧（Netflix Originals Only）」降级状态。当 Netflix 检测到你的出口 IP 属于已知数据中心 IDC ASN 或多人共享代理池，但尚未将其列入完全封杀黑名单时，系统会隐藏所有第三方授权的非自制版权电影与剧集，只保留 Netflix 拥有全球发行权的自有版权内容。只有能正常检索并播放非自制版权剧，才算真正的全区解锁。

### 2. 如何不依赖第三方测速脚本，自己在浏览器里 10 秒判断节点是不是全区解锁？
在无痕浏览器打开两个权威验证地址即可交叉判定：先访问自制剧测试片号 `netflix.com/title/80018499` 确认首页未遭封锁；再访问经典非自制版权剧测试片号 `netflix.com/title/70143836`（《绝命毒师》Breaking Bad），若页面正常显示播放按钮（Play）与剧集列表且可顺利加载 1080P/4K 视频，即代表解锁了该区非自制版权库；最后顺便打开 Netflix 官方测速站 `fast.com` 并展开详细信息，核对真实拉流带宽是否稳定在 `25 Mbps` 以上。

### 3. 机场宣传的「原生 IP 解锁」和「非原生 DNS 解锁中转」有什么区别？为什么开了自定义 DoH 反而看不了全区剧？
原生 IP（或优质商业 ISP 落地）是指服务器本身的出口 IP 在风控库中直接通过 Netflix 审查，不依赖中间劫持，延迟稳定且无视本地加密 DNS 设置；而绝大多数平价机场采用的是「非原生 DNS 解锁中转」，即普通机房服务器将发往 `netflix.com` 的解析劫持转发给一台专门购买的解锁小鸡。如果你在自己的 Clash 或路由器中开启了强制本地 DoH（如向 `1.1.1.1` 加密解析）或自定义了 `nameserver-policy` 绕过机场远端 DNS，就会跳过解锁通道，瞬间被打回仅自制剧状态。

### 4. 为什么同一条节点在电脑浏览器能看 Netflix 全区剧，换成 Apple TV、Android TV 或手机 App 却报 `M7111-5059` 或 `E100` 代理错误？
电视盒子与官方移动 App 的底层反代理检测远严于网页端。常见诱因有三个：第一是 App 底层硬编码直接向 `8.8.8.8` / `8.8.4.4` 发起直连 DNS 探测，绕过了普通代理规则；第二是电视盒子或手机通过家庭路由器拿到了中国大陆运营商 IPv6 地址，访问双栈域名时产生 IPv6 泄漏；第三是主站 `netflix.com` 与视频流 CDN 域名 `nflxvideo.net` 走了不同节点的分流策略组。解决核心是在客户端与软路由彻底设置 `ipv6: false`、开启 DNS 劫持并将整套 `geosite:netflix` 锁死在同一节点。

### 5. 用 `fast.com` 测试 Netflix 速度时需要注意什么？显示高带宽就代表看 4K 一定不卡吗？
`fast.com` 是 Netflix 官方提供的测速网站，直接连接 Netflix Open Connect（OCA）内容分发节点，因此比一般 Speedtest 更贴近真实观影链路。但看 4K HDR/Dolby Vision 不仅要求总带宽稳定在 `25 Mbps` 以上，还要求低抖动与解锁中转不限速；如果机场采用小带宽的 DNS 解锁中转机统一承载全服用户的 `nflxvideo.net` 视频流，可能会出现 `fast.com` 勉强跑出速度、但晚高峰实际拉流频繁降码率到 480P 甚至卡顿转圈的现象。

### 6. 香港、台湾、新加坡、日本与美国地区的 Netflix 节点该怎么选？为什么有时台湾节点会识别成欧洲（ES）？
片库与中文字幕习惯是选区关键：香港、台湾与新加坡节点拥有最完整的繁体中文字幕与丰富的华语、港台、韩剧片库；日本区适合追新番动画且画质极佳，但大量日本本土片源没有中文字幕；美国区美剧全但部分片源仅配英文字幕。需要注意的是，部分机场会采购欧洲或跨区迁移的广播 IP 落地到台湾或亚太机房，例如在本站归档的 `2026-07` [灵动云](/brands/lingdong/)实测中，就出现了台湾节点被 Netflix 与 Disney+ 识别为西班牙（ES）的漂移情况。

### 7. 在 31 家机场品牌库中，哪些品牌明确标注支持 Netflix？选大屏电视端观影要注意什么？
根据本站 `2026-11-23` 核验的 [品牌数据库](/brands/directory/)，[光速云](/brands/guangsuyun/)、[暮光加速](/brands/muguang/)、[飞猫云](/brands/feimao/)、[微风网络](/brands/weifeng/)、[星岛梦](/brands/xingdaomeng/)、[一翻云](/brands/yifan/)、[梯子云](/brands/tiziyun/) 等 17 家品牌标注为资料支持解锁（`vendor` 级别）；[光年梯](/brands/guangnian/)标注为视节点而定（`conditional + vendor`）；[灵动云](/brands/lingdong/)在 `2026-07` 实测中被标为 `conditional + measured`（台湾落地识别偏欧）；[可信云](/brands/kexin/)等 12 家为待核实（`unknown`）。如果你需要在 Apple TV 或 OpenWrt 软路由（OpenClash）上全屋大屏看 Netflix，务必排除「仅专属客户端」的 8 家品牌（如飞猫云、隐形人、SOGO 云、Firefly 等），选择支持 Clash/Mihomo 通用订阅的品牌。
