# 多设备机场与家庭共享方案：不限设备风控边界与软路由收敛指南

<div class="answer-first-box">
  <div class="answer-first-label">核心结论 · Answer First</div>
  <p>挑选“多设备机场”与搭建“家庭共享方案”时，最致命的误区是把商家海报上的<strong>“不限设备数”</strong>误解为“全网随便分享不限人数”，或忽略了<strong>“不限设备 ≠ 支持软路由订阅”</strong>。从工程机制上看，机场后台通常通过<strong>并发源 IP 数与最大并发 TCP/UDP 连接数</strong>来约束共享行为；即便购买了库内标注不限设备的品牌，也必须优先排查其是否支持<strong>第三方通用订阅链接</strong>。拥有多台手机、电脑、Apple TV 与游戏主机的小家庭，最佳实践是在家庭网关部署运行 Mihomo 或 sing-box 的 <strong>OpenWrt 软路由（如 <a href="/clients/openclash/">OpenClash</a> 或 <a href="/clients/nikki/">Nikki</a>）</strong>，把全屋终端收敛为单一出口 IP，再配合倍率过滤与直连分流防超支。</p>
</div>

现代家庭的网络终端数量早已不止一台电脑和一部手机——客厅里的 Apple TV 4K 电视盒子、书房里的台式机与 MacBook、手头的 iPhone 与安卓备用机、客厅的 Switch/PS5 主机，甚至还有跑着容器镜像同步的 NAS。如果为每台设备单独安装客户端并手配规则，不仅电视和游戏机极其折腾，还很容易因为多台设备同时拉取流量而触发机场后台风控；反过来，如果盲目买了一个不支持导出 Clash 订阅的“不限设备”品牌，买回家才发现根本没法放进路由器里。下面我们从服务端检测机制、31 家库内品牌核对、软路由单 IP 收敛原理和流量防爆规则四个维度彻底理顺多设备共享方案。

## 一、服务端风控机制拆解：机场到底怎么统计“设备数”？

很多人好奇：代理节点本质上只是一个远端加密转发端口，机场老板怎么知道我到底连了几台设备？实际上，机场面板（如 V2Board、SSPanel 等主流后端）与节点后端程序（如 XrayR、V2bX）并不去读取你手机的硬件序列号，而是通过以下三层网络特征来判定在线设备与异常共享：

### 1. 源 IP 并发计数（最核心的“设备数”判定依据）
当你的手机连接家里 Wi-Fi、打开微信刷着信息流、电脑同时挂着后台代理时，数据包离开你家光猫后，全部顶着**同一个家庭宽带公网出口 IP（或运营商分配的同一级 NAT 出口 IP）**抵达机场的国内入口服务器。
- **在入口服务器视角**：无论你家路由器下面挂了 3 台还是 25 台设备，只要它们在家里同一个局域网走网关出去，源 IP 全部是同一个，在大部分标准计数机制下**仅算作 1 个活跃出口 IP**。
- **真正触发风控的场景**：当你把一条订阅链接同时发给广州的同学、成都的父母和北京的同事，或者你一边在公司 Wi-Fi 用电脑、一边在外面用 5G 手机、同时家里 NAS 还在挂着下载。在同一个 60 秒检测周期内，服务端后台看到同一个账号密钥（UUID）后面挂着 **4–8 个来自不同城市、不同运营商的源 IP** 在持续产生流量，风控系统就会直接触发限速或暂时踢下线。

### 2. 短时间窗口 IP 漂移与订阅拉取频率检测
除了同时在线并发 IP，很多机场还会统计每小时拉取订阅链接（Subscribe URL）的次数和来源 IP 变化。如果你把链接公开到群里或者几十人高频自动刷新订阅，订阅接口本身就会直接返回 `403` 封禁或自动重置订阅 Token，导致原本自己正常使用的设备也全部拉取失败。

### 3. 单账号最大并发连接数（Connection Limit）与端口耗尽
哪怕你只用一台笔记本电脑、只有一个公网 IP，如果你开着代理去跑 BT/PT 下载、多线程爬虫、大量 Docker 镜像并发拉取或者高频端口扫描，瞬间建立上千条并发 TCP/UDP 会话，同样会触及节点后端的 `max-connections` 保护阈值，导致网页突然全部打不开甚至暂时被节点防火墙拉黑几分钟。

> **核心结论**：所谓“不限设备数”，工程上的真实含义是**“允许同一用户在个人常见多终端（家庭网关 + 随身手机 + 办公电脑，通常表现为 1–3 个合理公网 IP 范围内）自由并发，而不卡死 2 台或 3 台的硬性连接数上限”**，绝对不是允许跨省多家庭合租分摊费用。

## 三、方案抉择与局域网单 IP 收敛原理（OpenClash / Nikki / HomeProxy）

多设备家庭共享通常有两种部署思路：**方案 A（每台设备独立安装客户端）** 与 **方案 B（OpenWrt 软路由统一网关代理）**。

### 1. 为什么软路由能够实现“全屋设备收敛为单出口 IP”？
理解原理只需看清网络数据包经过网关时的地址转换（NAT / SNAT）：

```
[手机 192.168.10.101] ──┐
[电脑 192.168.10.102] ──┼──► [OpenWrt 软路由 (OpenClash / Nikki)] ──(家庭宽带唯一公网IP)──► [机场入口服务器]
[Apple TV .103]       ──┤        ▲ 在此完成规则分流与加密封装
[PS5 / Switch .104]   ──┘        └─ 国内流量直连光猫，境外流量全部收敛进单条加密隧道
```

当你在每台设备分别装软件时，每台设备各自独立发起到机场入口的连接，不仅配置繁琐，而且手机后台切换网络极易漏出多余 IP；而把代理客户端（如运行 Mihomo 内核的 [OpenClash](/clients/openclash/) 或 [Nikki](/clients/nikki/)）部署在家庭主路由或旁路由之后：
1. **对机场服务端完全隐身内网拓扑**：所有内网设备请求首先发到软路由的 `7892/7893` TProxy 或 TUN 监听口，由软路由内核统一做域名/IP 分流后，再通过家庭宽带的同一个 WAN 口对外发起连接。在机场服务端看来，这 20 台设备只有一个完全相同的源 IP，完美规避“并发 IP 过多”风控。
2. **原生接管无客户端设备**：PlayStation、Nintendo Switch、Xbox、智能电视和 Kindle 等根本无法装代理插件的硬件，只要网关指向了软路由，不需要任何配置就能直接加速联机商店或流媒体。
3. **集中维护一份分流规则**：全屋只需要维护路由器里的那一份规则集与订阅自动更新任务，不必每次新增一台平板或重装一次系统就重新导一遍订阅。

### 2. 方案 A（多端独立装端）vs 方案 B（软路由网关）全维对比

| 评估维度 | 方案 A：各设备独立安装客户端 | 方案 B：OpenWrt 软路由统一收敛 |
| :--- | :--- | :--- |
| **品牌模式要求** | 可兼容“仅专属客户端”和“第三方订阅”两类品牌 | **强制要求支持第三方通用订阅**（Clash YAML / sing-box / Base64） |
| **无插件终端（电视/游戏机）** | Apple TV 需买专门 App，PS5/Switch 必须靠电脑开热点中转 | 局域网全终端零配置接入，还可按内网静态 IP 或 MAC 地址精准开关代理 |
| **多端协同与 IP 风控** | 电脑+平板+电视同时运行易产生过多独立隧道会话 | 全屋对外高度收敛为 **1 个家庭出口 IP**，防并发风控能力最强 |
| **外出移动/出差场景** | 本机自带软件，出门切换 5G 无缝继续使用 | 软路由只能覆盖家里 Wi-Fi；出门后手机仍需本地装 [Shadowrocket](/clients/shadowrocket/) 或 [FlClash](/clients/flclash/) |
| **突发流量烧毁风险** | 用哪台开哪台，相对可控 | 若不配置直连白名单，电视 4K、手机半夜系统升级和 NAS 拉镜像会瞬间跑飞流量 |

### 3. OpenWrt 软路由四大核心插件选型边界（必查固件版本！）
决定上软路由之前，绝对不能闭眼乱装插件——OpenWrt 近年来经历了从旧版 `fw3 (iptables)` 向新版 `fw4 (nftables)` 的底层防火墙大迁移，装错插件会直接导致路由器断网或内核无法启动。详细教程可查阅 [OpenWrt 软路由客户端中心](/clients/platform/openwrt/)：

| 软路由插件 | 底层代理核心 | 固件与防火墙硬性要求 | 核心特征与适用场景 | 教程入口 |
| :--- | :--- | :--- | :--- | :--- |
| **OpenClash** | **Mihomo** (Clash.Meta) | 兼容老版 fw3 (iptables) 与新版 fw4 (nftables) | 社区资料最庞大、界面可视化规则覆写最细、支持多机场合并与假 IP/Redir-Host 切换，适合 21.02/22.03/23.05 及新固件 | [OpenClash 配置指南](/clients/openclash/) |
| **Nikki**（原 MihomoTProxy） | **Mihomo** (Clash.Meta) | **明确要求 OpenWrt 24.10+**（纯 firewall4 / nftables） | 架构极其清爽、直接调用原生 nftables TProxy 性能损耗极低；**23.05 及以下旧版系统切勿强装** | [Nikki 配置指南](/clients/nikki/) |
| **PassWall2** | **Xray-core / sing-box** | 常见 OpenWrt 架构均可（需留意路由 Flash 空间） | 偏向单节点直接切换与分流列表管理，适合习惯 Base64 通用节点订阅的老玩家 | [PassWall2 配置指南](/clients/passwall2/) |
| **HomeProxy** | **sing-box** | OpenWrt / ImmortalWrt（firewall4 环境） | 现代原生 sing-box LuCI 界面，内存占用低；需机场提供或转换出标准的 sing-box JSON 配置 | [HomeProxy 配置指南](/clients/homeproxy/) |

### 4. 部署前必跑的 OpenWrt SSH 环境自检命令
在安装任何软路由代理包前，请通过 SSH 连入路由器终端，花 10 秒钟核对系统版本号、剩余可用闪存空间与防火墙后端，防止装包到一半爆空间卡死路由器：

```sh
# 1. 查看当前 OpenWrt / ImmortalWrt 发行版本与 CPU 架构（如 x86_64、aarch64_cortex-a53）
cat /etc/openwrt_release

# 2. 检查 /overlay 剩余可用空间（至少保留 30MB–50MB 以上再同时存放核心与 Geo 数据库）
df -h /overlay

# 3. 确认当前固件使用的防火墙后端是 fw4 (nftables) 还是 fw3 (iptables)
which fw4 && nft --version || which fw3
```

## 四、家庭多端并发的流量测算与防超支配置实战

从单人单设备切换到全家共享（尤其是接入了客厅 4K 智能电视与多部手机之后），每个月的代理流量消耗通常会从原来的 `30–50GB/月` 猛增至 **`200–500GB/月`**。如果不做防超支保护，哪怕买了 300GB 套餐也可能在半个月内归零。以下四项规则是家庭软路由上线当天必须同步落实的保护锁：

### 1. 核清各场景月度流量消耗基数，按需选档
- **日常网页浏览 + 微信消息 + AI 对话**：每人每月约 `15–30GB`；
- **YouTube / Netflix 1080p 视频**：约 `1.5–3GB/小时`；
- **YouTube / Netflix 4K HDR 流媒体**：高达 **`7–12GB/小时`**（每天晚上全家看两小时 4K 剧集，一个月仅电视盒子就要吃掉 **400GB 以上**）；
- **合理档位参考**：3 人以上有电视观影需求的家庭，建议月付套餐直接从 **300GB–500GB 档位**起步（如 [光速云](/brands/guangsuyun/) 流光版 268GB/¥34 或量子版 568GB/¥68、[星岛梦](/brands/xingdaomeng/) 进阶 300GB/¥50 或闪光 500GB/¥70、[一翻云](/brands/yifan/) 舒享版 350GB/¥35 或尊享版 600GB/¥55）。

### 2. 严防自动测速组选中 `2× / 3×` 高倍率节点（核心防超支脚本）
很多机场订阅里同时混杂了 `1×` 常规专线节点和 `2×`、`3×` 甚至 `5×` 的昂贵稀有地区节点（比如某些住宅家宽 IP 或特殊 IPLC 节点）。如果你在软路由的 `url-test` 自动测速组里不加过滤地把所有节点都塞进去，只要有一次高倍率节点延迟比普通节点低 10 毫秒，全家人晚上看 4K 视频就会按 **3 倍速度扣流量**！

在使用 Mihomo 核心的 [OpenClash](/clients/openclash/) 或 [Nikki](/clients/nikki/) 时，务必在策略组或订阅覆写中添加正则表达式过滤，将包含 `2x`、`3x`、`5x`、`高倍率` 字样的节点排除在家庭主力自动组之外（同时优先选择像 [星岛梦](/brands/xingdaomeng/)、[唯兔云](/brands/weitu/)、[光速云](/brands/guangsuyun/) 极速版这种明确注明 `1倍` 的方案）：

```yaml
# Mihomo / OpenClash 策略组正则过滤示例：主力组仅允许 1 倍或未标高倍率的常规亚太节点进入
proxy-groups:
  - name: "🏠 家庭主力低倍率组"
    type: url-test
    use:
      - my-airport-provider
    # 仅保留香港/日本/新加坡/台湾，且剔除任何标注 2x / 3x / 5x / 高倍率 / IPLC高倍 的节点
    filter: "^(?=.*(香港|日本|新加坡|台湾|HK|JP|SG|TW))(?!.*(2x|3x|4x|5x|2\\.0|3\\.0|高倍|倍率)).*$"
    url: "https://cp.cloudflare.com/generate_204"
    interval: 300
    tolerance: 80
```

### 3. 强制国内大流量下载与游戏更新直连（防止烧穿机场配额）
软路由最怕的不是正常看网页，而是下面三类“无声流量黑洞”：
1. **Steam / Epic / PS5 / Xbox 游戏包下载与更新**：动辄 50GB–100GB 的游戏安装包，只要走错一点 CDN 规则就会瞬间清空月度配额。
2. **手机 iCloud 自动备份 / 相册同步 / 系统 OTA 更新**：全家三四部手机半夜插着电自动更新 iOS 和同步几千张 4K 照片，如果苹果 CDN 规则误走代理，一晚上能跑掉几十 GB。
3. **NAS / BT / PT 挂机下载**：**必须在软路由“访问控制（MAC/内网 IP 黑白名单）”中将 NAS 下载机或专属 BT 设备直接设为绕过代理（直连）**，既省流量又能避免上千条 P2P 并发连接触发机场封号。

确保你在 OpenClash / Nikki 中开启了最新的 `geosite:cn`、`geoip:cn` 与 `geosite:apple-cn`、`geosite:steam@cn` 等主流直连规则集（完整分流工程实践见 [分流规则（GeoIP/GeoSite/Rule-Set）深度教程](/guides/routing/)）。

### 4. 家庭 + 户外移动端的双轨协同技巧
软路由接管了家里所有固定和连 Wi-Fi 的手机后，最后一步是为出门在外的手机做好衔接：
- **同一份支持通用订阅的套餐，完全可以同时填在家里软路由和手机的 [Shadowrocket](/clients/shadowrocket/) / [FlClash](/clients/flclash/) 中**：在家连着 Wi-Fi 时手机关掉本地代理 App（直接吃软路由网关即可，避免双重代理冲突耗电）；出门切到 5G 蜂窝网络时打开手机代理开关。
- **使用自动化快捷指令省心切换**：在 iPhone 的“快捷指令（Shortcuts）”中设置自动化规则——“当手机连接到家里 Wi-Fi 名称时，自动关闭 Shadowrocket；当断开家里 Wi-Fi 时，自动开启 Shadowrocket”。这样既不会让手机在家里画蛇添足做二次代理，又能保证出门无缝上网，而且对机场后台而言，家里网关（1 个 IP）+ 出门在外的 1 到 2 部手机（各 1 个移动 IP）永远处于安全合乎常理的并发范围内。

## 常见问题（FAQ）

### 机场写着“不限设备数”，我把订阅分享给异地朋友和父母家一起用会被封号吗？
极高概率触发风控限速或封号。绝大多数机场后台并不是去数你手机电脑的 MAC 地址，而是实时监测同一账户在短时间内并发访问节点的公网源 IP 数量。同一家庭 Wi-Fi 下十台设备对外通常只表现为 1 个家庭出口 IP；一旦检测到 4 个以上跨省跨运营商 IP 同时拉取流量，仍会被判定为违规转卖或多人合租。

### 数据库里标注了“不限设备”的品牌，是不是全部都能直接装进软路由给全家人用？
绝对不是！支持“不限设备”和“提供第三方通用订阅链接”是两个完全独立的参数。例如 [Firefly（萤火虫）](/brands/firefly/) 和 [灵猫网络](/brands/lingmao/) 虽然均标注不限设备，但它们明确采用“仅专属客户端”模式，不提供订阅链接，根本无法导入 [OpenWrt 软路由](/clients/platform/openwrt/) 的 OpenClash 或 Nikki；购买家庭共享方案前必须核查 `clientMode` 是否支持第三方订阅。

### 家里设备多且包含 Apple TV、Switch、PS5 和智能电视，该每台装端还是上软路由？
强烈推荐部署 OpenWrt 软路由（旁路由或主路由）。电视盒子、游戏主机和 IoT 设备大多无法直接安装代理客户端，在网关层面运行 [OpenClash](/clients/openclash/)、[Nikki](/clients/nikki/) 或 [HomeProxy](/clients/homeproxy/) 后，全屋所有设备不仅零配置自动分流，而且在机场入口侧永远收敛为唯一一个家庭公网出口 IP。

### OpenWrt 软路由部署 OpenClash 和 Nikki（原 MihomoTProxy）该怎么选？
核心分水岭在于你的 OpenWrt 固件版本与防火墙架构。[OpenClash](/clients/openclash/) 兼容性极广，同时支持老版本的 `fw3 (iptables)` 与新版本 `fw4 (nftables)`，生态教程最全；而 [Nikki](/clients/nikki/) 虽然架构更精简且 TProxy 转发性能优异，但官方项目明确要求 **OpenWrt 24.10 及以上版本（firewall4）**，在 21.02、22.03 或 23.05 旧版固件上切勿强行安装。

### 家里开了软路由给全屋共享后，手机出门切 5G 移动网络还能同时用同一个机场订阅吗？
可以，但要注意控制并发与连接数。家庭网关算 1 个出口 IP，外出手机开 5G 算第 2 个出口 IP，对一般个人或小家庭而言 2 个并发 IP 属于正常合理范围。只要手机端不要同时运行大并发下载，且确认机场本身没有严苛的“单 IP 锁死”限制即可顺畅协同。

### 为什么家里接上软路由后，原本够用的 100GB 月流量几天就见底了？
最常见的原因有两个：第一是电视盒子播放 4K 视频或手机系统自动备份、Steam 游戏更新误走了代理通道；第二是软路由的 `url-test` 自动测速组不小心选中了订阅里带有 `2×` 或 `3×` 高倍率的节点，看一晚高清剧集直接扣掉双倍或三倍配额。必须配置规则直连保护与高倍率正则过滤。

### 有没有适合家庭多设备共享的“不限设备 + 全节点 1 倍流量 + 支持通用订阅”组合思路？
在选购前先做三项对齐：确认支持第三方订阅导入（避开仅专属客户端）、尽量挑选明确标注 `1 倍` 流量且月流量在 `200GB–500GB` 以上的档位（例如 [光速云](/brands/guangsuyun/) 流光版 268GB 或极速版 168GB 标全节点×1 且双支持，或核实面板支持通用订阅的 [星岛梦](/brands/xingdaomeng/) 300GB/500GB 1 倍档、[一翻云](/brands/yifan/) 350GB 档），并在路由器内做好国内下载直连分流。
