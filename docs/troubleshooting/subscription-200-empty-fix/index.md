faq:
  - q: 为什么订阅链接返回 HTTP 200，但下载下来的配置文件大小是 0 字节或节点列表为空？
    a: 绝大多数面板系统会根据 HTTP 请求头中的 User-Agent 字段动态匹配客户端配置模板，或针对未知请求头启用防扫描静默丢弃。当客户端发送空 User-Agent、浏览器默认 UA 或不被面板白名单识别的自定义请求头时，后端不会返回 403，而是直接下发 HTTP 200 状态码配 0 字节空响应体，或在排除不兼容的新协议节点后只留空壳结构。将订阅设置中的 User-Agent 显式指定为 clash-verge/v2.2.3 或 mihomo/1.18.0 通常即可恢复。
  - q: 更新订阅时总是报连接超时或 EOF，是不是必须挂着代理才能更新订阅？
    a: 恰恰相反，排障第一步必须先关闭系统代理和 TUN 模式进行直连更新。当旧节点已经全部断网时，如果客户端仍开着系统代理或启用了通过代理更新订阅，拉取新订阅的 HTTP 请求也会被客户端拦截并塞进已经失效的死隧道里，形成代理环路死循环。只有在关闭本地全部代理后直连依然超时，确认订阅域名本身已被当前宽带阻断时，才应切换手机蜂窝热点或借道某个确定存活的备用节点进行代理更新。
  - q: 用 curl 测试订阅链接时，直接访问返回 0 字节而加上 -A 参数就出现完整配置，说明什么问题？
    a: 这可以直接实锤故障完全不在网络连通性，也不在账号到期，而是典型的服务端 User-Agent 策略拦截。不带 -A 参数时 curl 默认发送 curl/8.x 请求头，被机场分发网关当作普通脚本或爬虫直接静默返回空内容；加上 -A "clash-verge/v2.2.3" 后服务端命中了 Mihomo/Clash 模板白名单，因此正常吐出了 YAML 节点列表。回到客户端订阅编辑界面把 User-Agent 改成一致的值即可。
  - q: 为什么服务端返回了 HTTP 200 且字节数正常，客户端导入时却报错 yaml unmarshal errors？
    a: 返回状态码为 200 且文件不为空但无法解析，常见有三类情况：第一是返回了 Cloudflare 验证码盾网页、机场登录 HTML 页面或运营商劫持提示页，只是页面状态码恰好为 200；第二是把 Base64 节点文本直接导入了只支持 YAML 的 Mihomo 客户端；第三是中转或自建配置文件带入了 UTF-8 BOM 隐藏文件头或全角空格、制表符 Tab 缩进错误。用文本编辑器或 curl.exe -i 查看响应前十行即可一目了然。
  - q: 订阅链接在微信或 QQ 里转发一次再复制粘贴，为什么更新总是返回空或者提示 Token 无效？
    a: 即时通讯软件的链接安全预览与自动排版功能经常破坏订阅 URL 结构。常见破坏包括把 & 符号转义成 &amp;、在长网址末尾截断查询参数、在参数中混入不可见的换行符或零宽空格，甚至在聊天窗口里自动触发预览爬虫导致某些带防爆破策略的订阅接口临时拉黑请求。建议始终从网页面板直接点击复制按钮获取完整原始 URL，并先粘贴到纯文本记事本核对首尾字符。
  - q: 套餐到期或流量超限后，为什么有的订阅链接不报错而是返回一个只有提示节点的空配置文件？
    a: 为了防止客户端每小时自动重试请求打满服务端接口，不少面板在检测到用户套餐到期、流量耗尽或订阅 Token 已被封禁重置时，不会返回 401 或 404，而是依然返回 HTTP 200 并下发一个仅包含一两条“套餐已过期/剩余流量不足”占位信息的最小配置文件，或者干脆返回空 proxies 列表。登录服务商官网控制台核对到期日与可用流量即可确认。

# 订阅链接返回 200 但内容为空或更新失败怎么办？代理环路与 UA 拦截修复

<div class="answer-first-box">
  <div class="answer-first-label">核心结论（Answer-First）</div>
  <p>当你遇到<strong>“订阅链接返回 200 但内容为空（0 字节）”</strong>、<strong>“点击更新订阅一直转圈超时”</strong>或<strong>“拉回内容却报 YAML 解析错误”</strong>时，不要反复重装客户端。此类故障几乎全部落在五个可快速实测定位的环节：<strong>代理环路死循环</strong>（开着失效代理去拉取订阅）、<strong>服务端 User-Agent 拦截</strong>（未匹配到 <code>clash-verge</code> 等白名单 UA 时后端静默返回 <code>200</code> 与空响应体）、<strong>订阅域名遭 DNS 污染或 SNI 阻断</strong>、<strong>UTF-8 BOM 与格式错配</strong>（返回 HTML 或 Base64 混入 YAML），以及<strong>套餐过期/Token 失效下发空占位配置</strong>。先关闭所有系统代理与 TUN 开关，再用脱敏后的 <code>curl.exe -i</code> 与 <code>curl -A "clash-verge/v2.2.3"</code> 对照探测，3 分钟内即可精准定界并修复。</p>
</div>

## 一、症状判断：5 类“订阅返回 200 空内容或更新失败”快速定界

不同客户端在拉取订阅异常时的提示文案略有差异，但底层 HTTP 响应特征高度一致。在修改任何配置前，先对照下表锁定你当前命中的故障象限：

| 客户端界面现象与报错 | `curl` 实测响应特征 | 第一嫌疑根因 | 排查优先级 |
|---|---|---|---|
| 点击更新后提示 `HTTP 200` 但节点数为 0，或文件显示 `0 B` | `HTTP/2 200` 且 `content-length: 0` | **User-Agent 拦截**（面板按 UA 过滤或旧 UA 剔除了新协议节点） | 最高（第 2 步直出） |
| 提示 `HTTP 200`，导入却报 `yaml: unmarshal errors` 或非法字符 | `HTTP/2 200`，正文开头为 `&lt;html&gt;`、Base64 串或 `\xEF\xBB\xBF` | **HTML 盾页/格式错配**，或自建转换文件带有 **UTF-8 BOM 头** | 高（查看响应首行） |
| 更新按钮转圈 10 秒后报 `timeout`、`EOF` 或 `context deadline exceeded` | 客户端超时；关闭代理直连 `curl` 却秒出结果 | **代理环路死循环**（开着已断网的旧代理去请求订阅服务器） | 最高（第 1 步先关代理） |
| 关闭代理直连同样报 `Connection reset`、TLS 握手中断或跳转陌生页面 | `curl` 返回解析到 `127.0.0.1`/异常 IP，或 TLS 握手被重置 | **订阅域名 DNS 污染 / SNI 阻断**，或本地时钟偏差 | 高（第 3 步切 DNS/热点） |
| 更新后没有任何报错，节点列表里只剩一条“已过期/流量不足”提示节点 | `HTTP/2 200`，响应头中无有效可用流量或正文仅含占位说明 | **Token 失效、套餐到期或面板风控空占位返回** | 中（核对官网账户状态） |

如果你的故障属于更广泛的订阅导入基础操作、证书有效期或在线转换工具安全风险，可以先结合 [订阅更新失败与 200+0 字节总览排查](/troubleshooting/subscription/) 与 [代理订阅导入与自动更新基础指南](/guides/subscription/) 交叉核对。

## 二、原因分类：深入拆解五大致命根因

把五种看似都表现为“更新不了”的故障拆开，能避免你在“换客户端”和“重置电脑网络”之间盲目兜圈。

### 1. 代理环路死循环（System Proxy / TUN 开启期间自锁）

这是所有桌面与移动端用户最容易忽视的逻辑闭环。假设你昨天使用的节点今天已经失效或中转入口更换，客户端界面依然开着**系统代理（System Proxy）**或 **TUN 虚拟网卡模式**，或者你在订阅卡片设置里勾选了“使用代理更新（Update with Proxy）”。

当你点击刷新订阅时，客户端发往订阅域名的 HTTPS 请求并不会直接走本地宽带出去，而是被操作系统或客户端自身的路由钩子重新拦截，送进那个**已经彻底不通的旧代理通道**。结果就是“想靠更新订阅救活代理，更新订阅的请求却死在旧代理里”，表现为无限转圈、超时或 `EOF` 断开。只要当前存在失效代理接管，重试一百次都无法成功。

### 2. User-Agent 白名单拦截与空响应（返回 200 却 0 字节或 HTML）

现代主流分发面板（如 V2Board、Xboard、SSPanel 及其衍生网关）普遍把一条订阅地址作为多端统一入口，后端服务器依赖 HTTP 请求头中的 `User-Agent`（简称 UA）来决定下发什么内容。这会引发两种典型的“假成功”返回：

- **防探测静默返回 0 字节**：为防止扫描器遍历订阅接口暴露节点 IP，许多服务端只放行白名单内的代理客户端 UA（如 `clash-verge`、`mihomo`、`ClashMetaForAndroid`、`sing-box`、`Shadowrocket`、`v2rayN`）。当客户端发送了空白 UA、未登记的冷门自定义 UA，或者用户在浏览器直接粘贴订阅地址发送了 `Mozilla/5.0` 时，后端为了不返回明显的错误码误导探测，会故意返回状态码 `200 OK` 但响应体长度为 `0` 字节，甚至直接返回一个伪装空白页或登录跳转 HTML。
- **旧版 UA 触发协议全量过滤**：许多服务商节点已全面迁移到 VLESS-Reality、Hysteria 2 或 AnyTLS 等新协议。如果你的客户端发送了老旧原版客户端标识（例如早已停止维护的 Clash for Windows 请求头，或 URL 中带有 `?flag=clash` 而非 `?flag=meta`），面板脚本在筛选节点时会判定你的内核不支持上述全部新协议，把不兼容节点全部剔除后，依然返回 `HTTP 200`，但 `proxies` 字段是空的，导入客户端后看起来就像“内容为空”。

### 3. 订阅域名 DNS 污染、SNI 阻断与链接字符截断

国内网络环境下，部分订阅分发域名如果没有接入国内高防或独立轮换域名，很容易遭遇本地宽带运营商 DNS 污染或防火墙 SNI 阻断：

- **DNS 污染劫持**：本地运营商 DNS 将订阅域名解析到一个错误的内网地址（如 `127.0.0.1`、`0.0.0.0`）或反诈拦截提示服务器，甚至返回一个状态码为 `200` 的运营商拦截提示 HTML 页面，导致客户端误以为拉取成功却在解析阶段报错。
- **TLS SNI 阻断**：域名解析出了真实 IP，但在 TLS ClientHello 握手阶段因为明文携带了敏感订阅域名 SNI，直接被中间设备发 TCP RST 重置（表现为 `connection reset by peer` 或 `EOF`）。
- **复制转义损坏参数**：把订阅链接通过微信、QQ 或某些笔记软件中转复制时，`&` 常被转义成 `&amp;`，长 Token 末尾缺字符，或头部混入空格与换行符，服务端查不到对应 Token 时同样可能返回 200 空内容。

### 4. YAML 语法损坏、格式错配与 UTF-8 BOM 隐藏字符

即便网络完全畅通、UA 也命中了模板，客户端本地解析器依然可能因为文本格式和字节编码问题报错罢工：

- **格式张冠李戴**：[Clash Verge Rev](/clients/clash-verge-rev/)、[FlClash](/clients/flclash/) 等基于 [Mihomo](/clients/mihomo/) 内核的客户端只认结构化 YAML 配置文件；如果订阅返回的是 Base64 编码节点文本、纯 `sing-box` JSON，或者是服务端触发 Cloudflare WAF 返回的五秒盾网页 HTML，解析器就会立即抛出 `yaml: unmarshal errors: cannot unmarshal !!str`。关于三类格式边界可参考 [代理订阅格式全解析](/guides/subscription-formats-explained/)。
- **UTF-8 BOM 头作祟**：部分用户自己用 Windows 记事本修改过本地托管配置、或使用了不规范的中转脚本生成订阅文件时，文件最前面会被写入 3 个不可见的字节序标记（`0xEF 0xBB 0xBF`，即 UTF-8 BOM）。严苛的 YAML 解析器会把首行 `port:` 或 `proxies:` 前面的不可见 BOM 字节当成非法键名，导致整份配置直接解析失败或表现为空配置。

### 5. 过期、停用或被重置的 Token 返回空占位文件

订阅链接本质上是把账户认证凭据编码在 URL 的 Token 参数中。以下状态变化都会导致返回看似正常但无可用节点的结果：
- 套餐已过期或当月流量配额已经耗尽，面板按策略下发只含“到期提醒”的空壳配置或空节点列表；
- 账户因触发并发设备数限制或异常请求频率被风控冻结，或在官网后台手动点击过“重置订阅链接”，导致旧链接里的 Token 瞬间作废；
- 极少数情况下，面板后端数据库与 Redis 缓存脱节，返回了缺少 `proxies:` 核心字段的残缺模板。

## 三、逐项检查：PowerShell 与 curl 安全脱敏实操诊断

排障时不要在客户端里盲目连点十几次“更新订阅”，高频失败请求很容易触发服务端的 Cloudflare 速率限制（429/403）。正确做法是在 Windows PowerShell（macOS/Linux 使用终端）中用命令行执行**只读、可控请求头的精准诊断**。

> **安全脱敏提醒**：你的订阅链接包含账户私有 Token，严禁将完整链接发给他人或粘贴到公共群聊与来路不明的在线转换网站。以下所有测试均仅在**本机终端**运行，且如果截图求助务必将 `token=...` 部分打码。

### 第 1 步：强制关闭代理并验证纯直连响应头（`curl.exe -i`）

先在代理客户端界面**关闭「系统代理」与「TUN 模式」**，确认当前浏览器和终端处于裸网直连状态。随后打开 PowerShell，用系统自带的 `curl.exe`（注意在 PowerShell 中必须写全 `curl.exe`，否则 `curl` 会被解析为 PowerShell 的 `Invoke-WebRequest` 别名，参数语法完全不同）抓取响应头与前几行内容：

```powershell
# 1. 将 <订阅链接> 替换为你的真实 URL（保留外层双引号）
# -i 显示完整 HTTP 响应头；-L 跟随重定向；-sS 静默进度条但保留报错；--max-time 10 限制超时
curl.exe -i -L -sS --max-time 10 "<订阅链接>" | Select-Object -First 30
```

如果你只想先看状态码、响应长度和流量配额头而不打印正文，可以追加 `-I` 或限制只看头部与前几字节：

```powershell
# 仅探测响应头与实际下载字节数、HTTP 状态码
curl.exe -sS -o NUL -w "HTTP状态码:%{http_code} 下载字节数:%{size_download} 总耗时:%{time_total}s\n" "<订阅链接>"
```

**如何解读第 1 步结果**：
- **情况 A（直接超时 / `Could not resolve host` / `Connection reset`）**：说明当前裸网直连根本无法触达订阅域名（DNS 污染或 SNI 阻断），直接跳到下文第 3 步做域名解析排查，或临时换手机 5G 热点复测。
- **情况 B（输出 `HTTP状态码:200 下载字节数:0`）**：恭喜你，网络通路 100% 正常！你精准命中了 **UA 拦截或 Token 返回空**，立即执行第 2 步做对照实验。
- **情况 C（`下载字节数` 大于 0，但前 30 行显示 `&lt;!DOCTYPE html&gt;`、纯乱码字母或空白符号）**：说明返回了拦截页或 Base64 文本，执行第 2 步并检查文本格式与 BOM。

### 第 2 步：显式模拟客户端 User-Agent 对照探测（`curl -A`）

现在保持直连状态，给 `curl.exe` 强制加上现代客户端请求头，对比返回字节数与正文开头的变化：

```powershell
# 测试 1：模拟 Clash Verge Rev / Mihomo 标准请求头
curl.exe -sS -A "clash-verge/v2.2.3" -o NUL -w "UA=clash-verge 状态码:%{http_code} 字节数:%{size_download}\n" "<订阅链接>"

# 测试 2：对照查看实际返回的前 20 行正文（确认是 YAML、Base64 还是 HTML）
curl.exe -sS -L -A "clash-verge/v2.2.3" "<订阅链接>" | Select-Object -First 20
```

如果测试 1 返回字节数依然为 `0`，可以继续测试其他主流 UA 与后缀参数（注意若原 URL 中已有 `?`，拼接参数请用 `&flag=meta`；若无 `?` 则用 `?flag=meta`）：

```powershell
# 测试备选 Mihomo / sing-box 请求头
curl.exe -sS -A "ClashMetaForAndroid/2.11.5" -o NUL -w "UA=CMFA 状态码:%{http_code} 字节数:%{size_download}\n" "<订阅链接>"
curl.exe -sS -A "sing-box" -o NUL -w "UA=sing-box 状态码:%{http_code} 字节数:%{size_download}\n" "<订阅链接>"
```

**对照判读**：
- 不加 `-A` 时为 `0` 字节，加上 `-A "clash-verge/v2.2.3"` 后瞬间变成几万到几十万字节，且正文前 20 行出现 `port:`、`mixed-port:`、`proxies:` 等标准 YAML 字段——**100% 实锤服务端 UA 拦截**。
- 无论怎么换 `-A`，正文都是 `&lt;html&gt;` 验证码页（如 Cloudflare `Just a moment...`）——说明当前宽带出口 IP 被 WAF 盾拦截，或订阅域名已改为官网展示页。
- 无论怎么换 `-A` 与参数，状态码始终是 `200` 且字节数为 `0`——高度指向你的**订阅 Token 已失效/被重置**，或账户已到期且面板策略设为返回空体。

### 第 3 步：排查本地 DNS 污染与检查 UTF-8 BOM 隐藏头

如果第 1 步出现连接重置、超时，或怀疑自建/中转配置存在隐藏编码错误，用下面两条命令做精确验尸：

```powershell
# 1. 从订阅 URL 中提取域名，对比系统默认 DNS 与公共 DoH/阿里 DNS 的解析结果是否一致
nslookup sub.example.com
nslookup sub.example.com 223.5.5.5

# 2. 将拉取到的订阅文件保存为临时文件，检查前 6 个字节的十六进制编码（排查 UTF-8 BOM：EF BB BF）
curl.exe -sS -A "clash-verge/v2.2.3" "<订阅链接>" -o "$env:TEMP\sub_check.txt"
Format-Hex -Path "$env:TEMP\sub_check.txt" | Select-Object -First 2
```

**判读要点**：
- 若本机默认 `nslookup` 返回了 `127.0.0.1`、`0.0.0.0`、内网保留段，或与 `223.5.5.5` 返回的 IP 完全不同，即可确认本地遭遇了 **DNS 污染或路由劫持**。
- 若 `Format-Hex` 输出的第一行前三个字节显示为 `EF BB BF`，则证明该配置文件带有 **UTF-8 BOM**，部分解析器会因此报错或无法识别首行字段（检测完毕后记得执行 `Remove-Item "$env:TEMP\sub_check.txt"` 清理包含订阅内容的临时文件）。

## 四、修复操作：按根因精准解除拦截与环路

根据上一节 `curl.exe` 的诊断结论，直接执行对应的修复方案：

### 修复方案 A：解除代理环路并配置正确拉取策略

1. 在 [Clash Verge Rev](/clients/clash-verge-rev/)、[FlClash](/clients/flclash/) 或 [v2rayN](/clients/v2rayn/) 中，**先同时关闭「系统代理」与「TUN 模式」**。
2. 在 Clash Verge Rev 的「订阅（Profiles）」页面，右键你的订阅卡片选择 **「编辑信息（Edit Info）」**，确保代理拉取选项处于默认直连状态（**不要勾选**“使用系统代理更新”或“使用 Clash 代理更新”，除非你明确知道该订阅域名已被国内彻底阻断且当前有一个可用的备用节点）。
3. **如果订阅域名确已被本地宽带阻断**：先不要硬刷新，而是连接**手机 5G 热点**让电脑直连更新一次；或者在节点列表里找一个还能 ping 通的冷门地区节点选中后，再临时勾选“使用代理更新”，拉回最新订阅后记得立刻改回直连策略。

### 修复方案 B：修正客户端 User-Agent 与订阅格式参数

1. **在 Mihomo / Clash 系客户端（Clash Verge Rev / FlClash）中**：
   - 右键订阅卡片 →「编辑信息（Edit Info）」→ 找到 **`User-Agent`** 字段，填入 `clash-verge/v2.2.3`（或 `mihomo/1.18.0`）。
   - 如果此前在官网复制的链接末尾没有指定模板参数，且服务端同时兼容多种格式，可在确认原始 URL 无误的前提下，尝试在面板重新复制标注为 **「Clash Meta / Mihomo」** 的专用订阅地址，避免手动拼接错 `?` 和 `&`。
2. **在多核心或跨格式客户端（[v2rayN](/clients/v2rayn/) / [Hiddify](/clients/hiddify/) / [Karing](/clients/karing/)）中**：
   - 使用 v2rayN 时务必分清导入入口：复制的是 Base64 通用订阅就走常规订阅分组；复制的是 Clash YAML 配置则应切换兼容核心并匹配对应 UA，切勿把 Base64 文本喂给要求 YAML 的入口，也不建议依赖来路不明的第三方公共在线转换接口以免泄露订阅 Token。
   - 使用 Hiddify 或 Karing 时，如遇到服务端不支持直接识别其默认 UA 返回 0 字节，可在订阅高级设置里把 UA 伪装为 `clash-verge/v2.2.3` 拉取完整规则配置。

### 修复方案 C：绕过 DNS 污染与 SNI 阻断

1. **修复本地网卡 DNS**：若 `nslookup` 证实本地 DNS 被劫持，进入 Windows 网络适配器设置将 IPv4 DNS 改为 `223.5.5.5` 与 `119.29.29.29`，或使用客户端内针对订阅域名的加密 DoH 解析功能，避免污染节点下发错误 IP。详细 DNS 链路问题可参阅 [DNS 错误与泄漏排查修复方案](/troubleshooting/dns-leak-and-hijack-fix/)。
2. **切换备用订阅入口**：主流服务商通常在官网用户中心提供多个备选订阅地址（或防屏蔽域名）。直连主域名遭遇 SNI 重置时，登录控制台切换到备用域名重新导入，或先在浏览器直接下载 `.yaml` 配置文件后通过客户端「导入本地文件」应急恢复联网，联网后再更新远程订阅。

### 修复方案 D：清除 UTF-8 BOM 与修复受损 URL / Token

1. **清除自建配置 UTF-8 BOM**：如果是自建服务端、托管规则或本地保存的配置文件报 YAML 解析错误，用 VS Code、Notepad++ 等编辑器打开文件，在右下角编码栏选择 **「转换为 UTF-8（无 BOM）」**（UTF-8 without BOM）并保存；Linux/PowerShell 环境下也可用命令剥离首部 3 字节 BOM。
2. **核对 URL 完整性与账户配额**：登录服务商控制面板，确认套餐未到期且剩余流量大于零；若怀疑订阅链接在社交软件转发过程中损坏或 Token 已被泄露风控，直接在官网点击**「重置订阅链接」**生成全新 Token，再用纯净文本方式复制导入客户端，并及时删除已失效的旧订阅卡片。

## 五、验证结果：三项硬指标确认彻底恢复

完成上述修复动作后，不要只凭感觉点一下开关，请依次核验以下三项标准：

1. **命令行体积与结构验证**：在对应网络状态下运行 `curl.exe -sS -A "clash-verge/v2.2.3" "<订阅链接>" | Select-Object -First 15`，确认返回状态码为 `200`，下载大小脱离 `0 B`（常见完整 Clash 配置通常在数万字节以上），且开头出现清晰的 `proxies:` 或节点结构定义，无 `&lt;html&gt;` 标签与 BOM 乱码。
2. **客户端导入与卡片配额验证**：在客户端中点击刷新订阅，观察状态提示变为“更新成功”，配置文件大小显示正常；双击进入节点列表能看到完整地区分组且执行真连接延迟测速时有正常毫秒级延迟返回；若服务端支持 `subscription-userinfo` 响应头，卡片上还应正常刷新出剩余流量与套餐到期时间。
3. **自动更新安全性复查**：确认客户端的「自动更新间隔（Auto Update Interval）」设置为合理周期（如 `720` 或 `1440` 分钟），避免每几分钟高频拉取触发面板限流，同时确保本地保留了正常无污染的系统网络状态。

## 六、常见问题（FAQ）

### 为什么订阅链接返回 HTTP 200，但下载下来的配置文件大小是 0 字节或节点列表为空？

绝大多数面板系统会根据 HTTP 请求头中的 User-Agent 字段动态匹配客户端配置模板，或针对未知请求头启用防扫描静默丢弃。当客户端发送空 User-Agent、浏览器默认 UA 或不被面板白名单识别的自定义请求头时，后端不会返回 403，而是直接下发 HTTP 200 状态码配 0 字节空响应体，或在排除不兼容的新协议节点后只留空壳结构。将订阅设置中的 User-Agent 显式指定为 clash-verge/v2.2.3 或 mihomo/1.18.0 通常即可恢复。

### 更新订阅时总是报连接超时或 EOF，是不是必须挂着代理才能更新订阅？

恰恰相反，排障第一步必须先关闭系统代理和 TUN 模式进行直连更新。当旧节点已经全部断网时，如果客户端仍开着系统代理或启用了通过代理更新订阅，拉取新订阅的 HTTP 请求也会被客户端拦截并塞进已经失效的死隧道里，形成代理环路死循环。只有在关闭本地全部代理后直连依然超时，确认订阅域名本身已被当前宽带阻断时，才应切换手机蜂窝热点或借道某个确定存活的备用节点进行代理更新。

### 用 curl 测试订阅链接时，直接访问返回 0 字节而加上 -A 参数就出现完整配置，说明什么问题？

这可以直接实锤故障完全不在网络连通性，也不在账号到期，而是典型的服务端 User-Agent 策略拦截。不带 -A 参数时 curl 默认发送 curl/8.x 请求头，被机场分发网关当作普通脚本或爬虫直接静默返回空内容；加上 -A "clash-verge/v2.2.3" 后服务端命中了 Mihomo/Clash 模板白名单，因此正常吐出了 YAML 节点列表。回到客户端订阅编辑界面把 User-Agent 改成一致的值即可。

### 为什么服务端返回了 HTTP 200 且字节数正常，客户端导入时却报错 yaml unmarshal errors？

返回状态码为 200 且文件不为空但无法解析，常见有三类情况：第一是返回了 Cloudflare 验证码盾网页、机场登录 HTML 页面或运营商劫持提示页，只是页面状态码恰好为 200；第二是把 Base64 节点文本直接导入了只支持 YAML 的 Mihomo 客户端；第三是中转或自建配置文件带入了 UTF-8 BOM 隐藏文件头或全角空格、制表符 Tab 缩进错误。用文本编辑器或 curl.exe -i 查看响应前十行即可一目了然。

### 订阅链接在微信或 QQ 里转发一次再复制粘贴，为什么更新总是返回空或者提示 Token 无效？

即时通讯软件的链接安全预览与自动排版功能经常破坏订阅 URL 结构。常见破坏包括把 & 符号转义成 &amp;、在长网址末尾截断查询参数、在参数中混入不可见的换行符或零宽空格，甚至在聊天窗口里自动触发预览爬虫导致某些带防爆破策略的订阅接口临时拉黑请求。建议始终从网页面板直接点击复制按钮获取完整原始 URL，并先粘贴到纯文本记事本核对首尾字符。

### 套餐到期或流量超限后，为什么有的订阅链接不报错而是返回一个只有提示节点的空配置文件？

为了防止客户端每小时自动重试请求打满服务端接口，不少面板在检测到用户套餐到期、流量耗尽或订阅 Token 已被封禁重置时，不会返回 401 或 404，而是依然返回 HTTP 200 并下发一个仅包含一两条“套餐已过期/剩余流量不足”占位信息的最小配置文件，或者干脆返回空 proxies 列表。登录服务商官网控制台核对到期日与可用流量即可确认。
