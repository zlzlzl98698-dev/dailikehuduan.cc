# 代理连接成功没网络、网页打不开与频繁断线排查指南

<div class="answer-first-box">
<div class="answer-first-label">核心结论 · Answer First</div>
<p>客户端面板显示<strong>“已连接”且节点延迟正常</strong>，却出现<strong>“代理连接成功没网络”</strong>、<strong>“节点已连接但网页打不开”</strong>或<strong>“使用几分钟就频繁断线”</strong>，本质上并非远端节点彻底宕机，而是<strong>本地流量没有正确进入有效代理隧道</strong>或<strong>长连接在本地/服务端链路被强行打断</strong>。桌面端排障应优先核验 <code>7890</code>/<code>7897</code>/<code>10808</code> 监听端口是否被僵尸进程抢占、浏览器是否被 SwitchyOmega 插件覆盖、出站模式是否误设为 <code>Direct</code> 以及规则集是否下载就绪；移动端重点解决国产 ROM 省电杀后台与 iOS Network Extension（15MB–50MB）内存超限；多设备轮流掉线则优先核对套餐并发限制，晚高峰降速需通过网线/MTU/单线程对照测试隔离本地 Wi-Fi 与上游入口拥塞。</p>
</div>

## 一、现象分诊矩阵：6 类「连接成功却断网/断线」故障快速定位

在用户反馈中，**“机场连上了但打不开网页”**与**“用一会儿就断线”**往往混杂在一起。不同故障表现对应的网络层级截然不同，盲目重启电脑或反复切换节点只会浪费时间。根据本站 [客户端兼容性档案](/clients/)（`2026-11-23` 核验）与排障实战记录，建议先对照下表锁定故障层级，再跳转至对应章节执行验证命令：

| 典型故障现象 | 故障所属层级 | 第一嫌疑根因 | 快速验证指标 / 命令 | 平均排查耗时 |
| :--- | :--- | :--- | :--- | :--- |
| **延迟显示绿色 40ms，浏览器任何海外网页都打不开** | 本地流量接管层 | 未开系统代理、SwitchyOmega 指向错误端口、旧进程占口 | `netstat -ano` 核对监听 PID 与浏览器报错代码 | **2 分钟** |
| **节点已连接但国内外网页全打不开，提示 `ERR_PROXY_CONNECTION_FAILED`** | 浏览器与系统代理层 | 系统代理指向了已关闭的旧端口（如 `7890`），或与扩展打架 | `reg query` 检查 `ProxyServer` 与关闭浏览器扩展 | **2 分钟** |
| **只有部分海外站点能开或全部直连，测速正常却不走代理** | 规则与策略组层 | 误设 `Direct` 直连、`GLOBAL` 停在 `DIRECT`、规则集下载失败 | 客户端「连接（Connections）」面板观察命中规则与出站 | **3 分钟** |
| **手机锁屏 5 分钟断流，点亮屏幕 10 秒后才恢复** | 移动端系统管控层 | Android 电池优化杀后台、iOS 规则集过大触发 OOM 回收 | 检查状态栏 VPN 钥匙图标是否曾短暂消失重现 | **5 分钟** |
| **多台设备每隔 1–2 分钟轮流掉线一次** | 服务端账号并发层 | 套餐限制同时在线设备数（如限 2–3 台），后端踢出旧会话 | 仅保留单台设备测试 15 分钟观察是否恢复稳定 | **5 分钟** |
| **白天流畅，晚上 20:00–23:00 网页龟速、视频断流** | 无线物理层 / 链路拥塞层 | 本地 Wi-Fi 信道拥堵 / MTU 分片丢包，或机场跨省入口晚高峰限速 | 网线直连测试 + 单线程对比 + `ping -f -l 1472` | **8 分钟** |

## 二、排查一：本地监听端口冲突（7890 / 7897 / 10808 被旧进程抢占）

### 1. 问题与直接答案
为什么明明新装了 [Clash Verge Rev](/clients/clash-verge-rev/) 或 [v2rayN](/clients/v2rayn/) 并点击了连接，浏览器还是提示无法连接代理或完全没网？最常见的原因是**端口监听与系统代理转发错位**。当后台残留着已经停止维护的旧客户端进程（例如旧版 Clash for Windows 的 `clash-win64.exe`）或其他下载工具、虚拟机占用了相同端口时，系统代理会把浏览器请求发给那个没有有效节点的“空壳进程”，导致出现“软件里节点有延迟，浏览器却打不开网页”的假象。

### 2. 条件说明与主流客户端默认端口对照
不同代理客户端及核心默认占用的混合代理端口（Mixed Port，同时承载 HTTP 与 SOCKS5）与控制面板端口并不一致，混用或同时打开两款客户端极易撞车：

| 客户端名称 | 底层内核 | 默认代理端口（Mixed / HTTP / SOCKS） | 默认控制端口（API） | 典型冲突场景 |
| :--- | :--- | :--- | :--- | :--- |
| **[Clash Verge Rev](/clients/clash-verge-rev/)** | Mihomo (Clash.Meta) | `7897`（Mixed Port） | `9097` | 用户沿用旧教程在插件填 `7890`，或与老版 Clash 撞车 |
| **旧版 Clash 系（已停更 CFW 等）** | 原版 Clash | `7890`（Mixed）、`7891`（SOCKS） | `9090` | 残留僵尸进程占死 `7890`，新客户端切端口后插件未改 |
| **[FlClash](/clients/flclash/)** | Mihomo (Clash.Meta) | `7890`（可在设置修改） | 动态 / 自定义 | 与系统内其它 Clash 客户端并行运行发生端口抢占 |
| **[v2rayN](/clients/v2rayn/)** | 多核心 (Xray/sing-box/Mihomo) | `10808`（SOCKS5）、`10809`（HTTP） | 核心内置分配 | 同时运行 Hiddify 或其他 Xray 壳程序抢占 `10808` |
| **[Hiddify](/clients/hiddify/)** | sing-box | `12334`（默认 Mixed，随版本可能调整） | 动态分配 | 浏览器手动代理仍停留在 `7890` 或 `10809` |

### 3. 检查步骤与操作命令
打开系统终端（Windows 下用 PowerShell，macOS/Linux 用 Terminal），不要猜测端口号，直接查询当前到底是谁在监听端口以及系统代理指向哪里：

```powershell
# Windows 10 / 11：查询 789x 与 1080x 端口的监听进程 PID
netstat -ano | findstr ":789 :1080"

# 假设上一步最后一列输出的 PID 是 14520，反查具体程序名
tasklist | findstr "14520"

# 核对 Windows 注册表当前生效的系统代理地址与端口
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" | findstr /i "ProxyEnable ProxyServer ProxyOverride"
```

```bash
# macOS / Linux：一次性检查常见代理端口被哪个进程占用
lsof -nP -iTCP:7890,7897,10808,10809 -sTCP:LISTEN

# macOS 查看系统网络接口当前生效的 HTTP / SOCKS 代理设置（以 Wi-Fi 为例）
networksetup -getwebproxy "Wi-Fi"
networksetup -getsocksfirewallproxy "Wi-Fi"
```

### 4. 处理方法与验证结果
- **正常基准状态**：`ProxyEnable` 为 `0x1`，`ProxyServer`（如 `127.0.0.1:7897`）必须与当前主用客户端面板里设置的端口**逐字一致**，且 `netstat` / `lsof` 中该端口只能由当前运行的 `verge-mihomo.exe`、`mihomo`、`xray.exe` 或 `sing-box` 唯一监听。
- **若发现多进程冲突或僵尸进程**：先在客户端退出软件，再执行 `taskkill /F /PID <PID>`（macOS/Linux 用 `kill -15 <PID>`）清理掉残留的旧进程，最后仅启动一款主力客户端并重新勾选“系统代理”。如果无法释放特定端口（例如被 Windows Hyper-V 动态端口范围保留），可在 Clash Verge Rev 设置中将混合端口修改为 `17897` 或 `27897` 等高位端口避让。
- **下一步**：端口核对无误后，使用 `curl -x http://127.0.0.1:7897 -I https://www.google.com` 验证命令行是否返回 `HTTP/1.1 200 OK` 或 `301/302`。若命令行通畅但浏览器依然打不开，说明问题出在浏览器插件或 DNS 层，立即进入下一节排查。

## 三、排查二：浏览器代理扩展（SwitchyOmega / ZeroOmega）覆盖系统代理

### 1. 问题与直接答案
**“命令行能通、客户端有流量，唯独 Chrome 或 Edge 打开网页报错 `ERR_PROXY_CONNECTION_FAILED` 或全部超时”**，九成以上是因为浏览器安装了第三方代理扩展（如 Proxy SwitchyOmega、ZeroOmega 或部分集成了代理功能的爬虫/跨境电商插件）。在 Chromium 内核浏览器中，**扩展程序接管代理的优先级高于操作系统级系统代理**。一旦扩展接管权激活并指向了失效端口，你在客户端里怎么开关“系统代理”都不会对浏览器产生任何影响。

### 2. 条件说明与常见冲突陷阱
除了代理切换插件本身，以下三类浏览器内部机制也会导致“连接成功却没网络”：
1. **SwitchyOmega 停留在过时情景模式**：用户两年前配置过指向 `127.0.0.1:7890` 或 `127.0.0.1:10809` 的情景模式，升级到监听 `7897` 的 [Clash Verge Rev](/clients/clash-verge-rev/) 后，插件仍在强行把浏览器流量发往无人监听的 `7890`。
2. **跨境电商 / 指纹浏览器 / 安全类扩展冲突**：部分电商选品插件、翻译工具或企业安全插件内部附带 `chrome.proxy` 权限，会在后台静默把浏览器代理改为 `[直接连接]` 或指向外部失效接口。你可以在 Chrome 地址栏输入 `chrome://settings/system`（Edge 为 `edge://settings/system`），如果看到“您的代理设置正由某个扩展程序控制”的提示，即可 100% 确诊。
3. **浏览器内置安全 DNS（DoH）绕过客户端嗅探**：当浏览器开启了内置 DoH（如指向阿里云或 Cloudflare DoH）且客户端仅运行在系统代理模式下时，浏览器发出的 HTTPS 加密连接有时在扩展或分流边界产生延迟，导致页面反复转圈；而在 TUN 模式下，浏览器自带 DoH 则可能绕过 Fake-IP 拦截造成分流失效（详见 [DNS 错误与泄漏排查指南](/troubleshooting/dns/)）。

### 3. 检查与处理步骤
1. **无痕窗口快速隔离验证**：按 `Ctrl + Shift + N`（macOS 为 `Cmd + Shift + N`）打开浏览器无痕窗口（无痕模式默认禁用未显式授权的扩展），在客户端开启系统代理的情况下访问海外网页。如果无痕模式秒开而普通窗口打不开，100% 是扩展冲突。
2. **明确“二选一”架构原则**：
   - **普通用户推荐方案**：直接关闭或卸载 SwitchyOmega 等浏览器代理插件，进入扩展管理页停用所有带代理权限的插件，完全依赖客户端自身的**系统代理**或 **TUN 模式**配合内置分流规则工作。
   - **开发者/多端口分流方案**：若确实需要用 SwitchyOmega（或开源替代版 ZeroOmega）把特定网站分流到特定端口，请**关闭代理客户端面板中的“系统代理”开关**（避免双层代理叠加），并在 SwitchyOmega 的情景模式中核实代理协议为 `HTTP`（或 `SOCKS5`）、服务器 `127.0.0.1`、端口与客户端面板当前端口完全一致，然后点击扩展左侧的**「应用选项」**保存。
3. **刷新浏览器代理与主机缓存**：修改完成后，访问 `chrome://net-internals/#proxy` 点击 `Re-apply settings`，并顺手访问 `chrome://net-internals/#dns` 点击 `Clear host cache`。

### 4. 验证与结论
执行上述清理后，在地址栏访问 `https://www.youtube.com` 或 `https://cp.cloudflare.com/generate_204`，同时打开客户端的「连接（Connections）」监控面板。只要能在连接列表里看到对应浏览器进程（如 `chrome.exe` / `msedge.exe`）的域名连接记录且上传下载字节数持续跳动，即证明浏览器流量已成功接入代理内核。

## 四、排查三：代理模式误设为 Direct 与规则集未下载完成

### 1. 问题与直接答案
**“客户端显示已连接，端口也没冲突，为什么既能打开百度又能打开部分站，就是海外 AI 和视频打不开，或者所有请求都没走节点？”** 这类“软失效”最常见于两个配置误区：一是出站模式（Mode）误选为 **Direct（直连模式）**，二是订阅配置里的**远程规则集（Rule-Providers / GeoIP / GeoSite）尚未下载完成或下载失败**，导致内核缺少分流依据。

### 2. 三种出站模式的工作逻辑与典型误操作
无论你使用的是基于 Mihomo 的 [Clash Verge Rev](/clients/clash-verge-rev/)、[FlClash](/clients/flclash/)，还是基于 sing-box 的 [Hiddify](/clients/hiddify/)、[Karing](/clients/karing/)，代理面板顶部通常都提供三种模式切换（更多规则原理见 [分流规则与路由配置指南](/guides/routing/)）：

| 出站模式 | 核心路由逻辑 | 常见导致“没网络/打不开”的误操作 | 排查与修正方式 |
| :--- | :--- | :--- | :--- |
| **Rule（规则模式）** | 按规则列表匹配，国内直连、海外走代理，未命中走兜底 `MATCH` | 1. 导入订阅时挂着旧代理导致外部 `Rule-Provider` 规则集下载失败；<br>2. `Proxy` 主策略组错选成了 `DIRECT` 或失效节点。 | 打开「连接」面板看规则命中；去「规则」或「订阅」界面手动更新 Geo 数据库与外部规则集，确认主策略组选在有效节点上。 |
| **Global（全局模式）** | 忽略绝大多数分流规则，所有流量统一发往 `GLOBAL` 策略组 | 许多用户切到 Global 模式后，**忘记展开 `GLOBAL` 策略组切换节点**——新配置里 `GLOBAL` 默认第一项往往是 `DIRECT`（直连），等价于没开代理！ | 切换到全局模式时，务必进入代理页最顶端的 `GLOBAL` 组，手动点选具体的香港/日本/美国节点或主代理组。 |
| **Direct（直连模式）** | 全部流量绕过节点直接从本地宽带发出 | 临时关闭代理排查国内网站时切到了 `Direct`，用完忘记切回 `Rule`。 | 在客户端主页「代理」标签顶部直接切回 `Rule（规则模式）`。 |

### 3. 规则集与 GeoData 未就绪的识别与修复
现代机场订阅为了减小单文件体积，广泛采用 `rule-providers`（外部规则集）与 `geosite.dat` / `geoip.dat` 数据库。如果你刚安装客户端就导入订阅，而此时没有代理通道去 GitHub 拉取这些规则文件，客户端日志会出现如下报错：
- `initial rule provider xxx error: context deadline exceeded`
- `can't download geoip/geosite database`

**标准解决步骤**：
1. 在客户端「设置 → 内核/资源设置」中，核对是否配置了可用的国内镜像或加速源（部分活跃客户端内置了可切换的 Geo 资源更新地址），手动点击一次**「更新 Geo 数据库」**。
2. 先切到 `Global` 模式并手动选中一个能用的海外节点，保持连通状态 30 秒，再前往「规则」面板点击右上角的**「更新全部规则集」**，等所有规则集条数从 `0` 变成正常数字（如 `5000+`）后，再切回 `Rule` 模式。
3. **核查域名嗅探（Sniffer）**：如果你通过浏览器开启了某些按 IP 发起请求的程序，或使用 TUN 模式时客户端无法拿到真实域名，请确保配置中 `sniffer.enable: true` 已开启（详见 [Clash 配置文件覆写指南](/guides/clash-config/)），防止因为只看到纯 IP 而错误命中直连规则。

## 五、排查四：移动端（Android / iOS）后台省电杀进程与内存超限

移动设备的网络断开往往不是协议故障，而是操作系统出于续航和内存安全考虑，在用户无感知的情况下**静默终止或冻结了代理核心进程**。Android 与 iOS 的底层限制机制完全不同，必须分开治理。

### 1. Android 端：国产 ROM 后台冻结与 VpnService 回收
在小米（HyperOS/MIUI）、OPPO（ColorOS）、vivo（OriginOS）、华为（HarmonyOS）等高度定制的 Android 系统上，锁屏 5–15 分钟后系统会执行 Doze 深度睡眠并清理非白名单后台服务。一旦 [v2rayNG](/clients/v2rayng/)、[FlClash](/clients/flclash/) 或 [Clash Meta for Android](/clients/clash-meta/) 被回收，系统 VPN 通道瞬间撤销，手机表现为**通知栏小钥匙图标消失、微信和海外应用同时断网**，解锁重新打开 App 后才恢复。

**Android 端保活 4 步标准配置**：
1. **电池策略设为“无限制”**：长按代理客户端图标 →「应用信息」→「省电策略 / 耗电管理」→ 改为**无限制（允许后台高耗电 / 不优化）**。
2. **开启自启动与关联启动**：在应用权限或手机管家中允许该客户端「自启动」和「允许后台弹出界面 / 关联启动」。
3. **多任务视图加锁**：打开近期任务列表，下拉或点击该客户端卡片右上角的**锁头图标**锁定后台，防止一键清理时误杀。
4. **保留常驻通知与防休眠开关**：不要屏蔽代理客户端的系统通知权限（Android 要求 VPN 前台服务必须挂一条常驻通知才能保活）；若使用 v2rayNG 或 Clash Meta for Android，可在软件设置中检查是否开启了「阻止休眠 / WakeLock」或核心保活选项。

### 2. iOS 端：Network Extension 内存硬上限（OOM 强杀）
苹果 iOS 系统对第三方代理应用使用的 `NEPacketTunnelProvider` 网络扩展进程施加了极严格的**内存红线限制（通常约 15MB–50MB，视系统版本与机型略有浮动）**。这是很多 iPhone 用户遇到**“用得好好的突然右上角 VPN 图标闪烁一下就断网，切回桌面又要重新连接”**的头号元凶。

**为什么会触发 iOS 内存 OOM 强杀？**
- 你在 [Shadowrocket](/clients/shadowrocket/)、[Stash](/clients/stash/)、[Quantumult X](/clients/quantumult-x/) 或 [Karing](/clients/karing/) 中订阅了别人分享的“大而全”去广告规则（动辄包含 50,000–150,000 条域名与正则匹配）、臃肿的 GeoIP 数据库，或同时开启了十几条复杂的 HTTP 重写与 MitM 脚本。
- 后台运行期间只要有大量并发连接触发规则编译或加载，扩展进程内存瞬间突破 50MB 阈值，iOS Jetsam 内存管理机制会**在毫秒内强杀隧道扩展**，且没有任何弹窗提示。

**iOS 端减负与稳态配置建议**：
- **精简规则集**：删除冗余的巨型去广告、隐私追踪规则列表，仅保留机场自带的基础分流规则（通常仅数千条，内存占用控制在 15MB 以内）。
- **按需关闭 MitM 与复杂脚本**：日常仅做科学访问时，关闭全量 HTTPS MitM 解密与多余重写脚本。
- **使用轻量替代方案**：如果机场订阅自带庞大规则集导致老款 iPhone 频繁闪断，可在 [Shadowrocket](/clients/shadowrocket/) 中切换为「仅保留内置精简分流（如白名单/绕过大陆列表）」，或评估切换至规则解析开销更低的配置模板。

### 3. Wi-Fi 与 5G 蜂窝网络切换导致的连接僵死
当你走出家门从 Wi-Fi 切换到手机 5G 网络时，设备本地出口 IP 发生变更。此时原本建立的 TCP 长连接或基于 UDP 的 QUIC（Hysteria 2 / TUIC）会话仍绑定在旧网卡上下文上，导致前 15–30 秒看似连接正常实则全部丢包。建议在客户端设置中开启**「网络切换时自动重置连接 / 关闭旧连接」**；若发现切网后短暂没网，在控制中心或客户端主页点击一次开关重连即可立即刷新底层 Socket。

## 六、排查五：套餐并发设备数或 IP 数超限被踢出

### 1. 现象规律：多设备“轮流掉线”
若单台手机全天稳定，一回家开启电脑、平板或软路由后就出现设备轮流断线、或每隔几分钟集体失联再自动恢复，基本可判定触发了机场后端的**并发设备数 / 同时在线 IP 数限制**。

### 2. 服务端审计机制与品牌套餐差异
主流面板（V2Board / SSPanel-Uim / Xboard）通过统计同一用户在 60–180 秒时间窗口内接入的**公网出口 IP 数**来判定并发设备数：手机 5G、家里宽带与公司网络同时在线即计为 3 个 IP；若客户端同时用 IPv4 与 IPv6 建连，部分老面板还会按双倍 IP 计数。

根据本站 `brands.ts`（`2026-11-23` 核验快照）品牌公开资料对比，并发策略差异明显：
- **资料标注支持不限设备/多设备在线的品牌**（均为品牌方资料宣称，建议实测并遵守合理使用条款）：如 [光速云](/brands/guangsuyun/)、[牧光云](/brands/muguang/)、[飞猫云](/brands/feimao/)、[大佬云](/brands/dalaoyun/)、[隐形人](/brands/yinxingren/)、[二猫子](/brands/ermao/) 与 [Firefly](/brands/firefly/) 等。
- **严格限制设备数的入门套餐**：部分超低价入门小包（参考 [一元机场评估](/plans/one-yuan/) 与 [平价套餐专题](/plans/budget/)）常硬性限制 **1–3 台设备在线**，超限即踢出旧会话或临时封锁端口。

### 3. 排查与彻底解决策略
1. **单设备孤立验证**：关闭其他所有设备上的代理，仅留一台终端测试 20 分钟；若周期断流消失，即可确诊并发超限。
2. **排查 Token 泄漏**：仅开单台设备仍提示超限，立即登录机场控制台查看在线记录并重置订阅 Token。
3. **家庭多终端升级**：超过 5 台设备长期在线时，建议在路由器部署 [OpenWrt 软路由（OpenClash / Nikki / PassWall2）](/clients/platform/openwrt/) 统一出口，或按 [多设备与家庭方案指南](/airport/multi-device/) 选用高并发套餐。

## 七、排查六：晚高峰速度慢与延迟高——本地 Wi-Fi / MTU 与节点拥塞区分法

晚高峰（20:00–23:30）看视频卡顿或网页加载慢，可能是本地无线干扰与光猫瓶颈，也可能是机场跨省入口拥塞。可通过以下 4 步精准隔离：

### 第 1 步：网线直连 + 国内测速剥离本地瓶颈
关闭代理并插上网线（或近距离连 5GHz Wi-Fi），终端持续 Ping 路由器网关（`ping 192.168.1.1 -t`）并跑国内 Speedtest。正常内网延迟应稳定在 `1ms–3ms`（0% 丢包），国内测速应接近签约带宽 85% 以上；若内网已高延迟或丢包，问题在本地路由器或 Wi-Fi 信道干扰。

### 第 2 步：排查 PPPoE 与虚拟网卡叠加引发的 MTU 分片丢包
以太网默认 MTU 为 `1500`，PPPoE 占 8 字节后为 `1492`，再叠加 TUN 与加密隧道包头后，若本地 MTU 过大且路径禁止分片，会出现**文字网页能开但视频和大文件下载直接卡死在 0KB/s**。

```powershell
# Windows 测试当前物理网络链路最大不分片载荷（从 1472 往下试，加上 28 字节 IP/ICMP 头即 MTU）
ping -f -l 1472 223.5.5.5
# 若提示“需要拆分数据包但是设置 DF”，逐步减小数值测试（如 1464、1452、1400）直到正常通畅
ping -f -l 1452 223.5.5.5
```

```bash
# macOS / Linux 测试不分片大包
ping -D -s 1464 223.5.5.5     # macOS
ping -M do -s 1464 223.5.5.5  # Linux
```

若大包不通，在 [Clash Verge Rev](/clients/clash-verge-rev/) TUN 覆写配置中将 `tun.mtu` 下调至 **`1400`** 或 **`1380`**（部分移动宽带可试 `1280`）后重启 TUN 验证。

### 第 3 步：对比单线程速率与不同协议节点
本地测速与 MTU 均正常时，瓶颈位于代理链路（详参 [节点延迟与抖动测量方法](/routes/latency/)）：
1. **厘清历史数据口径**：查阅本站 [品牌实测数据库](/brands/directory/) 时，`brands.ts` 标注 `2026-10-19（历史资料标注）` 的速率均属**非晚高峰**汇总记录；衡量晚高峰体验须看 21:00 实测的**单线程下载速率**与连续百次 Ping 抖动。
2. **切协议与专线入口**：移动宽带与部分城域网晚高峰常对 UDP 限速，若 Hysteria 2 / TUIC 卡顿，可切回 TCP 443 端口的 **VLESS-Reality** 或 **Trojan** 节点；多入口套餐可尝试切换 [IEPL 专线](/routes/iepl/) / [IPLC 专线](/routes/iplc/) 入口并注意核对 [流量倍率](/routes/multipliers/)。

### 第 4 步：对照结论表决定最终行动
| 检查结果组合 | 最终根因判定 | 推荐解决动作 |
| :--- | :--- | :--- |
| 内网 Ping 网关跳动大 / 关代理国内测速慢 | **本地 Wi-Fi 干扰或小区宽带拥塞** | 切 5GHz Wi-Fi / 接六类网线；重启光猫并限制局域网下载软件抢带宽 |
| 小包通畅、大网页加载一半卡死、`ping -f` 不通 | **链路 MTU 过大导致分片丢包** | 将客户端 TUN `mtu` 下调至 `1400` 或 `1380`；或检查路由器 PPPoE MTU |
| 本地一切满速，仅晚高峰海外单线程跌至 2Mbps 以下且高丢包 | **机场入口带宽超售或公网跨省出口拥塞** | 切换同订阅内其他入口/地区或低抖动专线节点；长期严重拥塞则考虑更换稳定架构品牌 |

## 常见问题（FAQ）

### 1. 为什么代理客户端显示连接成功且节点延迟只有 30ms，但浏览器打开任何网页都转圈或没网络？
节点测速成功只代表内核能连上远端入口，浏览器打不开网页说明“本地应用流量没有交由内核接管”或“模式选错”。常见原因有四项：一是未开启系统代理或 TUN 模式；二是浏览器装有 SwitchyOmega 等代理扩展，把流量硬编码送往了错误的端口（如 `7890` vs `7897`）；三是旧残留进程占用了监听端口；四是出站模式误设为 `Direct`（直连）或 `GLOBAL` 组默认停在 `DIRECT`。

### 2. 如何确认是 Clash Verge Rev 监听的 7897 端口，还是被旧客户端抢占了端口？
在 Windows 终端执行 `netstat -ano | findstr ":789"` 查看目标端口对应的 PID，再运行 `tasklist | findstr "PID编号"` 即可定位实际占用进程。如果同时存在旧版 Clash for Windows 残留进程或两个代理客户端，系统代理虽然指向该端口，数据包却被没有有效节点的僵尸进程吞掉，从而导致连接成功却没网络。

### 3. 为什么开启代理后，手机锁屏几分钟就自动断线，切回桌面又要等好几秒才恢复？
这是移动操作系统的后台省电与内存回收机制所致。Android 定制系统会在锁屏后冻结非白名单应用的网络与保活进程，需要关闭电池优化并锁定后台；iOS 则对 Network Extension 扩展进程施加了约 15MB–50MB 的严格内存上限，若在 Shadowrocket 或 Stash 中挂载了数万条冗余去广告规则，极易触发 OOM 强杀导致断线。

### 4. 家里电脑和手机同时开着同一个机场订阅，为什么每隔一两分钟就轮流掉线？
这是典型的“套餐同时在线设备数或并发 IP 超限”现象。部分低价套餐限制仅允许 2 台或 3 台设备同时在线，当家里软路由、电脑、手机、平板同时连接时，后端审计会踢掉较早建立的会话或短暂封禁连接，造成多台设备交替断流。遇到此情况需检查机场面板的设备数限制，或升级至支持多设备同时在线的方案。

### 5. 为什么白天测速能跑满宽带，一到晚高峰就网页打不开、视频缓冲转圈，怎么区分是自家 Wi-Fi 还是机场节点拥塞？
最直接的定位法是“用网线直连光猫/路由器 + 测试国内测速点 + 对比单线程下载”。如果插网线测国内 Speedtest 稳定跑满、Ping 路由器网关延迟小于 2ms 且无丢包，而连代理后只有海外晚高峰时段丢包或单线程卡在 2Mbps 以下，属于机场跨网中转入口拥塞；若连国内网页也卡顿或内网 Ping 网关出现高抖动，则是本地 Wi-Fi 信道干扰或 MTU 分片问题。

### 6. 为什么开启代理后微信、QQ 等国内软件变慢甚至断网，海外网页也打不开？
通常是规则集（Rule-Provider / GeoSite）尚未下载完成，或者订阅配置文件中缺失分流规则且默认兜底（MATCH）指向了不可用的节点。当规则集下载卡在初始化阶段时，内核无法识别国内外域名，部分流量会直接进入超时等待。在客户端内手动更新规则集并检查策略组选中节点即可恢复。

### 7. SwitchyOmega / ZeroOmega 插件和客户端系统代理冲突时，应该保留哪一个？
普通用户只需开启客户端自带的“系统代理”或“TUN 虚拟网卡”即可，建议直接停用或删除浏览器第三方代理插件；只有需要在浏览器内做精细多情景分流（例如指定某几个测试标签页走不同端口）的开发者才保留 SwitchyOmega，且此时应关闭客户端自动修改系统代理的开关，并核对插件内端口与客户端 Mixed Port 完全一致。
