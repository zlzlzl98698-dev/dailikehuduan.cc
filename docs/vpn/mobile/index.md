许多用户在 Windows 电脑上配置好规则代理后，顺手把同一份庞大的订阅配置原封不动导入手机，结果很快遇到三种典型挫折：刚出门从客厅 Wi-Fi 走到楼下 5G 就断网转圈；iPhone 晚上锁屏充电或刷长视频时 VPN 莫名其妙断开；或者安卓手机挂了一天代理，系统电池统计里代理软件耗电排进前三。出现这些问题并非节点本身质量差，而是把桌面端的资源冗余思维直接套用在了算力、内存与射频功耗高度受限的移动操作系统上。本专题从 iOS 与 Android 的系统级网络扩展机制出发，逐层拆解手机 VPN 的内存边界、后台保活、切网重连、始终开启防护与选型策略。

## 一、iOS 端底层机制：`NEPacketTunnelProvider` 50MB 内存硬上限与 JetSam 崩溃机理

**为什么桌面端跑几百兆内存毫无压力的复杂规则集，一导入 iPhone 就会出现 VPN 图标突然消失、网页全部卡死甚至需要手动重连？**

**直接答案**：这是苹果 iOS 操作系统内核级沙盒配额与内存回收机制共同作用的结果。iOS 上任何第三方 VPN 应用程序本身只负责图形界面与配置编辑，真正接管系统数据包并加密转发的代理核心运行在一个独立的系统扩展进程——**`NEPacketTunnelProvider`（Network Extension）**中。出于对后台常驻进程严格控耗与保护前台应用流畅度的考量，iOS 内核对这个网络扩展进程施加了约 **50MB** 的物理内存驻留（Dirty Memory）硬上限；一旦扩展进程的实时内存占用跨越红线，内核内存守护进程 **JetSam** 会在毫秒内直接向其发送 `SIGKILL` 强制终止信号，且不会弹出任何用户报错提示。

### 1.1 条件说明：主 App 与 Network Extension 的双进程隔离模型

在理解 iPhone 代理稳定性之前，必须先厘清 iOS `NetworkExtension` 框架的进程隔离设计：
1. **主界面进程（Containing App）**：当你打开 Shadowrocket、Stash 或 Karing 时运行的前台进程，享有数百 MB 至数 GB 的常规 App 内存额度，用于渲染节点列表、编辑规则与解析远程订阅下载。当你滑回桌面或锁屏时，主 App 很快被系统挂起（Suspended）。
2. **隧道扩展进程（Packet Tunnel Provider）**：由系统 `neagent` / `nesessionmanager` 在后台独立拉起并长期驻留的轻量级守护进程。手机所有的 IPv4/IPv6 数据包均经由 `utun` 虚拟接口进入该扩展进程，由内置代理核心完成域名匹配、DNS 解析与加密封装后发往远端服务器。
3. **JetSam 强杀的典型触发场景**：在桌面端 16GB 内存环境下微不足道的开销，在 50MB 的窄口下极易触礁。常见元凶包括：第一，一次性加载未经裁剪的完整版 `geosite.dat` 与 `geoip.dat`（仅解析后常驻内存索引树即可占用 20–35MB）；第二，在核心中启用高并发连接跟踪、大量正则表达式重写（URL Rewrite）与多条大型广告屏蔽列表（如十几万条域名规则）；第三，P2P 下载、视频流预加载或某些后台同步软件在短时间内并发打开数百个连接，导致加密缓冲区与连接表内存瞬间飙升突破 50MB。

### 1.2 证据与对比：iOS 主流核心与客户端内存控制特征

根据本站 `clients.ts`（2026-11-23 核验快照）收录的苹果生态客户端架构，不同技术路线在 50MB 内存上限下的工程应对方式存在明显差异：

| iOS 客户端名称 | 底层核心与授权模式 | 内存占用控制策略 | 规则与订阅兼容性 | 适用人群与内存避坑要点 |

### 1.3 防止 iOS JetSam 崩溃的四步调优操作

1. **用二进制规则集替代海量明文规则**：优先选用按需编译的 `.mrs` 或 `.srs` 二进制规则集，仅保留核心 `cn` 与常用流媒体/AI 规则，剔除十万行以上的通用广告黑名单。
2. **关闭非必要的全量日志与高频抓包**：在 Shadowrocket 或 Stash 设置中关闭常驻请求体抓取，将历史记录保留条数限制在 200 条以内，防止日志缓冲区耗尽 50MB 额度。
3. **开启 Go 核心低内存回收策略**：基于 Go 内核（sing-box）的工具可启用低内存模式或提高 GC 回收频率，压低峰值内存占用。
4. **严守 iOS 账号安全红线**：大陆区 App Store 未上架此类工具。获取正版应自注册外区 Apple ID 并通过正规礼品卡充值，**仅在 App Store 内切换登录，严禁在“系统设置 → iCloud”登录陌生共享号**，以防远程锁机变砖。

**结论与延伸阅读**：iOS 断连首要排查规则集内存超载。详细配置请参阅 [iOS 客户端选型中心](/clients/platform/ios/) 与 [Shadowrocket 教程](/clients/shadowrocket/)。

## 二、Android 电池优化、后台保活与国产定制系统省电机制对抗

**为什么很多安卓手机开启代理后，屏幕黑屏十几分钟或者放进口袋半小时，顶部状态栏的 VPN 钥匙图标还在（或突然消失），所有海外网页却全部断流？**

**直接答案**：除了标准 Android 原生系统的 Doze 深度休眠机制外，国内主流品牌手机的定制 ROM（如小米 HyperOS/MIUI、OPPO ColorOS、vivo OriginOS、华为 HarmonyOS 等）普遍内置了极其激进的后台进程查杀与网络冻结策略。当手机熄屏进入空闲状态，系统会判定代理客户端“无前台界面交互”而冻结其后台 Socket 连接或直接回收服务进程。要实现安卓手机 VPN 全天稳定在线，必须同时完成**系统白名单放行、本地核心低功耗调参、以及原生分应用绕过**三层配置。

### 2.1 条件说明：Android 后台保活与耗电的矛盾本质

从电源管理工程视角看，移动设备电量消耗大户并非代理加密算法本身（现代 ARMv8 芯片普遍具备硬件 AES 与 NEON 加速指令集，加密 100Mbps 流量的 CPU 功耗微乎其微），真正的电量黑洞在于**基带无线射频模块（Cellular Modem / Wi-Fi Radio）的状态机跃迁与 CPU 唤醒锁（WakeLock）**。
- 当手机没有后台保活时，每次打开微信或浏览器都需要系统重新拉起代理进程并执行 TLS/VLESS 握手，反而更耗电且断流。
- 反之，如果代理软件虽然保活成功，但内部配置了极高频率的测速或心跳包，就会阻止手机蜂窝基带从高功耗的 `RRC_CONNECTED` 状态回落到休眠的 `RRC_IDLE` 状态——这正是“挂着代理放一晚掉电 25%”的核心原因。

### 2.2 国产安卓系统（HyperOS / ColorOS / OriginOS / HarmonyOS）保活四步规范

无论使用 [FlClash](/clients/flclash/)、[v2rayNG](/clients/v2rayng/)、[Clash Meta for Android](/clients/clash-meta/) 还是 [Hiddify](/clients/hiddify/)，首次安装后应完成以下四项系统放行：

1. **关闭电池优化**：进入 `设置 → 应用管理 → 对应客户端 → 省电策略`，改为 **“无限制”** 并允许后台高耗电。
2. **多任务卡片加锁**：在最近任务界面长按或下拉客户端卡片点击**小锁锁定**，防止一键清理或系统内存回收误杀。
3. **开启自启动与保留前台通知**：允许自启动与后台关联启动，且**切勿关闭客户端常驻状态栏通知**（Android 依赖可见前台通知维持高存活优先级）。
4. **配置分应用绕过**：利用 `VpnService` 原生分应用接口，将微信、支付宝、手机银行、抖音、淘宝与地图软件加入绕过列表，从源头削减不必要的隧道唤醒与耗电。

### 2.3 移动端专属省电调参清单（比对桌面端习惯）

| 调优参数项 | 桌面端常见默认设置 | 移动端省电推荐设置 | 背后功耗与流量节省原理 |
| :--- | :--- | :--- | :--- |
| **节点自动测速策略组（`url-test` `interval`）** | `180s` 或 `300s`（甚至部分机场模板配 `60s`） | **`600s`–`1800s`，或手机主力改用 `select` 手动选点** | 避免每分钟批量向几十个海外节点发起 TLS/HTTP 测速，防止蜂窝基带频繁从低功耗休眠态唤醒，实测可大幅降低待机发热量 |
| **订阅自动更新周期** | 每 6–12 小时静默拉取 | **设为 24–72 小时，或仅在连接 Wi-Fi 时手动更新** | 减少后台定期唤醒拉取数 MB 配置文件与远程规则集的流量与射频开销 |
| **域名嗅探（Sniffer）范围** | 全端口嗅探 + 强制覆盖所有连接 | **仅针对常见 80/443 端口开启，或依赖精确规则分流** | 降低每一次新建短连接时的 TLS ClientHello 解包解析算力消耗 |
| **IPv6 路由处理** | 视桌面双栈网络情况开启 | **若本地移动网络或节点不支持完整 IPv6，建议关闭客户端 IPv6** | 防止手机在 5G 双栈环境下先尝试连接无响应的 IPv6 节点等待超时回退，消灭“转圈等待耗时”与重传耗电 |
| **传输协议选择（Wi-Fi vs 弱网 5G）** | 桌面宽带常用高并发 QUIC/Hysteria 2 | **日常待机优先 TCP/TLS（如 VLESS-Reality / Trojan），仅在高铁弱网拉流时切 Hysteria 2** | 常规长连接空闲时 TCP Keepalive 周期远长于 UDP NAT 映射保活（通常每 15–30 秒需发一次心跳维持端口映射），TCP 待机显著更省电 |

**结论与延伸阅读**：安卓省电与保活的秘诀在于“把系统权限全部放开，把内部心跳频率大幅降下来”。有关安卓端 `VpnService` 底层原理与 APK 安全校验方法，请继续参阅同系列专题 [安卓 VPN 与代理区别（VpnService 与 APK 安全）](/vpn/android/)。

## 三、Wi-Fi 与 5G 蜂窝网络切换重连机制与断流自愈

**为什么在家连接 Wi-Fi 刷网页一切正常，一出门走进楼道切换成 5G 蜂窝网络，手机状态栏依然显示 VPN 连接中，但所有浏览器和 App 却彻底卡死转圈？**

**直接答案**：网络切换（Network Handoff）引发了本地网络栈与代理核心之间的状态撕裂。当手机从家庭宽带 Wi-Fi（例如本地网关 `192.168.1.1`、运营商分配 DNS `192.168.1.1`）瞬间切换至 5G 蜂窝基站（本地分配新内网 IP 与运营商蜂窝 DNS）时，物理网卡接口已从 `wlan0` 变更为 `rmnet_data0`。如果代理客户端的核心未在毫秒级捕获路由变更事件并清理旧出口套接字与 DNS 缓存，就会继续往已经失效的旧网关套接字发包，导致长达 15–60 秒的假死等待甚至连接池彻底僵死。

### 3.1 条件说明：切网瞬间发生了哪三次底层断裂？

1. **底层物理 Socket 五元组失效**：无论代理服务器走 TCP（VLESS / Trojan）还是 UDP（Hysteria 2 / WireGuard），客户端与远端中转节点建立的加密隧道连接绑定在原本地 IP 上。离开 Wi-Fi 覆盖范围后，原出口 IP 消失，服务端发回的数据包无法抵达你的 5G 手机，客户端发出的包在内核也会遭遇路由不可达或等待 TCP 重传指数退避（Exponential Backoff）超时。
2. **本地与直连 DNS 缓存污染/不可达**：在家里 Wi-Fi 环境下，代理核心向路由器网关 `192.168.1.1:53` 发送直连域名 DNS 查询；切到 5G 后，手机不再处于 `192.168.1.0/24` 局域网内，若核心没有重新探测当前活动网卡的网关 DNS，或客户端开启了局域网私有 DoH 指向失效内网地址，所有直连域名解析会立即挂掉。
3. **Fake-IP 映射表与多路径并发冲突**：当系统网络刚从 Wi-Fi 边缘（极弱 1 格信号，还没完全断开）向 5G 切换的几十秒过渡期内，iOS（Wi-Fi 助理）与 Android（智能双通道切换）可能同时保持双接口存活，致使客户端的虚拟网卡流量落入黑洞路由。

### 3.2 证据与对比：主流移动端协议与核心的切网恢复能力

| 协议 / 核心机制 | 切网时的底层表现 | 原生漫游/重连支持度 | 实操优化与故障恢复建议 |
| :--- | :--- | :--- | :--- |
| **IKEv2 / MOBIKE（传统商业 VPN）** | 协议原生支持移动性扩展（RFC 4555），可不重新完整握手直接迁移外层 IP | **极强**（专为早期 3G/4G 移动漫游设计） | 若使用传统商业 VPN 且经常在地铁、高铁通勤，优先选择支持 MOBIKE 的 IKEv2 协议，但仍需留意高干扰网络阻断特征 |
| **WireGuard（传统商业 VPN）** | 无状态漫游设计：只要携带有效密钥从新 IP 发包，服务端自动更新对端 Endpoint IP | **强**（但依赖固定公钥映射且受限于跨境 UDP 阻断） | 在海外本地移动网络切换极为丝滑；但在跨境高丢包/阻断网络下极易触发特征封锁 |
| **Mihomo 核心（FlClash / CMFA / Stash）** | 依托系统网卡变更监听接口自动触发连接关闭（Close All Connections）并重置 DNS | **良好**（取决于客户端 App 对系统接口变更回调的封装） | 务必关闭固定指向路由器内网 IP 的 `nameserver`，改用公共加密 DNS（如阿里 `223.5.5.5` / 腾讯 `119.29.29.29` DoH）作为直连兜底 |
| **sing-box 核心（Karing / Hiddify / SFI / SFA）** | 支持精细的 `auto_detect_interface` 与接口监听重置，并可配合 QUIC 连接迁移思路优化 | **良好至优秀** | 确认客户端设置中开启了默认出站网卡自动探测（`auto_detect_interface`）；切网假死时使用下拉快捷开关重连 |
| **Xray-core（v2rayNG / Shadowrocket）** | 对长期挂起的半开 TCP 连接缺乏主动快速清理，极弱 Wi-Fi 边缘最容易卡死 | **中等** | 走出家门前习惯性主动断开 Wi-Fi 开关直接切入 5G，比在 1 格信号边缘让系统被动切换快 10 倍 |

### 3.3 移动端切网无感知的实战检查步骤

1. **替换固定内网 DNS**：检查配置中的直连 `nameserver`，确保填写公共 DNS（如 `223.5.5.5`、`119.29.29.29` 或阿里 DoH），**切勿硬编码路由器地址 `192.168.1.1`**。
2. **控制中心快捷磁贴重连**：将 FlClash / v2rayNG 的快捷磁贴或 Shadowrocket 锁屏小组件放到顺手位置，进出电梯假死时点击关闭再打开（约 2 秒）即可强制清空僵尸连接池。
3. **排查运营商局部限制**：若切换 5G 后重连依旧全部超时，请参考 [断线重连排查手册](/troubleshooting/disconnected/) 与 [节点超时排查](/troubleshooting/timeout/) 核验端口或 UDP 限速情况。

## 四、Always-On VPN 与 Kill Switch 在移动端的边界与安全隐患

**手机系统自带的“始终开启 VPN（Always-On VPN）”和“阻断无 VPN 连接（Kill Switch）”到底该不该开？**

**直接答案**：**“始终开启 VPN”可按需用于辅助保活，但“阻断无 VPN 连接”对国内规则代理用户而言往往弊大于利**。强阻断开关的设计前提是全机 100% 流量盲目进出商业 VPN 隧道，一旦与规则分流或分应用绕过叠加，极易造成客户端自身更新订阅与直连流量死锁。

### 4.1 两个系统级开关的真实作用机理

1. **Android 原生 `Always-On VPN` 与 `Block connections without VPN`**：仅开启“始终开启的 VPN”，系统会在开机或进程异常退出时尝试自动拉起客户端；但若再勾选“阻断无 VPN 连接”，内核防火墙会直接拦截所有未走 `tun0` 的物理网卡数据包，导致被分应用绕过的国内 App 断网，或在机场订阅到期时无法打开官网续费。
2. **iOS 按需连接（Connect On Demand）**：iOS 个人设备无全局硬核 Kill Switch 开关，而是通过 Shadowrocket、Stash 或 Surge 内置的 **按需连接规则** 实现自动化——例如设定“连入家庭软路由 Wi-Fi SSID 时自动断开，切出蜂窝网络时自动启用”，兼顾省电与防双重代理冲突。

### 4.2 移动端安全防护与体验平衡对照表

| 用户场景与工具类型 | Always-On / 按需连接建议 | Kill Switch（阻断无隧道流量）建议 | 潜在风险与避坑提示 |
| :--- | :--- | :--- | :--- |
| **海外留学/出差 + 国际商业 VPN（连公共 Wi-Fi）** | **强烈建议开启** | **建议开启** | 确保在咖啡馆、机场不加密热点断开重连瞬间，手机后台邮件与网银绝不以明文泄漏至公共局域网 |
| **国内日常 + 开源规则代理（FlClash / v2rayNG）** | **可选开启**（优先用前述四步电池保活代替） | **强烈不建议开启** | 开启强阻断易与客户端分应用绕过（微信/银行直连）及本地局域网投屏冲突，极端情况下会导致机场订阅到期或失效后无法打开官网续费 |
| **iOS 设备 + Shadowrocket / Stash / Surge** | **强烈建议配置“按需连接（On Demand）”** | 无系统全局硬开关（依靠配置内策略兜底） | 利用 SSID 规则实现“回家连入软路由 Wi-Fi 自动关掉小火箭、出门自动开启”，完美避开双重代理套娃 |

## 常见问题（FAQ）

### 为什么 iPhone 上的代理软件或手机 VPN 经常在锁屏或看长视频时突然“无声断开”？

iOS 系统规定所有第三方 VPN 与代理内核必须运行在独立的 Network Extension（`NEPacketTunnelProvider`）沙盒扩展进程中，且系统对其施加了约 50MB 的严格物理内存上限。一旦导入体积过大的 GeoIP/GeoSite 数据库、高并发打开大量网页连接，或同时开启复杂正则重写与 MitM 解密，扩展进程内存瞬间突破阈值，就会被 iOS 内核守护进程 JetSam 直接强杀，表现为状态栏 VPN 图标消失或连接假死。

### 手机上一直挂着 VPN 或代理软件，为什么比平时掉电快很多甚至机身发热？

移动端代理耗电激增通常由四个因素叠加导致：一是策略组设置了过短的自动测速间隔（例如每 60 秒对几十个节点发起一次 `url-test`），迫使基带射频模块无法进入休眠；二是开启了高频率的域名嗅探（Sniffer）与全量远程规则定期拉取；三是弱信号环境下长连接（尤其是 UDP/QUIC 心跳）频繁超时重连唤醒 CPU；四是国内高频 App 流量全部经由本地 TUN 虚拟网卡中转。优化测速周期、精简规则集并配置安卓分应用绕过可显著降低功耗。

### iOS 端应该购买 Shadowrocket（小火箭）、Stash 还是选择免费的 Karing / Hiddify？

若你拥有非大陆区个人 Apple ID 且看重长期低内存占用与生态兼容性，一次性买断的 Shadowrocket（私有轻量核心）在 50MB 内存限制下的稳定性经过多年验证，Stash 则适合需要直接复用桌面端 Clash YAML 配置的用户，Quantumult X 偏向重度脚本与重写玩家；如果不希望额外付费且需要导入常见订阅，可评估基于 sing-box 核心的开源客户端 Karing 或 Hiddify，但需提前确认所在地区 App Store 当前上架状态。

### 从家里 Wi-Fi 切换到户外 5G 蜂窝网络，或进出电梯后，为什么手机 VPN 会断网十余秒甚至彻底假死？

网络接口切换瞬间，手机的默认网关、公网出口 IP 与运营商分配的本地 DNS 服务器会同步变更。如果代理客户端未监听系统的网络路径变化通知，或者本地保留了错误的 Fake-IP 映射与旧接口绑定套接字，原本的 TCP 长连接与 Hysteria 2 等 UDP/QUIC 会话就会等待漫长的协议超时。选用支持接口变更自动重置连接的 Mihomo / sing-box 新版客户端，并合理设置移动网络切换策略，可明显缩短恢复时间。

### 安卓手机开启“电池优化无限制”后，为什么锁屏几小时还是会被系统杀死后台？

国产定制安卓系统（如 HyperOS、ColorOS、OriginOS、HarmonyOS）除了标准 Android Doze 休眠机制外，还叠加了多任务内存自动清理、深度睡眠应用冻结以及后台关联唤醒拦截。仅关闭单个电池优化并不足够，必须同时完成四项设置：电池策略设为无限制、最近任务界面加锁锁定、开启允许后台高耗电/自启动权限，并在系统 VPN 设置中开启“始终开启的 VPN（Always-On VPN）”。

### 手机系统的 Always-On VPN（始终开启 VPN）和 Kill Switch（阻断无 VPN 连接）有必要同时打开吗？

需要区分使用场景。如果使用的是正规商业 VPN 在海外公共 Wi-Fi 防窃听，同时开启 Always-On VPN 与“阻断无 VPN 连接（Kill Switch）”可以确保隧道意外崩溃时不会泄漏明文数据包；但若你在国内使用规则代理客户端（如 FlClash 或 v2rayNG），开启“阻断无 VPN 连接”会导致客户端更新节点、检测网络或自身发起直连请求受阻，甚至在手机重启后未解锁前彻底断网，因此通常只建议按需开启 Always-On，谨慎启用强阻断开关。

### 购买机场服务时，为什么手机双端用户应优先避开“仅专属客户端”品牌？

根据本站 2026-11-23 品牌数据库快照，飞猫云、SOGO 云、隐形人等品牌采用“仅专属客户端”模式，虽然免去了配置订阅的步骤，但无法导出通用订阅链接给 iOS 上的 Shadowrocket、Stash 或 Surge 使用，也无法在更换手机平台或主力设备时维持一致的分流规则与家宽软路由同步；选择支持第三方通用订阅的品牌（如光速云、一翻云、可信云等），才能保障 iOS、Android 与桌面端的多端协同体验。
