## 一、OSI 网络层 vs 传输/应用层：VPN 和代理（Proxy）的底层技术解剖

**从网络数据包离开应用程序的那一刻算起，传统 VPN 与现代规则代理（SOCKS5 / VLESS / Trojan + Mihomo / sing-box）在操作系统内核与网络协议栈里到底经历了哪些截然不同的处理流程？**

**直接答案**：**传统 VPN 在网络第 3 层（L3）无差别截获并封装整机所有原始 IP 数据报，对上层域名和业务内容“一无所知”；而现代规则代理在传输层与应用层（L4/L5/L7）工作，必须先理解你的连接“想访问哪个域名或哪个地区的服务器”，再决定是直接放行还是加密转发。** 即使现代代理客户端为了接管不认系统代理的软件而开启了 [TUN 虚拟网卡模式](/guides/tun/)，数据包进入用户态核心后依然要立刻还原成四层/七层会话流接受规则引擎的精细审阅。

### 1.1 条件说明：两种协议栈的数据包生命周期对比

#### 路径 A：传统商业 VPN 的 OSI 第 3 层全包封装路径（IP-in-IP / WireGuard / OpenVPN）
1. **全局虚拟网卡捕获**：VPN 客户端在系统内核挂载虚拟网卡（Windows 下为 `Wintun` 或 `TAP-Windows`，macOS/iOS 下为 `utun` / `NEPacketTunnelProvider`，Android 下为 `VpnService tun0`），并将操作系统默认路由表 `0.0.0.0/0` 的最高优先级指向该虚拟网卡。
2. **整包盲加密打包**：无论是 Chrome 浏览器发起的 HTTPS 请求、CMD 终端发出的 `ping`（ICMP 协议）、还是微信视频通话的 UDP 包，系统一视同仁全部交由虚拟网卡读取原始 IP 数据报（包含源 IP、目标 IP 与负载）。
3. **单一通道外发与统一出口**：WireGuard（使用 `ChaCha20-Poly1305`）或 OpenVPN（使用 `AES-256-GCM`）直接对整个 IP 数据包再次加密并套上新的外层 UDP/TCP 头部，统一送往你在地图上选定的单一海外网关节点，由该节点拆封并以自身 IP 代为访问目标。
4. **核心工程后果**：传统 VPN 隧道天然具备**“全有或全无”的强包裹性**——安全性与防局域网嗅探能力拉满，但隧道内部缺乏内置的全球数万条域名实时决策表；哪怕国内目标服务器就在同城机房，数据包也往往要绕行海外网关一圈再回来。

#### 路径 B：现代规则代理机场的传输/应用层引擎路径（Mihomo / sing-box / Xray）
1. **本地监听接入或 TUN 协议栈重组**：
   - **系统代理模式**：客户端在本地回环地址 `127.0.0.1` 监听 HTTP/HTTPS 与 SOCKS5 端口（如 `7897`、`10808`），浏览器在发起 TCP 握手前主动把目标域名（如 `api.openai.com`）直接递交给代理端口。
   - **TUN 模式**：客户端同样创建虚拟网卡捕获 IP 包，但**绝不直接发往海外**，而是由内置的轻量级用户态 TCP/IP 协议栈（`gVisor` / `lwIP`）将零散的三层 IP 包重组为完整的 TCP/UDP 数据流。
2. **域名嗅探（Sniffing）与 Fake-IP 还原**：即便终端程序只传来了经过本地解析的 IP 地址，代理核心也会主动嗅探 HTTPS 握手第一帧（TLS `ClientHello` 中的 `SNI` 字段）或 HTTP `Host` 头，或者通过本地保留网段（如 `198.18.0.1/16`）的 Fake-IP 映射表瞬间反查出用户真正要访问的完整域名。
3. **规则引擎毫秒级路由决策（Routing Engine）**：拿到精确域名与目标 IP 后，核心依次比对规则集（例如 `GEOSITE,cn,DIRECT`、`GEOIP,CN,DIRECT`、`DOMAIN-SUFFIX,openai.com,🇺🇸 美国节点`）。
   - **国内目标**：直接不经过加密协议封装，由物理网卡本地直发；
   - **海外目标**：根据预先写好的策略组规则，把“ChatGPT 请求”发往美国原生/合规节点，把“Netflix/YouTube 请求”同时发往香港或新加坡高速节点，支持并行分流。
4. **现代抗特征伪装协议封装**：最终出站数据包通过 **VLESS-Reality**（借用真实权威大站 TLS 1.3 证书链与回落防御主动探测）、**Trojan**（伪装标准 HTTPS 服务器）或 **Hysteria 2**（基于 QUIC 针对跨境丢包链路做强拥塞压榨）发往机场中转入口或 IEPL/IPLC 专线。

### 1.2 证据与对比：VPN 协议栈 vs 代理协议栈核心技术参数矩阵

| 技术拆解维度 | 传统商业 VPN（IP 层隧道） | 规则代理机场（传输/应用层规则引擎） | 专职游戏加速器（进程驱动 + UDP 优化） |
| :--- | :--- | :--- | :--- |
| **主导 OSI 工作层** | **第 3 层（网络层）** | **第 4/5/7 层（传输 / 会话 / 应用层）** | **内核过滤驱动层 + 传输层 UDP** |
| **典型底层协议** | WireGuard、OpenVPN (UDP/TCP)、IKEv2 | VLESS-Reality、Trojan、Shadowsocks (2022)、Hysteria 2、AnyTLS | 私有 UDP 隧道封装 + 双/多路冗余发包与前向纠错（FEC） |
| **加密粒度与防嗅探范围** | **设备级全流量无死角加密**（含 ICMP 与所有冷门端口） | **连接级按规则加密**：命中直连规则的国内流量保持原生 HTTPS 明文传输不入隧道 | **白名单进程级封装**：仅对游戏服务器特定端口 UDP/TCP 封装，不加密网页流量 |
| **国内直连分流精度** | **粗粒度（极低）**：全局接管下国内软件被迫绕远路；Split Tunneling 仅支持按应用或少数 IP 段排除，同浏览器内外网站混开无法分开 | **极高精度（域名 + IP + 进程）**：依托 `geosite`、`geoip` 与自定义覆写脚本，同一个浏览器内国内标签页直连、海外标签页自动分国别节点 | **极窄白名单直放行**：非游戏白名单软件全部旁路走本地物理网卡直连 |
| **DNS 防泄露与本地解析速度** | 由远端 VPN 节点统一代解析，无 DNS 泄露风险，但国内域名易被解析到海外缓慢 CDN | **分流双 DNS（Fake-IP / Redir-Host）**：国内域名交给阿里/腾讯公共 DoH 获最近节点，境外域名在防污染后交远端代理节点解析 | 仅劫持游戏登录认证及区服匹配域名，常规 DNS 解析不受影响 |
| **抗 DPI 特征识别能力** | **较弱**：标准 WireGuard（固定 `148B/92B` 握手包长）与 OpenVPN 握手特征明显，固定机房 IP 段易被集中阻断 | **极强**：Reality 借用真实权威站证书消除指纹，Trojan 模拟标准 Nginx HTTPS，配合国内入口专线/中转极少误伤 | **中等**：依托合规跨境专线或 BGP 游戏专用接入网关，仅保障游戏区服端口连通 |
| **多地区并发与故障转移** | 同一时间整机只能连向单一国家网关，节点卡顿需手工切换 | **多策略组并行 + 自动故障切换**：可按 `url-test` / `fallback` 自动剔除超时节点，不同网站同时走不同国家落地 | 自动优选当前游戏区服最低抖动线路，但严禁对局中途频繁切换出口 IP |

## 二、商业透明度、定价结构与“伪概念”辨析

很多用户在实际选购时不仅要分清技术原理，还要面对五花八门的商业宣传口径。结合本站 `brands.ts` 与 `clients.ts`（2026-11-23 核验快照），下面把三类工具的商业逻辑和常见误区彻底摊开对比。

### 2.1 三类工具的商业成本结构与透明审计差异

| 商业与安全维度 | 国际商业 VPN | 规则代理机场（含开源客户端生态） | 专职游戏加速器 |

| **开源与可审计透明度** | 头部品牌公布 **Cure53、PwC、Deloitte** 等近 1–2 年独立无日志审计（No-Logs Audit）与 RAM-Only 无盘服务器证明 | **客户端 100% 开源可核验**（如 [Clash Verge Rev](/clients/clash-verge-rev/)、[v2rayN](/clients/v2rayn/)、[FlClash](/clients/flclash/)、[Hiddify](/clients/hiddify/)、[Mihomo](/clients/mihomo/)）；但服务端由小团队运营，无第三方审计背书 | 客户端**全部闭源**，且国内商业合规产品普遍要求手机号实名认证或登录校验 |

| **典型计费与价格区间（2026-11-23 参考）** | 多为美元计价：长期年付折算约 **$3–$6/月**，纯月付约 **$10–$13/月**（折合人民币约 ¥70–¥95/月）；常标注“不限流量但限制同时在线设备数（如 5–10 台）”，且存在“首期优惠、次年高价自动续费”陷阱 | 多为人民币或 USDT 按月重置流量计费：**主流月付参考区间约 ¥15–¥35/月**（例如本站 `brands.ts` 收录的光速云极速版 ¥25/月 168GB、可信云参考档 ¥25/月 150GB、暮光加速 ¥20 起等）；另有 ¥99 级年付轻量包及不限时按量备用包 | 约 **¥20–¥45/月**按时长不限游戏流量计费，另常区分 PC 端会员、手游端会员与主机全平台会员（或单独售卖硬件加速盒） |
| **设备锁定与自由迁移度** | 绑定单一 VPN 品牌官方客户端（部分可导出标准 WireGuard 配置给路由器） | **支持第三方通用订阅的机场完全自由解耦**；而“仅专属客户端”机场强绑定自有软件 | 强绑定自家桌面/移动端闭源客户端与专用硬件盒子 |

### 2.2 四大高频“概念混淆”深度辟谣

1. **“我买了个提供免配置一键登录软件的‘VPN’，它算国际商业 VPN 吗？”**
   - **不算传统审计意义的商业 VPN**。在本站 `brands.ts`（2026-11-23 快照）中，收录了如 [飞猫云](/brands/feimao/)、[SOGO 云](/brands/sogo/)、[隐形人](/brands/yinxingren/)、[Firefly（萤火虫）](/brands/firefly/) 等标注为 **`仅专属客户端`** 模式的品牌。它们本质上是把自有代理节点与 Mihomo/Xray/sing-box 内核打包封装在一个带有登录界面的壳子里，虽然降低了新手复制粘贴订阅链接的门槛，并在安卓上同样通过 `VpnService` 亮起钥匙图标，但**并未经历任何独立第三方的无日志架构审计**，且不允许你把配置导出给开源工具（如 Shadowrocket 或 OpenClash）。
2. **“机场节点跑满百兆测速，为什么用来打 CS2 / Switch 马车联机还是卡爆？”**
   - 因为**大带宽吞吐（Throughput）与低抖动抗丢包（Low Jitter + FullCone NAT）是两套完全独立的工程要求**。看 4K 视频可以允许几百毫秒缓冲池慢慢重传，而实时竞技游戏依靠每秒数十上百次几十字节的小包 UDP 交互，只要晚高峰跨境链路出现 2% 丢包或出口为 Symmetric NAT（对称型 NAT），就会立刻表现为人物瞬移或主机提示 `NAT Type D / F`。完整原理可参阅 [游戏加速器原理与 FullCone NAT 解析](/vpn/gaming/)。
3. **“安卓手机顶部状态栏出现钥匙图标，是不是就代表正在使用传统 VPN？”**
   - **不是**。正如我们在 [安卓 VPN 与代理区别专题](/vpn/android/) 中拆解的，Android 沙盒安全模型规定任何非 Root 应用想接管全机流量都必须调用 `VpnService` 创建 `tun0` 虚拟网卡。无论是传统 WireGuard VPN 还是基于 rules 分流的 FlClash / v2rayNG，系统状态栏一律统一显示同一个钥匙图标，二者差异只在软件内部如何处置数据包。
4. **“我只是偶尔查查资料，先找个免费 VPN 顶一顶行不行？”**
   - 免费服务普遍存在**严苛限速、几百人挤爆同一个被标记的风控出口 IP（极易连坐封禁 ChatGPT 与 Google 账号）、甚至后台植入广告 SDK 与倒卖住宅出口带宽**的隐性代价。详细风险分析可阅读 [免费 VPN 的使用限制与隐性代价](/vpn/free/)。

2. **优先挑选“客户端与节点解耦”的开源生态**：在桌面端和手机端安装来自官方 GitHub Releases（核对 `SHA256`）或正版外区 App Store 的开源规则客户端（如 [Clash Verge Rev](/clients/clash-verge-rev/)、[FlClash](/clients/flclash/)、[Shadowrocket](/clients/shadowrocket/)），服务商则在 [品牌数据库](/brands/directory/) 中优先选择明确标注“自研+第三方订阅”或“第三方通用订阅”的品牌。这样哪怕某家机场突发维护或停止服务，你只需 30 秒更换订阅地址即可恢复工作，不被任何闭源软件绑定。
3. **本机路由与分流健康度核验**：安装配置完毕后，务必用两分钟执行一次基础分流检查——用本地查询工具确认国内 IP 测速显示当前城市宽带真实地址，而海外 IP 查询显示已切换至目标节点地区，且 DNS 请求未发生本地运营商抢答污染（排查方法详见 [DNS 污染与 Fake-IP 排障](/troubleshooting/dns/)）。

## 常见问题（FAQ）

### 从计算机网络原理看，VPN 和代理（Proxy）最本质的技术区别是什么？

本质区别在于工作在 OSI 七层模型中的不同层级与分流方式。传统 VPN 工作在 OSI 第 3 层（网络层），通过系统虚拟网卡捕获整机所有 IP 数据包（含 TCP/UDP/ICMP）进行整包加密隧道传输；而代理（SOCKS5 / HTTP / VLESS / Trojan）主要工作在传输层与应用层，由客户端核心先做域名嗅探与本地分流规则匹配（`geosite`/`geoip`），仅将命中规则的目标连接代理转发，未命中流量则由本地物理网卡直接发出。

### 普通个人用户日常开发、查资料、用 ChatGPT 和看 4K 流媒体，到底应该买商业 VPN 还是代理机场？

在存在强跨境干扰的网络环境下，应当优先选择“开源规则客户端（如 Clash Verge Rev、v2rayN、Shadowrocket、FlClash）+ 支持第三方订阅的代理机场”。原因在于代理协议（如 VLESS-Reality、Trojan、Hysteria 2）抗特征识别能力显著强于标准 WireGuard/OpenVPN，且本地规则引擎能保证微信、网银、国内网盘走本地直连零降速；只有当你长期身处海外、高频连接机场或酒店公共 Wi-Fi 且需要第三方无日志审计背书时，才建议购买国际商业 VPN。

### 为什么传统商业 VPN 即使带了 Split Tunneling（分应用隧道），在日常使用中依然不如规则代理顺滑？

商业 VPN 的 Split Tunneling 通常只能以操作系统“可执行文件或应用包名”为最小颗粒度做粗略排除（比如排除微信或钉钉）。但现代用户绝大多数工作都在同一个 Chrome 或 Edge 浏览器里完成——左边标签页开百度网盘、公司内网与淘宝，右边标签页开 GitHub、Google Scholar 与 ChatGPT。按进程分流对此无能为力，只有基于 Mihomo 或 sing-box 规则引擎的域名级分流才能实现同一浏览器内毫秒级内外分离。

### 怎么判断一个提供“一键下载专属客户端”的机场，本质上是代理机场还是国际商业 VPN？

可以从三个客观维度甄别：第一看审计与合规披露，正规国际商业 VPN 通常公开 Cure53、PwC 或 Deloitte 等独立第三方无日志审计报告及明确的注册司法管辖地，而专属客户端机场不具备此类报告；第二看底层协议，专属客户端机场底层往往仍是封装了 Mihomo/Xray 的 VLESS/Trojan/SS 节点；第三看生态定位，例如本站 2026-11-23 品牌数据库中的飞猫云、SOGO 云、隐形人、Firefly（萤火虫）均属于“仅专属客户端”模式机场，而非传统审计意义上的国际商业 VPN。

### 为什么很多重度用户会同时订阅“主力规则机场 + 专职游戏加速器”，甚至再备一个“不限时小流量包”？

因为三者的技术优化方向完全正交且无法相互替代：主力规则机场解决日常海外学术、AI 工具与 4K 流媒体，并保障国内软件直连不绕路；专职游戏加速器通过多倍冗余发包与 FullCone NAT（NAT Type A）解决 FPS 竞技与主机联机的 UDP 零丢包诉求；不限时一次性流量包（如部分品牌提供的百元级永久包）则专门用于在主力机场临时线路波动或维护时零月费兜底应急。

### 机场配合桌面端开启“TUN 模式”后，是不是在技术上就完全变成 VPN 了？

仅在“本机流量捕获方式”上借用了与 VPN 相同的三层虚拟网卡技术（Wintun / utun），能够强行接管终端命令行、Docker 或不支持系统代理的老旧桌面程序；但在“包进入客户端核心之后的路由逻辑”上它依然是规则代理。数据进入 TUN 后会被 Mihomo/sing-box 重新拆包还原并比对数万条 `geosite`/`geoip` 规则，依然保持国内直连、海外分区域代理以及抗特征伪装协议的优势。

### 使用免费 VPN 或来源不明的破译版加速器会面临哪些实质性安全与账号风险？

主要存在三重隐患：第一，数百名陌生用户挤在少数免费出口 IP 上，极易引发 ChatGPT 封号、Google 频繁人机验证与金融风控连坐；第二，部分免费移动端 App 通过在静默后台倒卖你的家庭宽带出口（P2P 住宅代理节点）或植入数据采集 SDK 变现；第三，搜索引擎广告位传播的“免费破解版软件”常捆绑窃取加密货币钱包与浏览器 Cookie 的木马，得不偿失。
