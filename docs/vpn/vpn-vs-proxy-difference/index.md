faq:
  - q: 从 OSI 网络模型来看，传统 VPN 和规则代理最本质的区别是什么？
    a: 本质区别在于工作层级与决策粒度。传统 VPN 工作在 OSI 第三层（网络层），通过虚拟网卡把整台设备发出的所有 IP 数据包整包加密打包送往单一远端网关，对上层域名与业务一无所知；而现代规则代理工作在第四至七层（传输层至应用层），客户端核心会先嗅探真实域名与进程来源，对照分流规则决定国内流量直接由物理网卡发出、海外流量按目标分别路由。
  - q: 日常写代码、用 ChatGPT 和看 Netflix 4K，应该买知名商业 VPN 还是规则代理机场？
    a: 绝大多数跨境网络环境下应当优先选择规则代理机场搭配 Clash Verge Rev、v2rayN、Shadowrocket 或 FlClash 等开源客户端。原因在于 VLESS、Trojan、Hysteria 2 等代理协议具备极强的抗流量特征识别能力，且精细规则引擎能让国内网盘、微信和银行应用维持本地原生直连不降速，同时把 AI 与流媒体自动分配到不同国家节点。
  - q: 为什么用着延迟很低的专线机场看 4K 视频秒开，打外服 FPS 游戏却经常跳红标甚至无法联机？
    a: 网页与视频基于 TCP 协议并带有数秒预缓冲，少量丢包可通过重传掩盖；而竞技游戏基于实时 UDP 小包，且主机和 P2P 对战游戏强依赖 FullCone NAT（NAT Type A）穿透。大多数代理机场出于防滥用和连接稳定性考虑，默认只对网页 TCP 做优化，部分节点甚至限制 UDP 转发或处于对称型 NAT 状态，难以替代专职游戏加速器的多倍冗余发包机制。
  - q: 为什么绝对不能把商业 VPN 和代理客户端的 TUN 模式同时打开？
    a: 商业 VPN 与代理客户端的 TUN 模式都会在操作系统内挂载虚拟网卡，并争夺默认路由表（0.0.0.0/0 或拆分的 0.0.0.0/1 与 128.0.0.0/1）以及本地 53 端口 DNS 劫持控制权。两者同时启动会导致默认网关不断互相覆盖，甚至让代理发往远端服务器的加密包被再次兜回 VPN 虚拟网卡形成死循环，直接造成全机断网并连带破坏 WSL2 与 Docker 网络。
  - q: 既然游戏加速器底层也是跨境专线加速，为什么不能顺便用来上 Google 或使用 ChatGPT？
    a: 合规运营的商业游戏加速器采用严格的白名单进程和游戏区服 IP 过滤驱动，仅拦截游戏主程序连接特定战网或游戏服务器端口的流量，其余浏览器、终端和 AI 客户端流量全部被旁路放行走本地普通宽带。这种设计既是为了控制高昂的跨境专线带宽成本，也是为了满足合规监管边界。
  - q: 如果公司远程办公必须连接企业自建 VPN，同时又想使用代理访问海外开发文档，应该如何共存？
    a: 千万不要在代理客户端开启全机 TUN 模式下直接重叠运行企业 VPN。正确做法有两种：一是在电脑上关闭代理客户端的 TUN 模式，仅开启系统代理（HTTP/SOCKS 端口）并把公司内网网段及域名加入直连与浏览器排除名单；二是在代理客户端配置文件中将公司 VPN 服务端 IP 与内网 CIDR 网段强制设为 DIRECT，或者将开发代理部署在旁路软路由而本机仅保留公司 VPN。

# VPN 与代理机场、游戏加速器有什么本质区别？技术栈与 12 场景选型指南

<div class="answer-first-box">
  <div class="answer-first-label">核心结论（Answer-First）</div>
  <p><strong>传统商业 VPN、规则代理机场与专职游戏加速器立足于完全不同的 OSI 协议栈层级，服务于三套彼此独立的工程目标</strong>。<strong>传统 VPN</strong>（OpenVPN / WireGuard）工作在 <strong>OSI 第 3 层网络层</strong>，专攻整机全流量加密与公共 Wi-Fi 防窃听，国内分流粗糙且易受特征阻断；<strong>规则代理机场</strong>配合开源客户端工作在 <strong>第 4–7 层传输与应用层</strong>，凭借 VLESS / Shadowsocks / Hysteria 2 / Trojan 协议与规则引擎，兼顾“国内直连零降速 + 多国 AI/流媒体并行分流”；<strong>游戏加速器</strong>依托内核过滤驱动与 <strong>UDP 多倍冗余 + FullCone NAT</strong>，专为低抖动联机设计。三者无法互相替代，且<strong>商业 VPN 绝不可与代理 TUN 模式同时开启</strong>，否则会直接冲毁系统路由表。</p>
</div>

很多人把能改变上网路径的软件统称为“VPN”，但在实际使用中却频频碰壁：海外榜首商业 VPN 连上后微信发图转圈、国内网盘龟速；专线机场看 4K 视频秒开，打外服 FPS 却瞬移掉线；游戏加速器稳如磐石，浏览器却打不开 GitHub。这源于三类工具底层协议栈与分流逻辑的根本差异。

## 一、比较结论：三类工具的选型总纲

1. **高强度隐私加密与海外公共热点防嗅探选“国际商业 VPN”**：长期身处海外、高频连接机场或酒店开放 Wi-Fi，且看重第三方独立无日志审计背书时，应选择三层全包加密的商业 VPN（参考[VPN 综合对比](/vpn/compare/)与[选型建议](/vpn/recommend/)）。
2. **代码开发、AI 工具与 4K 流媒体日常主力选“规则代理机场”**：在高频混用国内外应用与网站的环境下，只有搭载 [Mihomo](/clients/mihomo/) 或 [sing-box](/clients/sing-box/) 规则引擎的开源客户端配合通用订阅机场，才能实现“国内直连无损耗 + 多区海外自动分流”。
3. **外服竞技网游与主机联机选“专职游戏加速器”**：面对实时 UDP 小包低抖动、FullCone NAT（Type A）以及反作弊稳定性要求，游戏加速器的驱动级冗余补包机制不可被普通代理替代（机制详解见[游戏加速器与代理对比](/vpn/gaming/)）。

## 三、关键区别：底层协议栈差异与并发路由破坏机理

### 1. Layer 3 IP 隧道（OpenVPN / WireGuard）的“全有或全无”局限
传统 VPN 在操作系统内核挂载虚拟网卡后，会写入两条半覆盖默认路由（`0.0.0.0/1` 与 `128.0.0.0/1`），以高于物理网卡 `0.0.0.0/0` 的优先级接管整机全部 IP 数据包。无论是 **OpenVPN** 的 TLS 隧道还是 **WireGuard** 的 `ChaCha20-Poly1305` 内核转发，三层协议栈只能看到目标 IP 而无法感知完整域名。即便软件提供“分应用隧道（Split Tunneling）”，也无法切分同一个浏览器窗口里左半边淘宝、右半边 GitHub 的混合请求。同时，标准 WireGuard 固定的握手包长特征在跨境环境中更容易遭遇精准阻断。

### 2. Layer 4–7 规则代理（VLESS / SS / Hysteria 2 / Trojan）的精细引擎
现代代理客户端（如 [Clash Verge Rev](/clients/clash-verge-rev/)、[v2rayN](/clients/v2rayn/)、[Shadowrocket](/clients/shadowrocket/)、[FlClash](/clients/flclash/)）解决了加密伪装与精细分流两大难题：
- **协议抗探测**：**Trojan** 模拟标准 HTTPS 服务器响应；**VLESS-Reality** 直接借用真实权威大站的 TLS 1.3 证书链消除握手指纹；**Shadowsocks AEAD** 追求低开销；**Hysteria 2** 基于 QUIC 在高丢包链路上做拥塞优化。
- **用户态重构与域名还原**：即便为了接管终端命令行而开启代理 [TUN 模式](/guides/tun/)，数据包进入虚拟网卡后也不会盲目出境，而是先由 `gVisor` 或 `lwIP` 用户态协议栈重组为四层流，再通过 **Fake-IP（`198.18.0.1/16` 反查）** 或 **Sniffer（嗅探 TLS `SNI` 与 HTTP `Host`）** 还原出完整域名，对照 `rules:` 秒级决定直连还是发往特定国家出口。

### 3. 游戏加速器的内核驱动与 UDP 冗余
视频播放靠几秒预加载掩盖丢包，但竞技游戏毫秒必争。游戏加速器在驱动层截获游戏进程 UDP 报文后，通过轻量化私有封装在多条链路同时做冗余发包（FEC/双路并发），并用较低抖动的网关维持 **FullCone NAT** 映射，确保主机语音与对战匹配顺畅，代价则是严格禁止普通浏览器与第三方工具蹭用其专线。

### 4. 致命冲突：为什么同时开“商业 VPN + 代理 TUN 模式”会摧毁网络？
同时运行两个三层接管工具会立刻触发操作系统路由灾难：
1. **默认路由抢占打架**：商业 VPN 与代理 TUN 启动时都会试图把 `0.0.0.0/1`、`128.0.0.0/1` 指向自己的虚拟网卡，后启动者覆盖先启动者，或两者定时检测并互相强抢路由表，造成网关每秒剧烈跳变。
2. **隧道套娃环回死锁**：如果商业 VPN 抢到了路由，代理客户端发往境内中转入口服务器的加密包会被塞进海外 VPN 隧道兜一大圈；反之若代理 TUN 抢到路由且未排除 VPN 网关 IP，公司或商业 VPN 的心跳握手包会被拽入代理节点再连回网关，延迟飙升或 IP 跳变直接引发断线重连死循环。
3. **DNS 53 端口劫持与 WSL2/Docker 连坐瘫痪**：双方同时争抢本地 DNS 劫持规则，极易连带把 Windows Hyper-V、WSL2 与 Docker 的 `172.16.0.0/12` 网桥通信吸进隧道或切断转发。具体排查与共存写法见 [TUN 模式与 WSL2 / Docker 冲突修复](/troubleshooting/tun-wsl-docker-conflict/)。

## 四、适用人群与典型混合方案

- **开发者、科研与重度 AI 用户**：**“支持通用订阅的规则代理机场 + 开源桌面客户端”**为主力。日常保持 `Rule` 模式，有终端需求时开 TUN 并放行内网与 Docker 网段；连接公司 VPN 前切记关闭 TUN，仅用系统代理或设好 `DIRECT` 排除。
- **外服竞技玩家兼跨境浏览者**：**“专职游戏加速器 + 规则代理机场”**分时协同。打游戏时只开加速器，查资料看视频时使用系统代理模式的机场客户端。
- **国际差旅商务人士**：笔记本配备经过独立无日志审计的**国际商业 VPN** 专供公共热点加密，日常跨境分流另备手机端规则代理，严格分时单开。

## 五、条件与限制：合规、隐私与免费工具红线

1. **隐私审计边界**：头部商业 VPN 拥有 Cure53、PwC 等独立第三方无日志审计报告与纯内存无盘节点；个人代理机场由中小团队运维，客户端开源可核验但服务端无审计背书，连接期间**切勿导入不明根证书或关闭 HTTPS 校验**（详见[代理安全与隐私边界](/safety/privacy/)）。
2. **远离“免费 VPN”与破解加速器**：市面上的永久免费软件常通过把用户宽带转卖为住宅代理肉鸡或植入采集 SDK 变现，且共享脏 IP 会导致 ChatGPT 与 Google 账号批量连坐风控（见[免费 VPN 风险分析](/vpn/free/)与[避坑指南](/safety/avoid-scams/)）。
3. **遵守合规边界**：任何网络加速与代理工具仅应用于合法合规的研发、学术、跨境商务与个人正当信息获取，严禁用于违规攻击或恶意爬虫。

## 六、常见问题（FAQ）

### 从 OSI 网络模型来看，传统 VPN 和规则代理最本质的区别是什么？

本质区别在于工作层级与决策粒度。传统 VPN 工作在 OSI 第三层（网络层），通过虚拟网卡把整台设备发出的所有 IP 数据包整包加密打包送往单一远端网关，对上层域名与业务一无所知；而现代规则代理工作在第四至七层（传输层至应用层），客户端核心会先嗅探真实域名与进程来源，对照分流规则决定国内流量直接由物理网卡发出、海外流量按目标分别路由。

### 日常写代码、用 ChatGPT 和看 Netflix 4K，应该买知名商业 VPN 还是规则代理机场？

绝大多数跨境网络环境下应当优先选择规则代理机场搭配 Clash Verge Rev、v2rayN、Shadowrocket 或 FlClash 等开源客户端。原因在于 VLESS、Trojan、Hysteria 2 等代理协议具备极强的抗流量特征识别能力，且精细规则引擎能让国内网盘、微信和银行应用维持本地原生直连不降速，同时把 AI 与流媒体自动分配到不同国家节点。

### 为什么用着延迟很低的专线机场看 4K 视频秒开，打外服 FPS 游戏却经常跳红标甚至无法联机？

网页与视频基于 TCP 协议并带有数秒预缓冲，少量丢包可通过重传掩盖；而竞技游戏基于实时 UDP 小包，且主机和 P2P 对战游戏强依赖 FullCone NAT（NAT Type A）穿透。大多数代理机场出于防滥用和连接稳定性考虑，默认只对网页 TCP 做优化，部分节点甚至限制 UDP 转发或处于对称型 NAT 状态，难以替代专职游戏加速器的多倍冗余发包机制。

### 为什么绝对不能把商业 VPN 和代理客户端的 TUN 模式同时打开？

商业 VPN 与代理客户端的 TUN 模式都会在操作系统内挂载虚拟网卡，并争夺默认路由表（0.0.0.0/0 或拆分的 0.0.0.0/1 与 128.0.0.0/1）以及本地 53 端口 DNS 劫持控制权。两者同时启动会导致默认网关不断互相覆盖，甚至让代理发往远端服务器的加密包被再次兜回 VPN 虚拟网卡形成死循环，直接造成全机断网并连带破坏 WSL2 与 Docker 网络。

### 既然游戏加速器底层也是跨境专线加速，为什么不能顺便用来上 Google 或使用 ChatGPT？

合规运营的商业游戏加速器采用严格的白名单进程和游戏区服 IP 过滤驱动，仅拦截游戏主程序连接特定战网或游戏服务器端口的流量，其余浏览器、终端和 AI 客户端流量全部被旁路放行走本地普通宽带。这种设计既是为了控制高昂的跨境专线带宽成本，也是为了满足合规监管边界。

### 如果公司远程办公必须连接企业自建 VPN，同时又想使用代理访问海外开发文档，应该如何共存？

千万不要在代理客户端开启全机 TUN 模式下直接重叠运行企业 VPN。正确做法有两种：一是在电脑上关闭代理客户端的 TUN 模式，仅开启系统代理（HTTP/SOCKS 端口）并把公司内网网段及域名加入直连与浏览器排除名单；二是在代理客户端配置文件中将公司 VPN 服务端 IP 与内网 CIDR 网段强制设为 DIRECT，或者将开发代理部署在旁路软路由而本机仅保留公司 VPN。
