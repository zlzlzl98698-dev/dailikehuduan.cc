## 一、「仅专属客户端」与零通用订阅架构：哪些用户会被直接挡在门外？

在评测[隐形人](/brands/yinxingren/)的套餐价格和线路之前，必须把**客户端模式（Client Mode）**放在第一章第一顺位讲透。因为在代理客户端的实际使用中，价格贵几块钱只是财务问题，而**“不给通用订阅链接、强制绑定专属客户端”**则是决定您手头设备能不能用的根本问题。

在 `32家机场品牌清单.txt`（#27）中，隐形人的客户端策略写得非常决绝：**`隐形人自带专属客户端（明确不支持 Clash/Shadowrocket 等第三方客户端）`**，同时其底层代理协议显示为 **`未标注（自带客户端封装）`**。

### 1. 为什么越来越多机场在 2025–2026 年改用「仅专属客户端」？

从机场运营方的视角来看，放弃通用订阅而强制使用自研/打包专属客户端，主要出于以下三点商业与防封考量（详细技术对比见 [专属客户端 vs 第三方通用订阅深度解析](/airport/client-vs-third-party-subscription/)）：
1. **隐藏节点入口 IP 与底层协议特征**：通用 Clash YAML 或 Base64 订阅一旦导出，任何人都可以在明文配置里看到所有国内中转机房的入口域名、端口号、UUID 和传输协议（VLESS / Trojan / SS）。将配置加密封装在自带客户端内部，能防止同行恶意扒取节点列表或自动化爬虫举报。
2. **降低新手客服工单成本**：超过一半的新手连接失败是因为不会导入订阅、不会切换 Mihomo 内核或开错了系统代理与 TUN 模式。打包成“输入邮箱密码、点击一键连接”的专属端，能省去大量基础教学沟通。
3. **严格的设备数与防合租控制**：通过专属客户端的账号登录态（Token 会话踢线机制），运营方能比纯订阅链接更精准地控制同时在线终端数。

## 二、「晚高峰零卡顿、1 小时修复」售后声明 vs「全表 0 实测数据」的证据反差审计

在 `brands.ts` 数据库的 `claims`（品牌声明）与 `testRuns`（测速记录）两个字段之间，隐形人呈现出全库 31 家品牌中反差最强烈的一组对比。作为恪守五级证据链标准的独立评测机构，我们必须把这种**「高调售后承诺」与「空白实测台账」**并列摊开供读者审视。

<NetworkPathDiagram slug="yinxingren" />

### 1. 逐句拆解隐形人的四项 `vendor` 品牌方宣称

在 `32家机场品牌清单.txt`（#27）及汇总表中，隐形人的核心宣传卖点包括：
1. **「企业级 IPLC 专线直连」**（`evidence: 'vendor'`）：宣称采用不过公网防火墙的内网专线（关于 IPLC 与普通公网中转的物理差异，详见 [IPLC 国际专线科普与真伪查验](/routes/iplc/) 以及 [IEPL 专线的含义与价值评估](/airport/iepl-meaning-and-value/)）。
2. **「香港、日本、美国、新加坡、台湾 60+ 节点」**（`evidence: 'vendor'`）：覆盖标准五常地区，节点总数标称 60 个以上。
3. **「晚高峰零卡顿」**（`evidence: 'vendor'`）：这是典型的商业营销绝对化用语。在真实的网络拓扑中，用户的最终网速取决于「本地宽带运营商（电信/联通/移动）最后十公里 $\rightarrow$ 国内中转入口 BGP 机房 $\rightarrow$ IPLC/IEPL 过境专线 $\rightarrow$ 海外落地机房到目标网站」四段链路的总和。即便专线过境段带宽充足，只要用户本地省网到国内入口出现晚高峰 QoS 限速，或者海外落地 IP 被目标流媒体限流，就必然产生抖动。因此，**任何承诺“绝对零卡顿”的宣传语在工程上均不可采信为客观事实**（参见 [靠谱机场的 7 项可验证指标](/airport/reliable/)）。
4. **「1 小时修复承诺」**（`evidence: 'vendor'`）：这是隐形人在售后服务维度打出的差异化口号。在机场行业，节点 IP 被封或中转入口遭受 DDoS 攻击是家常便饭，品牌方敢于提出“1 小时修复”说明其主打响应速度卖点；但该承诺既无超时赔付细则（SLA），也明确伴随着“无免费试用”的前提，其真实工单响应速度只能在实际购入月付后通过发工单检验。

### 2. 为什么 `<PerformanceReport>` 显示为无可用测速数据？

请看上方的性能监测报告组件。在 `2026-10-19` 主表收录的众多品牌中，有 15 家附带了五地延迟与吞吐记录（尽管为非晚高峰历史汇总），另有 [灵动云](/brands/lingdong/) 附带了 `2026-07` 珠海联通 9Gbps 60 节点实测归档。**唯独隐形人在 `2026-10-19` 原始测速汇总表里，香港、台湾、新加坡、日本、美国五个地区的延迟与下载速度全部填写为 `—`（空白）**。

本站在编写 `brands.ts` 时严格执行**「零伪造铁律」**：既然原始档案全为 `—`，我们就绝不拿同价位其他 IPLC 品牌的 `500Mbps` 数据去替隐形人填表，而是将 `testRuns` 保持为空数组 `[]`，并在 `riskFlags` 第一条醒目标注：**`无可用测速数据（原表全为“—”）`**。

### 3. AI 与流媒体可用性矩阵：Claude、Gemini 与 TikTok 的条件性限制

<AvailabilityMatrix slug="yinxingren" />

再看隐形人的服务解锁矩阵（全部基于 `vendor` 品牌方资料标注）：

- **视具体节点与时段而定（`conditional`）**：**Claude、Gemini** 两项主流 AI，以及 **TikTok**。

但在隐形人这类**自带专属客户端**里，分流规则通常是由客户端内置写死的（只提供简单的“智能/规则模式”与“全局模式”两个按钮）。如果它内置的规则没有把 Claude、Gemini 或 TikTok 精准路由到干净的原生 IP 节点，用户就只能手动把整个客户端切到某个特定国家节点去碰运气。对于高频使用 Claude 3.5/3.7 写代码或运营 TikTok 的用户，这一操作局限必须提前知晓（相关排障原理可参考 [Claude 地区限制排查](/ai-streaming/claude/) 与 [Gemini 分流规则指南](/ai-streaming/gemini/)）。

### 1. 冲突一：「白银纪元」¥24/月到底是 100GB 还是 144GB？（单价差幅高达 44%）

在 `32家机场品牌清单.txt`（#27）中：
- 顶部 **「基础数据概要」** 写的是：月付起价 **`24 元 / 100GB / 月`**；
