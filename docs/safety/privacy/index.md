  <div class="answer-first-label">核心结论 · Answer First</div>
  <p>围绕<strong>“机场安全吗”</strong>的讨论常陷入“完全不安全能偷看密码”与“挂上代理就绝对隐身”两个极端。从密码学与分层传输原理看，只要坚持<strong>不安装任何未知第三方 CA 根证书</strong>并访问标准 HTTPS 站点，机场节点<strong>看不到你的网银、邮箱、GitHub 账号密码与聊天正文</strong>；但它必然看得到<strong>客户端源 IP、连接时间戳、目标域名（SNI / 远程 DNS）与流量大小</strong>。真正决定普通用户隐私下限的，是<strong>开源可审计客户端 + 拒绝不明 MitM 根证书 + 保护好订阅链接 Token + 独立密码与规则分流隔离</strong>。</p>

## 一、机场安全吗？先破除代理隐私的两大认知误区

围绕“机场安全吗”的争论，通常集中在两个极端：要么担心挂上代理就会被盗取网银和微信密码，要么误以为开启代理后自己在互联网上完全隐身。这两种想法都不符合现代网络协议的分层事实。

### 1. 为什么常规机场“偷看不了密码”，却“看得到你去了哪里”？

日常使用中，无论是直连还是走代理，流量都要经过物理宽带运营商。启用代理后，设备与海外网站之间会同时存在**两层互相独立的加密保护**：
- **外层代理隧道加密**：客户端通过 `VLESS`、`Trojan`、`Shadowsocks` 或 `Hysteria 2` 封装数据发往机场入口，使本地运营商和沿途路由无法直接读取你访问的海外域名及内容特征。
- **内层端到端 TLS（HTTPS）加密**：由浏览器或 App 直接与银行、Gmail、GitHub 或 ChatGPT 服务器协商会话密钥。**机场服务端既没有目标网站私钥，也无法绕过系统根证书校验去篡改 TLS 握手。**

因此，用于跨境办公、科研文献、[ChatGPT](/ai-streaming/chatgpt/) 与 [YouTube](/ai-streaming/youtube/) 访问时，配合标准 HTTPS 已具备极高内容保密性；但它绝不是零日志匿名通信工具，无法对服务端隐藏你的来源 IP 与目标域名记录。

### 2. 四方视角透视：数据链路上究竟谁能看到什么？

假设你正在用开源客户端 [Clash Verge Rev](/clients/clash-verge-rev/) 登录 `https://github.com/login`，四个环节各自可见的信息边界如下：

| 链路参与方 | 能明确观测到的信息（Visible Metadata） | 绝对看不到的信息（前提：标准 HTTPS 且未装未知 CA） | 核心隐私风险点 |
| :--- | :--- | :--- | :--- |
| **1. 本地设备与代理客户端** | **全部本地数据**（未加密前输入、剪贴板、浏览器 Cookie、订阅链接、DNS 记录） | 无（客户端运行在系统用户态或 TUN 权限层，具有最高本地可见性） | **风险最高层**：装入山寨木马客户端（见 [下载安全防钓鱼](/safety/security/)）会直接导致信息失守 |
| **2. 本地宽带运营商（ISP）** | 连接的国内中转入口 IP 与端口、加密隧道连接时间、吞吐量规律 | 最终访问的 `github.com` 域名、网页正文、密码及隧道内远程 DNS 请求 | 未开防泄漏时逃逸的本地 `UDP 53` DNS 查询 |
| **3. 机场入口 / 落地节点** | **你的公网源 IP**、上线时间戳、消耗流量、**目标域名（TLS 明文 SNI）与端口**、出口侧 DNS | **HTTPS 页面正文、URL 路径（如搜索词）、账号密码、表单与加密 Cookie** | 若经由节点访问**非加密纯 `http://` 网站**，出口节点可直接看到 HTTP 明文 |
| **4. 最终目标网站（如 GitHub）** | 机场落地节点的公网出口 IP、浏览器指纹、登录后的站内行为 | 你在家里宽带或手机基站的真实物理 IP 与居住地位置 | 多人共用落地 IP 高频操作易触发账号风控或验证码 |

> **关键认知落差**：普通人常担心服务端破解 HTTPS，却忽视了**客户端本身的安全性与未加密 HTTP 流量**。来源不明的闭源魔改程序根本无需破解加密，在本机内存和剪贴板就能读取一切。

## 二、HTTPS / TLS 端到端加密的真实保护边界与服务端可见元数据

为了让你在技术上彻底放心同时又不盲目大意，我们需要把“HTTPS 究竟保住了什么”以及“代理节点必然看到哪些元数据”拆解到协议字段级别。

### 1. 为什么只要不装第三方 CA 根证书，代理就看不到网银和聊天明文？

当你的手机银行 App、微信、或者 Chrome 浏览器访问任何 `https://` 开头的网址时，底层都会执行 **TLS（Transport Layer Security）握手协议**：
1. 你的设备向目标服务器发出 `ClientHello`，双方通过非对称加密算法（如 ECDHE 密钥交换）协商出一个仅在本次会话有效的**对称会话密钥**。
2. 目标服务器返回一张由全球公认权威机构（如 DigiCert、Let's Encrypt、Sectigo，已预置在 Windows/macOS/iOS 系统底层信任库中）签名的**数字证书**。
3. **机场代理服务器在这个过程中扮演的是“盲盒快递员”角色**：它负责把你的 TCP 字节流原封不动地从入口转发到目标服务器 443 端口，再把返回字节流原封不动地送回你的电脑。
4. 如果机场运营方试图在半路上偷看或替换这张证书，你的操作系统与浏览器会立刻比对数字签名并发现“证书颁发者不受信任 / 证书域名不匹配”，随即在屏幕弹出醒目的红色安全拦截页面（`NET::ERR_CERT_AUTHORITY_INVALID`），直接阻断连接。

因此，**只要没有出现证书告警、且你从未在系统证书库中手动信任过陌生第三方根证书（Root CA）**，哪怕机场后台开着抓包工具，抓取到的也全都是无法还原的高强度 AES/ChaCha20 随机密文流。

### 2. 代理服务端真正可见的四项核心元数据

尽管看不到通信正文，但代理服务器为了完成网络寻址与面板计费，必然需要读取或处理以下四项元数据（Metadata）：

1. **客户端公网源 IP（Source IP）**：你的设备连接机场中转入口 IP 时，TCP/UDP 数据包头部必须带有你家宽带或手机 4G/5G 基站分配的公网源 IP，否则回程数据包不知道该发回哪里。机场后台面板里的“当前在线 IP 数统计”就是基于此字段实现的。
2. **连接时间戳与持续时长（Connection Timestamps）**：服务器记录了某个账户凭证（如你的 VLESS `uuid` 或 Trojan 密码）在什么时间点建立连接、何时断开、同时发起了多少个并发 TCP 连接。
3. **目标域名 SNI、目标 IP 与端口（SNI & Destination IP）**：
   - 在现代互联网普及 ECH（Encrypted ClientHello）之前，标准 TLS 握手的第一个 `ClientHello` 数据包中，包含了用于告诉服务器你要访问哪个域名的明文扩展字段——**SNI（Server Name Indication）**。
   - 举个例子：当你在浏览器输入 `https://www.google.com/search?q=xxx` 时，机场落地服务器能从 SNI 和 DNS 解析中看到“该用户正在连接 `www.google.com` 的 `443` 端口”，但**看不到后面的 `/search?q=xxx` 具体路径与搜索关键词**，因为完整 HTTP 请求头和 URL 路径是在 TLS 握手完成之后才加密发送的。
4. **上下行流量字节数与协议消耗（Bandwidth Usage）**：为了扣除你的套餐月度配额（比如 150GB/月）和计算节点倍率（见 [线路倍率核算](/routes/multipliers/)），机场后端 Xray/Mihomo/sing-box 服务端进程必须实时统计每个用户的 `upload` 与 `download` 字节数。

## 三、绝对红线：严禁安装不明 MitM 根证书（Root CA）

如果整篇文章你只记住一条保命级安全原则，那就是：**绝对不要为了“免费上网”“网络加速”或“解锁某应用”，在操作系统或手机里安装并信任任何陌生人提供的根证书（Root CA）或描述文件！**

### 1. 中间人攻击（MitM）是如何一瞬间击穿 HTTPS 的？

前面我们解释过，HTTPS 之所以安全，是因为攻击者无法伪造由受信任 CA 签发的网站证书。然而，操作系统允许用户出于企业内网审计或本地开发调试的目的，**手动将一张新的 CA 根证书添加进“受信任的根证书颁发机构”**。

一旦你在弹窗引导下点击了“安装证书 → 设为始终信任”（在 iOS 上则表现为先安装配置描述文件，再去 `设置 → 通用 → 关于本机 → 证书信任设置` 中打开完全信任开关）：
- 该根证书的私钥持有者（即给你发软件的恶意组织或后台服务器）就获得了**向你设备签发任意网站合法证书的最高权力**。
- 当你打开银行网页、输入 Gmail 密码或提交支付表单时，恶意程序可以在本地或中转节点拦截请求：它先用自己的伪造证书骗过你的浏览器建立第一段 TLS，再用真实客户端身份去连接银行网站建立第二段 TLS。
- **整个过程中你的浏览器地址栏依然显示一把安全小绿锁，没有任何报错！** 但你的所有账号密码、短信验证码、Cookie 令牌与聊天图片已经全部以纯明文形态落入对方服务器。

### 2. 正规代理软件 vs 恶意 MitM 证书的判断铁律

- **普通代理转发永远不需要安装 Root CA**：无论是 [Clash Verge Rev](/clients/clash-verge-rev/)、[v2rayN](/clients/v2rayn/)、[FlClash](/clients/flclash/)、[Hiddify](/clients/hiddify/)、[Karing](/clients/karing/)、[v2rayNG](/clients/v2rayng/) 还是 [Shadowrocket](/clients/shadowrocket/)，在标准代理、分流和 [TUN 虚拟网卡模式](/guides/tun/) 下，**100% 不需要向系统安装任何自定义根证书**。
- **唯一的合法特例（需分清主动与被动）**：只有极少数专业网络调试工具（例如苹果生态的 [Surge](/clients/surge/) 与 [Quantumult X](/clients/quantumult-x/)）提供面向开发者的**本地 HTTPS 解密重写（MitM / Rewrite）功能**。该功能需要用户自己在本机生成一张仅供自己设备使用的局部临时 CA 证书，用于调试个人 API 或去广告脚本，且私钥绝不离开你的本地手机。如果一个不知名软件或机场官网弹窗要求下载外部 `.crt` / `.pem` / `.mobileconfig` 证书文件并声称“不装就上不了网”，**100% 是钓鱼或流量劫持行为，立即卸载并删除证书**。

### 3. 检查设备是否被偷偷植入未知根证书的排查命令

如果你曾经不小心下载运行过来源可疑的“免费加速器”或“破解版抓包工具”，建议立刻用系统自带工具核查一遍根证书列表：

```powershell
# Windows PowerShell：列出当前本机与当前用户“受信任的根证书颁发机构”中最近新增或非微软/非主流商业机构的证书
Get-ChildItem -Path Cert:\LocalMachine\Root, Cert:\CurrentUser\Root |
  Select-Object Subject, Issuer, NotAfter |
  Sort-Object Subject |
  Format-Table -AutoSize
```

```bash
# macOS Terminal：查看系统及登录钥匙串中被手动设为信任的自定义根证书
security dump-trust-settings -d
security dump-trust-settings
```

- **核对方法**：在输出结果中，重点查看 `Subject`（颁发给）名称里是否出现不知名的拼音缩写、某加速器软件名称、`Proxy`、`MitM` 或陌生个人邮箱。如果在 Windows 图形界面排查，可直接按 `Win + R` 运行 `certmgr.msc`（当前用户）和 `certlm.msc`（本地计算机），检查「受信任的根证书颁发机构 → 证书」目录；iPhone/iPad 用户请依次进入 `设置 → 通用 → VPN 与设备管理` 及 `关于本机 → 证书信任设置`，确认里面没有任何陌生的描述文件与开启的根证书开关。

## 四、订阅链接 Token 泄露与在线订阅转换网站的隐私风险及重置方法

在日常使用机场时，除了客户端木马和未知 CA 证书，**最高发的实质性安全事故就是“机场订阅链接泄露导致月度流量一夜被盗刷清零”**。

### 1. 为什么一条订阅 URL 等同于你的账号密码？

打开任何一家支持第三方通用订阅的机场后台，复制到的链接通常长这样：
`https://sub.example-domain.com/api/v1/client/subscribe?token=a1b2c3d4e5f67890abcd`

请注意链接尾部的 `token=`（部分面板或链接格式为 `/link/xxxxxx` 或直接包含一段 32 位随机字符）。这个接口设计初衷是为了让 [Clash Verge Rev](/clients/clash-verge-rev/) 等客户端能够免登录自动定时拉取最新节点，因此**服务器只认链接里的 `token`，不校验浏览器登录 Cookie**。换句话说：
- **谁拿到了你的完整订阅 URL，谁就能一键导出你的全部节点服务器地址、端口和个人认证 `uuid`/`password`**；
- 如果你订阅的机场不限制同时连接设备数（如数据库中 [光速云](/brands/guangsuyun/)、[星岛梦](/brands/xingdaomeng/)、[二猫云](/brands/ermao/)、[唯兔云](/brands/weitu/) 等均标注不限设备数），拿到你订阅链接的人可以同时挂几十台设备疯狂跑下载，几小时内把你 150GB 甚至 1TB 的流量配额刷光；如果机场限制了在线 IP 数（例如限制 3–5 台设备），你的账号甚至可能因为他人并发连接而被系统误判为“多人合租共享账号”从而触发封禁。

### 2. 使用公共“在线订阅转换网站”的四大隐蔽风险

很多用户在需要将某种订阅转换成另一种客户端格式时（参见 [订阅格式详解](/guides/subscription-formats-explained/)），习惯直接在搜索引擎找一个网页版的“Subconverter 在线订阅转换器”，把机场给的原始订阅 URL 粘贴进去，点击生成转换后的新链接再导入客户端。这种做法存在极高的隐私与资金风险：

1. **完整 Token 明文落入第三方服务器日志**：你粘贴进网页的原始订阅 URL 会通过 HTTP 请求发送到转换网站的后端服务器上。如果该公共转换站由恶意人员搭建（尤其是搜索引擎前排的匿名站点），后台只需写一行日志脚本就能自动收割每天成千上万条有效机场订阅 `token`。
2. **返回配置文件被暗中篡改节点或注入规则**：转换接口返回的是一份完整的 YAML 或 JSON 配置文件。恶意转换服务器完全可以在返回配置里偷偷删掉你的低倍率专线节点、替换成攻击者自己的蜜罐监测节点，或者修改 `rules` 分流规则，把特定的网银、交易所或开发平台域名劫持到攻击者控制的出口服务器上。
3. **分流规则泄露个人上网习惯**：转换时附加的自定义远程规则或参数也会暴露你的软件偏好与常用工具生态。
4. **“订阅链接直接发到社群求助”次生泄露**：不少新手遇到 [订阅更新失败](/troubleshooting/subscription/) 时，直接把包含完整 `token=` 的客户端报错截图发进公开微信群、Telegram 群或技术论坛，几分钟后流量即被围观爬虫脚本盗刷。

### 3. 安全替代与怀疑订阅泄露后的四步紧急重置法

**如何彻底规避在线转换风险？**
- **首选方案（零转换直连）**：现代开源客户端如 [Hiddify](/clients/hiddify/)、[Karing](/clients/karing/)、[Clash Verge Rev](/clients/clash-verge-rev/)、[FlClash](/clients/flclash/) 与新版 [v2rayN](/clients/v2rayn/) 已原生支持绝大部分机场下发的 Clash YAML、Base64 或 sing-box 格式，**根本不需要经过任何第三方转换网站**。如果你习惯在桌面使用规则覆写，直接利用 Clash Verge Rev 的本地全局脚本覆写功能即可完成规则定制（详见 [Clash 核心配置与覆写指南](/guides/clash-config/)）。
- **进阶方案（本地或私有转换）**：如果确实需要将复杂订阅转为 Surge 或特定格式，应在自己本机电脑使用 Docker 或官方开源程序启动本地 `127.0.0.1` 转换后端，确保敏感订阅链接永不出本机。

**一旦怀疑订阅链接可能已经泄露，请立刻按以下 4 步完成安全重置：**

1. **第一步：面板立即重置订阅密钥（最关键）**：使用可用网络登录机场用户后台面板，找到「仪表盘 / 个人中心 / 安全设置」中的 **“重置订阅链接（Reset Subscription / Reset UUID）”** 按钮并点击确认。系统会立即作废旧 `token` 并生成一条全新 URL，原有被窃取链接上的节点会在短时间内全部鉴权失效。
2. **第二步：同步更新所有本人设备**：在你的电脑 [Clash Verge Rev](/clients/clash-verge-rev/)、手机 [Shadowrocket](/clients/shadowrocket/) 或软路由 [OpenClash](/clients/openclash/) 中，彻底删除旧订阅条目，粘贴刚刚重置后的新订阅链接并执行一次拉取测试。
3. **第三步：核查面板流量明细与工单异常**：重置后观察未来 24 小时面板的「流量使用记录 / 每日消耗统计」，确认是否已经停止异常暴跌；若此前已因泄露被盗刷掉大量包月流量，可通过脱敏工单说明情况，询问客服是否支持手动清除异常时段连接缓存（注意：多数商家对用户自身泄露造成的流量损失不提供免费补流）。
4. **第四步：排查是否波及面板登录密码**：如果怀疑不只是订阅链接泄露，而是电脑可能中过木马或曾经使用过相同密码，务必同步修改机场面板的登录密码，并立刻检查其他重要账号。

## 五、账号密码隔离原则与日常低风险隐私实操习惯

在网络技术边界与订阅防护之外，决定长期数字资产安全的是日常使用习惯。把以下五条隐私隔离原则变成肌肉记忆，可以把风险降到最低：

1. **绝对密码隔离原则（一客一密）**：
   - 在任何机场网站注册账号，**必须使用密码管理器（如 Bitwarden、1Password 或系统原生钥匙串）生成 16 位以上的独立随机密码**。
   - **严禁复用**你的主力邮箱密码、Apple ID、微信/支付宝支付密码、GitHub 或公司内网密码。哪怕某天一家小站因为前端面板未及时更新补丁发生数据库泄露，攻击者拿到的也只是一串废密码，无法对你实施“撞库攻击”。
2. **邮箱别名与身份脱敏注册**：
   - 注册普通代理测试账号时，建议使用专门的副邮箱或邮箱别名功能（如 `+alias` 或独立匿名转发别名），避免把包含真实姓名拼音、公司后缀的工作邮箱暴露在各种小型机场面板的用户表中。
3. **始终启用 `Rule（规则分流）` 而非长期 `Global（全局）`**：
   - 保持客户端运行在规则分流模式下（参考 [分流规则配置基础](/guides/routing/)），确保国内银行 App、支付宝、微信支付、税务政务网站以及国内云盘直接走本地物理宽带直连。这样既不会因为代理出口在海外而触发银行风控锁卡，也让所有国内敏感个人活动彻底绕开第三方代理节点。
4. **定期审计 DNS 与 IPv6 旁路泄漏**：
   - 有时你以为流量走了代理，实际上浏览器的明文或直连 DNS（或未接管的 IPv6 请求）正直接穿透出去。建议在客户端配置内置安全 DNS / Fake-IP 模式，并定期按 [DNS 错误与泄漏排查指南](/troubleshooting/dns/) 验证海外域名解析是否完整经过代理隧道。
5. **支付与设备登录最小权限原则**：
   - 购买如 [Shadowrocket](/clients/shadowrocket/) 等外区付费工具时，**绝对不要用淘宝买来的或他人免费分享的“共享 Apple ID”直接登录手机系统的 iCloud 设置**（这可能导致手机被恶意开启“丢失模式”远程锁机勒索），只应通过正规自建非大陆区 Apple ID 在 App Store 商店内买断购买。

## 常见问题（FAQ）

### 用机场或代理软件之后，机场安全吗？运营方能看到我的网银密码、邮箱账号和聊天内容吗？

只要访问的是标准 HTTPS 网站（浏览器地址栏显示安全锁标且无证书警告），并且你没有在系统或手机里安装任何来路不明的第三方 CA 根证书，通信正文在离开你的设备前就已经由 TLS 1.3 端到端加密。机场节点与中转服务器只能看到加密密文，无法窥探你的账号密码、登录 Cookie、表单内容或聊天正文。

### 既然内容是 HTTPS 加密的，那机场服务端到底能记录或看到哪些信息？

代理服务端依然能够看到连接层与握手层元数据，具体包括四项：你的本地宽带或蜂窝网络公网源 IP、每次连接的精确时间戳、上下行消耗的流量字节数，以及你要访问的目标域名和端口（通过 TLS 握手时的明文 SNI 扩展字段以及经由代理节点转发的远程 DNS 查询）。

### 为什么有些免费加速器或陌生软件会提示“安装描述文件或信任根证书”，这有什么危害？

安装并信任第三方根证书（Root CA）等于授权对方在你的设备上执行 HTTPS 中间人解密（MitM）。一旦装上恶意或未知根证书，软件或中转服务器就可以动态伪造银行、邮箱或 GitHub 的数字证书，把端到端加密拆成两段解密，从而以明文形式读取你的所有密码、支付信息与私密内容。正规开源代理客户端在正常转发模式下永远不需要安装外部 CA 证书。

### 什么是机场订阅链接泄露？把订阅粘贴到在线订阅转换网站为什么会导致流量被盗刷？

机场订阅链接末端通常带有唯一的身份认证 token 或个人 UUID（如 ?token=xxxx），它本质上等同于你的节点访问密码。如果把完整订阅 URL 粘贴进不知名或非开源的公共在线订阅转换网站，或者在求助截屏中未打码露出完整链接，第三方服务后端就能记录你的订阅地址并直接白嫖、转卖甚至劫持修改你的节点配置，导致流量莫名耗尽。

### 发现流量莫名暴涨、怀疑订阅链接已经泄露时，应该如何紧急重置和止损？

请立即按四步止损：第一步，登录机场官网面板找到“重置订阅链接 / 重置 UUID（Token）”按钮并确认生效，使旧链接作废；第二步，在 Clash Verge Rev、v2rayN 或 Shadowrocket 中删除旧订阅并导入全新链接；第三步，检查面板的在线设备数或连接记录；第四步，如果连面板账号密码也有泄露嫌疑，立即修改面板登录密码并检查其他网站是否复用过同一密码。

### 在机场面板开启“Rule 规则分流”和“全局代理（Global）”，对隐私保护有什么区别？

开启 Rule 规则分流时，国内网银、支付宝、政务平台、微信及国内视频站的连接会直接通过你本地家庭宽带直连目标服务器，根本不经过机场服务器，既降低延迟又避免国内敏感金融或身份业务暴露在境外节点上；而如果长期挂着 Global 全局代理，所有国内访问元数据也会绕行机场节点，同时容易触发国内金融软件的异地风控。

### 开源代理客户端加常规机场、独立审计商业 VPN 和自建 VPS，隐私风险差距在哪里？

使用 Clash Verge Rev、FlClash 或 Hiddify 等开源客户端搭配常规机场，客户端本地代码可公开审计但机场服务端通常缺乏第三方无日志审计且会保留连接数与计费流量记录；经过独立无日志审计与 RAM-Only 内存运行架构的商业 VPN 在服务端日志约束力上更强；而自建 VPS 则需自己承担服务器日志配置并受限于机房所在司法管辖。
