# Clash 规则模式（Rule）与全局模式（Global）有什么区别？误用导致的流血与排障

<div class="answer-first-box">
  <div class="answer-first-label">核心结论（Answer-First）</div>
  <p>在 Clash 与现代 <a href="/clients/mihomo/">Mihomo（Clash.Meta）</a> 内核中，<strong>Rule（规则模式）与 Global（全局模式）的本质差异在于是否执行分流规则表</strong>。日常使用应当 <strong>99% 保持在 Rule 模式</strong>：内核依次比对局域网、国内域名、AI/流媒体专项规则与大陆 IP 库，实现国内应用物理网卡零损耗直连、海外服务按地区精确派发；而 <strong>Global 模式会绕过常规 <code>rules:</code> 列表，把所有接管流量全部送入 <code>GLOBAL</code> 策略组选定的单一节点</strong>，长期开启极易引发套餐流量“大出血”、国内应用绕远卡顿及网银风控拦截。Global 模式唯一的合理定位是<strong>短时间验证规则漏网或隔离排查单节点故障</strong>。</p>
</div>

很多刚接触 [Clash Verge Rev](/clients/clash-verge-rev/)、[FlClash](/clients/flclash/) 或 [OpenClash](/clients/openclash/) 的用户，遇到海外网页打不开时习惯性把模式从“规则”切成“全局”。页面可能暂时通了，但紧接着网盘下载速度暴跌、国内视频耗光半个月机场流量、甚至手机银行弹出风控拦截。下面从底层架构拆解四大运行模式与标准排障边界。

---

## 一、概念定义：Clash 四大运行模式的底层分流机制

客户端出站模式切换栏中的 `Rule`、`Global`、`Direct`（以及早期文档提及的 `Script`），由配置顶级字段 `mode:` 控制，决定内核收到入站连接后的路由分支：

| 运行模式（`mode`） | 规则表匹配情况 | 流量最终去向 | 适用状态与定位 |
| --- | --- | --- | --- |
| **规则模式（`rule`）** | **完整执行** `rules:` 自上而下顺序匹配 | 国内与内网走 `DIRECT`，海外按目标精准派发 | **日常唯一推荐主力模式** |
| **全局模式（`global`）** | **绕过绝大多数** `rules:` 分流规则 | 除极少数本地回环外，全部交由 `GLOBAL` 策略组选中出口 | **仅限临时排障与单节点纯净测试** |
| **直连模式（`direct`）** | **完全跳过** `rules:` 与节点选择 | 所有接管连接一律走 `DIRECT` 本地物理网卡直连 | 临时暂停翻墙或测本地宽带对照组 |
| **脚本模式（`script`）** | 通过自定义表达式动态拦截决策 | 由旧版内置解析器计算返回（Mihomo 已移除） | 仅存在于 2023 年前的原版旧内核配置 |

1. **Rule（规则模式）**：本地 `mixed-port`（如 `7897`）或 [TUN 虚拟网卡](/guides/tun/) 收到请求后先查表验明正身。访问微信、淘宝或公司内网时微秒级命中直连，**不走代理隧道、不耗套餐流量**；访问 Google、ChatGPT 或 Netflix 则按规则并分发往香港、美日或流媒体节点。
2. **Global（全局模式）**：内核直接忽略 `rules:` 下的国内与专项分流表，将所有接管请求统一归拢进内置的 `GLOBAL` 策略组。**新手最大盲区在于：开 Global 并不自动走你日常用的节点**。内核在全局模式下只认 `GLOBAL` 策略组当前选中的出站口；若默认排在首位的是 `DIRECT` 或失效节点，切到全局反而会原地断网。
3. **Direct（直连模式）**：客户端保留本地接管但全量旁路放行，适合排查“到底是本地宽带故障还是代理软件导致断网”（TUN 模式下仍会经本地 DNS 引擎，彻底排障建议连同 TUN 一并关闭）。
4. **Script（脚本模式）**：早期 Clash Premium 允许嵌入类 Python 脚本动态决定出口，因性能开销大与安全隔离问题已在 **Mihomo 内核中被正式废弃**。现代动态分流统一在 `rule` 模式下用 `sub-rules` 子规则或客户端 JavaScript 覆写脚本预处理实现。

## 二、技术原理：Rule 模式下精确的自上而下匹配顺序

很多用户抱怨规则模式不准确，往往是没有看懂 `rules:` 的**首条命中即终止（First-Match）**铁律。详细语法可参考[分流规则与策略组实战](/guides/routing/)和[Clash YAML 配置详解](/guides/clash-config/)。数据包进入 Rule 引擎后，严格按以下从窄到宽的顺序扫描：

1. **局域网与进程前置直连层**：`PROCESS-NAME`（如 `baidunetdisk.exe`、`Thunder.exe`）与私有网段（`192.168.0.0/16`、`10.0.0.0/8`）置顶，保障 NAS、打印机和大型下载工具第一时间直连。
2. **自定义规则与 `RULE-SET` 专项规则集**：个人微调域名与 `.mrs` 二进制规则集（如 `openai`、`netflix`、`reject`）。因为 [ChatGPT](/ai-streaming/chatgpt/)、[Claude](/ai-streaming/claude/) 和 [Gemini](/ai-streaming/gemini/) 封锁香港 IP，这些专项 `RULE-SET` 必须排在泛境外规则之前，才能把 AI 请求提前截胡送到美日节点。
3. **`GEOSITE` 域名归属地层**：`GEOSITE,cn,DIRECT` 与 `GEOSITE,geolocation-!cn,Proxy`。基于纯域名内存树比对，微秒级完成 90% 以上国内外站点的零 DNS 泄漏分流。
4. **`GEOIP,CN,DIRECT` IP 归属地防线**：对未命中域名库的长尾冷门站点做 IP 校验。
5. **`MATCH` 全局兜底规则**：位于最底部的 `MATCH,Proxy`（不可放在任何规则上方），接收所有漏网境外请求。

```yaml
rules:
  # 1. 局域网与私有 IP 必须加 no-resolve，避免对域名触发无效本地 DNS 查询
  - IP-CIDR,192.168.0.0/16,DIRECT,no-resolve
  - IP-CIDR,10.0.0.0/8,DIRECT,no-resolve
  # 2. 专项业务 RULE-SET 优先于泛境外规则
  - RULE-SET,openai,AI-专用组
  - RULE-SET,netflix,流媒体组
  # 3. 社区域名集合快速分流
  - GEOSITE,cn,DIRECT
  - GEOSITE,geolocation-!cn,Proxy
  # 4. 长尾未命中域名的 IP 兜底（故意不加 no-resolve，允许解析确认国内 IP）
  - GEOIP,CN,DIRECT
  # 5. 最底部唯一兜底
  - MATCH,Proxy
```

注意关键细节：排在前面的 `IP-CIDR` 或 `GEOIP,telegram` 务必加上 `,no-resolve`，防止域名请求经过时被迫停下来做本地 DNS 解析造成卡顿和泄漏；而末尾 `GEOIP,CN,DIRECT` 则故意不加 `no-resolve`，专门用来把冷门国内小站拦回直连。

## 三、实际影响：长期误开 Global 导致的“流血”与三大故障

把 Global 模式常驻后台会带来资金、速度与账号安全三重损耗：

1. **套餐流量“大出血”与倍率翻倍扣费**：日常国内流量通常是海外流量的十倍以上。全局模式下，Windows/macOS 系统更新、云盘同步、高清国产剧缓存和 Steam 国服更新全部经代理节点绕行，每一兆都扣除机场月度配额。若当前节点带有 `2x` 或 `3x` 倍率（参见[流量倍率计费详解](/routes/multipliers/)），一次游戏更新就能直接烧光全月流量。
2. **国内高速应用延迟翻倍与降速**：本地宽带直连国内 CDN 仅需 5–25ms。开 Global 后，哪怕走香港节点，数据也要先出境到香港再绕回国内服务器，物理路程翻倍不说，国内视频与下载站对境外机房 IP 的限速策略还会让下载速率断崖下跌、国内网游跳红标。
3. **网银、政务门户与本地局域网风控失效**：手机银行、证券软件、税务和政务门户对来访 IP 归属地极度敏感。全局模式下，你的请求带着多人共享的香港或美国机房 IP 接入，轻则反复弹出滑块和人脸验证，重则被风控判定异地盗号直接拦截或锁死账户；同时若叠加 TUN 且路由排除不全，局域网群晖 NAS 与企业 OA 内网也会同步失联。

## 四、使用场景：什么时候才应该“临时”开启 Global 模式？

Global 模式并非毫无用处，它是网络排障时最直接的“控制变量法工具”，仅建议在以下场景短时开启：

1. **快速区分“规则漏配”还是“节点故障”**：遇到冷门海外新站点或小众 API 打不开，在排除本地 [DNS 解析污染](/troubleshooting/dns/) 后，临时切到 Global 并确认 `GLOBAL` 组选了有效节点。如果瞬间打开，说明节点本身正常，单纯是 `rules:` 漏掉了该域名（或配置使用了 `MATCH,DIRECT` 白名单兜底）。此时切回 Rule 模式，打开客户端“连接（Connections）”面板查出真实域名补入自定义规则即可。
2. **单节点纯净出口与解锁测试**：在多策略组混杂时，为了排除自动测速跳组或规则分流干扰，临时开 Global 在 `GLOBAL` 组手动点名测试某一条节点的真实出口 IP 与流媒体解锁状态，测完立即切回 Rule。
3. **纯 IP 硬编码海外软件临时应急**：极少数冷门海外工具直接硬编码 IP 通信且未落入常规 `GEOIP` 放行范围时，可短时切 Global 应急。

> **排障闭环提示**：如果切到 Global 并选好可用节点后依然全部超时，问题通常不在分流模式，应检查[系统时间偏差与 TLS 握手](/guides/system-time-tls-fix/)或排查[全节点超时断连原因](/troubleshooting/disconnected/)。

## 五、常见误区：四个高频认知偏差

- **误区一：“全局模式比规则模式更快更稳。”** 走 Rule 模式时海外流量本来就走同一条代理通道，上限完全一致；Global 只是强行把国内快通道也拽进慢速绕路隧道。所谓“切全局变快”，往往只是你在 `GLOBAL` 组恰好挑了一个比原分流组更好的节点。
- **误区二：“切到 Global 后会自动沿用 `Proxy` 组选中的节点。”** `Proxy` 只是普通自定义策略组名称，Global 模式只听从内置 `GLOBAL` 组的当前选中项。忘记在 `GLOBAL` 组里切节点，是切全局后断网的头号原因。
- **误区三：“Global 模式就等于开启了 TUN 模式。”** 模式（`Rule/Global`）决定流量怎么分，接入方式（`系统代理/TUN`）决定哪些软件能进内核。只开系统代理的 Global 依然管不了终端命令行，而 Rule 模式下开启 TUN 一样能全机精准分流（详见 [TUN 与 WSL2/Docker 冲突排查](/troubleshooting/tun-wsl-docker-conflict/)）。
- **误区四：“用浏览器白名单插件就能替代 Clash Rule 模式。”** 浏览器插件无法接管桌面软件与终端，没有十万级 `GEOSITE` 库，也无法协调内核级 `Fake-IP` 防污染；现代场景应统一交由 Mihomo 或 [sing-box](/clients/sing-box/) 本地核心处理。

## 六、常见问题（FAQ）

### Clash 的 Rule 模式和 Global 模式最核心的区别是什么？

核心区别在于是否执行配置文件里的分流规则表。Rule 模式下，内核会对每一条请求自上而下匹配本地规则，让国内与局域网流量直连、境外流量按目标分别走向对应地区节点；Global 模式下，内核直接跳过绝大多数分流规则，将除内置极少数本地回环之外的所有接管流量强行送往 GLOBAL 策略组当前选中的单一出口。

### 为什么切换到 Global 全局模式后，微信发图、淘宝加载和百度网盘下载反而明显变慢？

因为在全局模式下，原本只需几毫秒即可走本地家庭宽带直连的国内服务器连接，也被强行加密打包送往了香港、日本甚至美国代理节点，再由海外机房绕回国内运营商网络。这不仅平白增加了几十到几百毫秒的跨海往返延迟，还让高带宽下载受限于机场节点单线速度上限。

### 误开 Global 全局模式为什么会导致机场流量“大出血”？

开启全局模式后，本地电脑或手机上的云盘同步、高清国产剧缓存、系统更新包以及 Steam 国服游戏下载全部从代理节点过境，每一兆字节都会计入机场套餐额度。如果当前选中的节点还带有 2 倍或 3 倍扣费倍率，一次大型客户端更新就可能瞬间消耗数十 GB 套餐流量。

### 为什么切到 Global 模式后反而完全上不了网，或者依然无法访问海外网页？

最常见原因是切换模式后没有检查 GLOBAL 策略组的选中项。在许多默认订阅配置里，GLOBAL 策略组默认停留在 DIRECT（直连）状态，或者停在了一个已经超时失效的节点上。切换到全局模式后，必须进入代理列表找到 GLOBAL 组并手动选定可用节点，才会真正经过代理出口。

### 什么情况下才应该临时把 Clash 切换到 Global 全局模式？

仅建议在两种排障测试场景下短时间使用：一是怀疑某个新网站或冷门接口因规则库漏掉域名而走直连导致打不开时，临时开 Global 验证能否正常加载；二是在测试单个节点的纯净海外出口 IP 或排查分流策略组故障时，排除复杂规则干扰，测完后应立即切回 Rule 模式。

### 早期资料里提到的 Script 脚本模式现在还能用吗，和 Rule 模式是什么关系？

Script 模式（mode 为 script）是早期 Clash 原版内核提供的通过嵌入式脚本动态计算出口的高级模式，因安全隔离、性能开销大且难以维护，已在现代 Mihomo（Clash.Meta）内核中被正式废弃。如今需要动态修改分流逻辑时，统一在 Rule 模式下配合客户端的 JavaScript 覆写扩展或 sub-rules 嵌套子规则实现。
