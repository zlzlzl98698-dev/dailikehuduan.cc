## 一、线路倍率的双向计费底层公式与套餐真实单价模拟

在传统的手机流量卡或家庭宽带认知里，下载 1 GB 文件就是消耗 1 GB 额度。但在商用代理机场的后端计费面板（如 V2Board、SSPanel-UIM、Xboard 等主流架构）中，流量账单由两个独立动作共同决定：**双向字节统计** 与 **节点乘数倍率（Rate / Multiplier）**。

### 1. 双向计费公式与“上行流量”的隐蔽放大效应

代理服务器每转发一个连接，节点端程序（如 Xray-core、Sing-box、Shadowsocks-libev、Hysteria）都会分别记录该用户端口入站与出站的字节总数，并按周期上报给计费数据库：

$$\text{后台实际扣减流量} = (\text{本机上行发送流量 } U + \text{本机下行接收流量 } D) \times \text{节点倍率 } M$$

很多新手习惯只按“我下载了多少东西”估算流量，却忽略了公式里的 **上行流量 $U$**：
- **纯网页浏览与流媒体观看场景**：TCP 确认包（ACK）与 HTTP 请求头上行极小，通常仅占下行流量的 **2%–5%**。例如看 10 GB 的 4K YouTube 视频，上行大约在 0.3 GB 左右，双向总量约 10.3 GB。
- **高上行并发场景（最易爆表）**：一旦你在代理下进行 **Google Drive / OneDrive / iCloud 照片备份、Git 推送大仓库、Docker `push` 镜像、远程桌面画面回传、Zoom/Teams 摄像头高清推流**，甚至在全局或 [TUN 模式](/guides/tun/) 下忘记过滤 **BT/PT 下载做种软件**，你的上行流量 $U$ 可能与下行 $D$ 持平甚至反超！如果此时正好挂在一个 `3x` 倍率节点上，上传 5 GB 文件就会瞬间从套餐里扣掉 `5 × 3 = 15 GB` 额度。

### 2. `0.2x` vs `1x` vs `2x–5x` 对每 GB 真实单价的影响模拟表

对照上表，就能轻松识破市场上常见的“大流量低价套路”：
- **品牌甲（套路型）**：宣传“月付 ¥15 享受 300 GB 超大流量，全线极速专线”，结果点进面板发现除了一条延迟 260ms 的美国 `0.5x` 垃圾直连外，所有能流畅使用的香港、日本、新加坡节点全部暗设为 **`3x` 倍率**。这意味着你花 ¥15 真正能用的亚太主力流量仅有 `300 ÷ 3 = 100 GB`，真实单价为 **¥0.15/GB**；如果全线设成 `5x`，真正可用流量只剩 `60 GB`，单价高达 **¥0.25/GB**，反而比正常 `1x` 机场更贵！
- **品牌乙（透明 `1x` 型）**：如月付 ¥20 提供 150 GB、全节点明确标注 `1x` 无倍率，实际可用就是扎扎实实的 150 GB（折合 **¥0.133/GB**），无需时刻提防哪天多看两部 4K 电影就把套餐跑穿。更多套餐性价比横评可参阅 [性价比机场横向比较](/plans/value/) 与 [低价便宜机场成本边界](/plans/budget/)。

## 二、为什么机场要设高倍率？剖析四大高倍率踩坑场景

把所有倍率设置一概骂成“奸商欺诈”并不客观。理解背后的电信带宽经济学，才能区分**合理的产品分层**与**恶意的隐蔽收割**。

### 1. 合理倍率背后的基础设施成本逻辑

如在 [IEPL 专线技术解析](/routes/iepl/) 中核算的，一条深港或沪日政企专线的采购模式是**按 Mbps 固定带宽包月**，而非按 GB 流量包月。与此同时，一张干净的香港 HKT 家宽或日本本土住宅原生 IP 不仅月租高昂，而且一旦被用户拿去跑大规模爬虫或视频离线下载，极易被目标平台封禁或触发上游运营商限速。

因此，成熟运营方采用**“价格杠杆 + 倍率隔离”**：
1. 用 **`0.2x` / `0.5x`** 把“系统更新、网盘同步、Steam/Docker 大包拉取”这类不敏感的吞吐型流量，引流到廉价的普通直连大带宽服务器上，既让用户省流量，又减轻主力节点压力。
2. 用 **`2x`–`3x`** 提高高成本专线或原生家宽 IP 的使用门槛，确保这类节点只被用于“AI 对话、4K 在线观影、远程办公会议”等高价值交互场景，防止少数下载大户把有限专线打满导致全员卡顿。

### 2. 普通用户最容易中招的四大高倍率陷阱

然而，一旦商业约束缺乏透明度，倍率机制就会沦为四大防坑重灾区：

1. **订阅节点名“隐身倍率”（最隐蔽）**：
   规范的机场会在节点名称中明确缀上 `[2x]`、`[倍率:3.0]` 或 `x2` 标识；但部分机场为了美观或刻意隐藏高倍扣费，订阅下发的节点名称只写 `香港 IEPL 01`，仅在官网冷门公告或用户中心节点列表里悄悄标注 `倍率 2.5`。用户在 [Clash Verge Rev](/clients/clash-verge-rev/) 里盲选时完全无法感知，直到半个月后收到流量告警邮件才追悔莫及。
2. **`url-test` 自动测速组的“流量雪崩效应”（最高发）**：
   这几乎是 **80% 新手一夜跑空月包的头号元凶**。因为在一个混合订阅里，`2x`、`3x` 或 `5x` 的高倍率专线或家宽节点，往往正是带宽最宽裕、晚高峰最不拥堵、HTTPS `generate_204` 延迟最低的那一批节点！
   当你导入订阅后直接点击软件默认的 **`♻️ 自动选择`（`type: url-test`）** 时，客户端内核每隔 5 分钟测一轮延迟，然后毫不犹豫地把全机默认代理永远锁定在延迟最低的 **`香港 IPLC [3x]`** 或 **`香港家宽 [5x]`** 上！接下来无论是看 4K 视频还是后台加载网页素材，全部按 3 倍到 5 倍疯狂扣流。
3. **动态倍率偷调（白天 `1x`、晚高峰切 `2x`）**：
   少数缺乏契约精神的运营方在前端不发公告，在晚高峰 20:00–23:30 负载过高时直接在后端面板把主力香港节点的倍率参数从 `1.0` 临时改成 `2.0`，次日凌晨再改回 `1.0`。如果用户在订阅导入时未同步开启强制流量账单审计，极难察觉。
4. **TUN 虚拟网卡模式下的“后台偷跑 × 高倍放大”**：
   开启 [TUN 模式](/guides/tun/) 接管全系统流量后，Windows Update 补丁推送、Steam/Epic 后台静默更新、iCloud 照片库自动上传、OneDrive 同步、Docker 镜像拉取等动辄数十 GB 的后台流量，一旦因为分流规则遗漏而走上了代理出口——只要当时命中了 `3x` 节点，一次 20 GB 的系统或游戏更新就会瞬间吃掉 **60 GB** 套餐配额。

## 三、客户端实战防坑：用 Mihomo `exclude-filter` 彻底隔离高倍节点

要根治“自动测速误切高倍率节点”与“大流量下载白白烧专线”的痛点，绝不能靠每次手动去节点列表里肉眼避雷。在目前主流的 **[Mihomo（Clash.Meta）](/clients/mihomo/)** 内核客户端（包括 [Clash Verge Rev](/clients/clash-verge-rev/)、[FlClash](/clients/flclash/)、[Stash](/clients/stash/) 与 [OpenClash](/clients/openclash/)）中，通过订阅覆写（Global Override / Script）配置 **`exclude-filter` 与 `filter` 正则表达式**，可以一劳永逸地把订阅节点按倍率切分为三层战略梯队。

### 1. 完整可复用 Mihomo 覆写模板：三层倍率自动隔离架构

在 [Clash Verge Rev](/clients/clash-verge-rev/) 的“订阅 → 右键编辑全局扩展配置（或单订阅覆写）”中，可参考以下经过实战验证的策略组架构（更多 YAML 语法说明见 [Clash 配置文件结构详解](/guides/clash-config/) 与 [分流规则与策略组](/guides/routing/)）：

```yaml
# Mihomo (Clash.Meta) 防高倍率雪崩三层策略组覆写模板
proxy-groups:
  # 第一层：日常主路由入口（默认始终走低/标准倍率自动组，绝不自动进高倍）
  - name: "🚀 日常主代理"
    type: select
    proxies:
      - "♻️ 自动优选 (仅≤1x安全节点)"
      - "⬇️ 低倍下载专线 (0.2x–0.5x)"
      - "🎯 精选高倍/家宽 (仅手动按需)"
      - "🇭🇰 香港 1x 自动"
      - "🇯🇵 日本 1x 自动"
      - "🇸🇬 新加坡 1x 自动"

  # 第二层（核心防坑组）：用 exclude-filter 彻底踢出一切高倍、家宽、定制关键字
  - name: "♻️ 自动优选 (仅≤1x安全节点)"
```

### 2. 匹配大文件分流规则：把吞吐型下载导向低倍或直连

光隔离了高倍节点还不够，配合简单的规则拦截，能把套餐利用率再提高一倍：
1. **国内与常见大流量软件直连**：确保 `GEOSITE,category-games@cn`、`GEOSITE,steam@cn`、`GEOSITE,microsoft`（Windows Update 按需直连）与国内云盘域名全部走 `DIRECT` 直连，彻底避免在 [TUN 模式](/guides/tun/) 下白白浪费机场流量。
2. **海外大文件 CDN 导向低倍组**：如果你在订阅中拥有 `0.2x` 或 `0.5x` 节点，可以把诸如海外大型安装包镜像、Linux 发行版 ISO 仓库或非紧急大体积文件下载规则手动指向 `⬇️ 低倍下载专线 (0.2x–0.5x)`；平时刷网页与使用 AI 时，则稳稳锁定在 `≤1x` 安全组；只有遇到极少数平台非原生住宅 IP 不可解锁时，再手动点开 `🎯 精选高倍/家宽` 切过去用完即切回。

### 3. 其他客户端内核（sing-box / Shadowrocket）如何实现类似隔离？

- **[sing-box](/clients/sing-box/) 内核客户端（如 [Hiddify](/clients/hiddify/)、[Karing](/clients/karing/)）**：若自行维护 JSON 配置，可结合订阅转换或 `outbound` 节点筛选逻辑（如在支持正则过滤的客户端规则里配置排除关键字）；对于不方便手写 JSON 的用户，最直接的方法是在 `Karing` 等客户端的“自动选择/测速”排除列表里手动取消勾选带有 `2x/3x/5x` 标签的节点。
- **[Shadowrocket](/clients/shadowrocket/)（iOS / macOS）**：小火箭本身对分组正则支持较轻量，可在“配置 → 编辑纯文本配置”的 `[Proxy Group]` 中使用 `url-test` 并在节点匹配正则里过滤，或更直观地在首页长按分组设置“仅测速指定子集”，把高倍率节点单独拖出默认测速组。

## 常见问题（FAQ）

### 1. 机场节点的流量倍率（如 0.2x、1x、2x、3x、5x）究竟是怎么计算的？
绝大多数代理机场的后端面板（如 V2Board、SSPanel 等）同时统计上行与下行双向流量，再乘以节点标注的倍率系数，即：`实际扣减流量 = (上行流量 + 下行流量) × 节点倍率`。例如你使用 `3x` 倍率节点下载了 10 GB 视频并产生了 0.4 GB 的 TCP 确认与控制上行数据包，后台账单实际会从你的套餐总额度中扣除 `(10 + 0.4) × 3 = 31.2 GB`。

### 2. 为什么标称每月 100 GB 的套餐，有时候看几天高清视频就提示流量耗尽？
最常见的原因是客户端自动测速组（`url-test`）把高倍率专线节点排在了第一位。通常高倍率（`2x` 至 `5x`）节点对应的往往是低延迟、大带宽的优质 IEPL/IPLC 专线或原生家宽 IP，测速延迟最低，因此未设置正则过滤的客户端会自动把所有网页、4K 视频乃至后台云盘同步流量全部导向这些高倍节点，使 100 GB 标称额度瞬间缩水为 20 GB 至 33 GB。

### 3. 机场为什么要在同一份订阅里设置 0.2x 低倍率和 3x–5x 高倍率，是不是纯粹为了坑人？
从商业带宽采购成本看，差异化倍率本身是一种合理的流量引导手段。`0.2x` 或 `0.5x` 节点通常是大带宽闲时资源或廉价直连机，商家用低扣费鼓励用户把系统更新、网盘同步和大文件下载分流过去；而 `2x` 至 `5x` 节点往往对应按 Mbps 高价采购的真 IEPL/IPLC 专线或稀缺本土家宽原生 IP，高倍率能防止少数重度下载户占满昂贵专线带宽。真正坑人的是订阅节点名字不标注倍率、仅在官网小字写高倍率，或在低价大流量套餐里全线暗设 `3x` 倍率。

### 4. 如何在 Clash Verge Rev 或 Mihomo 内核中彻底防止自动测速选中高倍率节点？
最有效的方法是在 `proxy-groups` 的 `url-test` 或 `fallback` 策略组中，利用 Mihomo 内核支持的 `exclude-filter` 正则字段，把名字中包含 `1.5x`、`2x`、`3x`、`4x`、`5x`、`高倍`、`家宽`、`专线VIP` 等关键字的节点从自动选点组彻底剔除，同时另建一个 `type: select` 的手动专用组把高倍节点单独收拢，只在需要解锁特定地区流媒体或高稳定会议时手动切换。

### 5. 上行流量和下行流量都要算倍率吗？哪些日常操作容易偷偷放大上行扣费？
是的，几乎所有商用机场均采用双向计费（`upload + download`）。日常刷网页和看视频时，上行流量通常只占下行流量的 3% 至 5%，感知不强；但如果你在开启代理（尤其是全局或 [TUN 模式](/guides/tun/)）的情况下使用 Google Drive / OneDrive / iCloud 云盘备份上传、Docker 镜像推送、Zoom/Teams 高清视频推流，或忘记关闭 BT/PT 做种上传，上行流量会与下行一样被乘以 `2x` 至 `5x` 扣除。

### 6. 本站 31 家品牌数据库里，有哪些明确标注全线 1 倍或无倍率的机场品牌？

### 7. 如果节点名称里根本没有写倍率，如何自己实测出一条节点是不是暗中设置了 2x 或 3x 倍率？
可以通过“定额单文件对照法”在 1 分钟内测出真实倍率：先关闭电脑和手机上所有其他联网软件与后台同步，刷新机场官网面板记下当前已用流量精确值；然后仅选中待测节点，使用 `curl` 单线程下载一个固定大小（例如恰好 `100 MB`）的测试文件；下载完毕等待 1 至 2 分钟让面板统计刷新，再用新已用流量减去旧值。如果扣了约 100–105 MB 说明是 `1x`，扣了 200–210 MB 则说明暗中开了 `2x` 倍率。
